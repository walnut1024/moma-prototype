# 当前注册流程（2026-10-14）

5.11.0和独立5.12.0已统一采用手机号注册→自动登录→选择实名认证/企业认证，也可稍后认证。已删除注册流程合集、旧企业注册入口及其场景文件。企业认证绑定当前登录账号，仅提交企业资料和授权信息，不注册或激活管理员。两个版本保留各自源码、资源与原存储键，未迁移或清除用户数据；没有接入真实短信/实人核验/企业审核，未发布。以下旧申请查询、邀请、账号激活的说明仅用于已有记录，不再构成新注册流程。

# 登录、注册与政企申请原型

5.11.0 沿用顶部 banner 入口。全部认证页面采用平台共享深色 banner、白色双栏与绿色控件。登录、个人注册和政企服务分别提供入口。页面文案采用 ASD-STE100 的中文清晰表述规则。

## 入口与登录

- `#/auth/login`：选择个人用户或政企用户，再选择登录方式。
- 个人用户使用手机号。注册只创建个人账号。
- 政企用户使用已登记的手机号或邮箱。登录必须具有有效账号和政企成员关系。多主体成员在验证后选择空间。
- `#/auth/register`：个人注册。选择政企用户后进入政企申请页。
- `#/auth/password`：验证手机号后设置密码。待激活账号不能通过找回密码绕过激活。
- `#/auth/invite?token=invite-jiangsu`：受邀手机号 `13800138000`。用户确认后建立普通成员关系。此记录独立于后台业务数据。

项目构建配置决定政企登录账号类型：

```dotenv
VITE_ENTERPRISE_LOGIN=phone,email
```

| 配置 | 政企登录 | 首位管理员账号 |
|---|---|---|
| `phone` | 手机号验证码或密码 | 手机号 |
| `email` | 邮箱和密码 | 邮箱 |
| `phone,email` | 手机号验证码；手机号或邮箱和密码 | 手机号或邮箱 |

注册时，申请联系人与首位管理员为同一人。姓名、联系地址和登录账号只填写一组，账号类型遵循项目配置。项目配置变更后需要重启开发服务或重新构建。

## 政企申请

`#/auth/enterprise` 使用浅色双栏布局，左侧展示无文字 AI 场景插图，右侧填写资料。手机使用单列。个人与政企注册入口提供身份切换。

1. 填写单位信息。选择政府机构或企业。填写主体全称、主体标识、省份和行业。城市选填。
2. 填写管理员与联系信息。填写姓名，选择手机号或邮箱，验证此账号。申请结果发送至该账号，开通后由此人担任首位管理员。此步骤不设置密码。
3. 核对资料。各组提供修改动作。阅读协议后提交申请。

返回上一步保留资料。修改联系地址或类型会使验证码失效。提交时再次校验验证码和所有资料。验证码过期时返回第二步，保留资料。连续点击提交只执行一次。保存失败时保留资料并显示错误。

申请提交只新增待处理申请。申请提交不创建个人账号、政企主体、组织、成员、项目、API Key 或配额，也不改变当前登录会话。旧的“验证管理员并注册账号 → 企业资料”代码路径已经删除。

## 进度查询与补充

`#/auth/application` 需要申请编号和申请联系地址。必须验证联系地址，才能读取对应申请。申请编号不能单独用于查询。查询入口不要求先创建个人账号。

| 申请状态 | 页面动作 |
|---|---|
| 待处理 | 查看记录，查询其他申请 |
| 需补充 | 展示处理意见，补充资料，重新提交 |
| 已开通 | 展示管理员账号状态，前往政企登录 |
| 已关闭 | 展示处理意见，重新申请 |

补充资料保留申请编号和原提交时间。只允许原联系地址提交补充资料。当前前台提供这些状态对应的交互；平台审核处理尚未接入，因此用户新提交的申请保持待处理。

## 管理员激活

平台工作人员开通主体、根组织和首位管理员关系。已设置密码的有效账号继续使用原账号。新账号接收独立激活链接。普通成员继续使用邀请流程。

`#/auth/activate?token=…` 校验平台签发的激活记录、有效期、启用身份和有效管理员关系。管理员验证登记的联系地址，再设置密码。激活不自动登录、不新增成员关系。激活成功后清除 token，旧链接不能再次使用。

前台本地模型所需账号字段：

```js
{
  id, name, status: '正常', phone /* 或 email */,
  activation: { token, type: 'phone' /* 或 email */, enterpriseId, expiresAt }
}
```

对应成员关系必须具有相同 userId、enterpriseId、`status: '已加入'`、`role: '企业管理员'`，并且主体未冻结。已开通申请用 `adminUserId` 关联身份；有密码摘要时展示已激活，否则展示待激活。

本轮没有把前台独立本地账号与后台身份数据合并，也没有新增前台审核按钮或伪造激活链接。有效激活分支通过状态测试验证；真实签发、消息发送和平台处理接口仍待接入。

## 接入边界

所有交互使用浏览器本地存储 `moma-auth-prototype-v1`，不发送短信或邮件。验证码由浏览器生成，在“本次验证信息”中查看。验证码绑定地址、类型和用途，5 分钟有效，60 秒后可重发，5 次错误后需重新获取。

密码使用 Web Crypto 的随机盐 PBKDF2 摘要，不保存明文。这只用于本地流程验证，不构成生产认证或授权。正式上线必须由服务端校验验证码、激活 token、申请查询权限和成员权限。

旧账号、成员关系及申请记录保留，不清空存储。旧流程提交的申请缺少独立联系验证字段，本轮不迁移这些记录。新查询流程读取本轮及后续提交的申请。

banner 空间切换只改变本地选中空间。现有模型、订单、项目、API Key 和用量页面仍使用原有业务源。后台权限保持原有控制。

协议弹窗说明正式条款尚未接入。未编造正式法律条款。

## 完整注册流程合集（2026-10-06）

`#/auth/flows` 汇总 11 个可独立体验的场景。通过 banner 的政企服务菜单进入，也可以直接访问合集 URL。

- 个人注册：手机号验证、注册结果、可选密码设置、进入个人空间、退出与再次登录。
- 政企申请：单位信息、管理员与联系信息、确认提交、申请结果和进度查询。
- 申请生命周期：待处理、需补充、已开通、已关闭。补充资料保留原申请编号，再次验证联系人后重新提交。
- 首位管理员：从已开通记录进入激活、验证管理员地址、设置密码、查看激活结果、政企登录。
- 受邀成员：查看邀请、验证受邀手机号、确认加入、查看结果、进入政企空间。
- 多空间：验证账号、选择政企空间、进入空间、切换空间。
- 政企密码登录：按项目账号规则预置已激活账号，使用已有密码进入政企空间；当前项目支持企业邮箱。
- 异常：激活链接无效或过期、字段校验、验证码错误或失效、重复注册、主体重复申请。

合集复用正式页面组件和现有认证状态函数。预置身份、申请和审核状态只存在于该次内存场景，不读写 `moma-auth-prototype-v1`，不改变后台账号、权限或组织。体验资料可展开查看；切换场景和重新开始会重置当前流程。合集表单的确认框只确认填写信息，不接受法律协议。一般认证页面仍保留协议入口及同意要求。

验证码可以在“本次验证信息”中查看。密码与管理员激活的成功分支通过状态测试验证；浏览器检查激活表单和无效链接、个人注册完成、政企申请完成、补充重新提交、成员加入及空间切换。正式审核、短信、邮箱和后台授权仍未接入。

本轮证据：`outputs/auth-suite-20261006/`。
