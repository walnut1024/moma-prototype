# 后台 2：执行入口

本目录提供后台规格、计划和交付证据。先确定目标版本与本次任务，再读取相关章节；文档存在不代表实现或发布完成。

## 目标与当前边界

后台 2 是覆盖业务运营、服务运维、平台治理的可交互 Web 原型，保留原版后台。各版本功能范围独立；新增规格、历史计划或文档整理不授权执行整份实施清单。

当前页面要求以[项目页面规格](../PAGE-SPEC.md)和[5.12.0 页面规格](../../versions/moma_5.12.0_estack/PAGE-SPEC.md)的适用章节为准；专题规格补充字段和流程。SPEC/PAGES/PLAN 含早期设计和历史任务，不用其中被替代的规则恢复旧页面。实际完成情况以相关 PROGRESS 证据和源码为准，差异需说明。

后台外观按当前任务的设计要求处理。历史材料中的配色、字号、密度、圆角、间距、固定排布及“保持原样式”不再作为设计约束；功能、数据、权限、版本隔离和无障碍要求继续按当前规格执行。

当前规格随仓库维护；本目录的 PROGRESS、SPEC/PAGES/PLAN 及归档是本地历史材料，不随 Git 分发。只在任务需要追溯且文件存在时读取；缺失时可按当前规格和源码继续工作，但历史交付结论保持未核实。

## 阅读顺序

1. 阅读项目根目录 [AGENTS.md](../../AGENTS.md)。
2. 读取目标版本的当前页面规格；5.12.0 模型术语和接入任务再读版本内 GLOSSARY、MODEL_ONBOARDING_SPEC 对应章节。
3. 需要核对交付状态时，读取版本内专属进度或本地存在的 [PROGRESS.md](PROGRESS.md) 相关记录，核对源码和工作区，区分已完成、仅本地和已发布。
4. 需要补充历史背景且本地材料存在时，读 [SPEC.md](SPEC.md)、[PAGES.md](PAGES.md) 的对应部分；只有当前任务涉及原计划时才读 [PLAN.md](PLAN.md) 依赖，不顺带执行其他任务。
5. 更新有效规格时直接替换受影响条款；验收和剩余事项更新 PROGRESS。历史决定和一次性发布记录不再追加到 AGENTS。

## 历史起点

以下为 2026-09-15 的只读检查记录，不代表当前仓库、页面或测试状态：

- `src/App.jsx` 已提供 front / legacy / v2 三个入口，原版为 `src/AdminConsole.jsx`。
- `src/AdminConsoleV2.jsx` 有 10 个一级功能区、48 个二级导航项和工作台。
- `BusinessPage` 按一级区域共用表头、行数据和统计；不是 48 个完成的业务页面。
- 新建、详情、编辑共用空白表单；“确定”仅关闭抽屉；没有业务保存、关联或持久化。
- `TrendChart` 使用固定两组数据；不是按真实原型记录计算的监控。
- `src/admin-v2.css` 和 `src/admin-v2-fix.css` 已存在；全局 header/aside/main 样式曾污染新版，需要在新版作用域验收。
- 项目有 React、Vite、ECharts、lucide-react；以 package.json 当前内容为准。
- 当前目录及 prototype 未发现 Git 仓库。后续执行前重新检查，不能假设可以提交或回滚。
- 上一轮构建和 4 项 Sites 包装测试通过，只证明构建和包装，不证明业务流程通过。

## 执行约定

- 不再整页套用同一份一级区域数据。可复用表格、搜索框等组件，但每页有自己的字段、动作、校验和状态。
- 原型在各版本内采用本地数据，保持版本与前后台身份隔离；不调用真实模型、不购买资源、不部署真实服务、不发送外部通知。
- 保留前台和原版后台。前台联动通过独立、默认关闭的“联动演示”模式完成，避免原有体验改变。
- 继续任务时以用户授权范围为准，PROGRESS 的历史“下一步”不自动变成本次待办。
- 未完成的页面在进度表明确标记，不能以按钮可点击或截图存在作为完成证据。

## 完成定义

本次授权范围内的功能与边界有对应验收证据，未完成项和验证缺口如实记录。原 PLAN 的整体目标仅在用户要求完成该整体计划时适用，不因读取文档扩大任务；历史验收不替代本轮验证。
