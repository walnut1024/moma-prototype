本文为上一轮已实施方案，现由 [账户与项目范围优化详细设计](SCOPE-DESIGN.md) 替代。仅保留历史验收记录，不作为后续实施目标。

## 1. 范围与结构

保留模型服务、模型体验、订单管理、模型观测四个分组及全部入口、顺序、页面交互。下半部分调整为「项目」分组中的项目管理、API Key，以及仅政企可见的「企业」分组中的企业管理。移除独立项目空间按钮，项目选择器保留。

项目管理默认进入当前项目概览，内部使用「概览、模型、成员、设置、操作记录」五个页签。企业管理默认进入组织与成员，内部使用「组织与成员、操作记录」两个页签。API Key 保持当前项目的独立入口。账号认证通过顶部账号服务提供明确入口，不再占用侧栏。

## 2. 页面与交互

复用现有项目、组织、审计页面和业务写入，不新建第二套状态。项目管理和企业管理有共同标题与页签，页面内保留各自的必要说明、统计筛选及业务操作。项目管理标题显示项目名称和说明，提供「全部项目」；原项目列表改称「全部项目」，保留创建、进入、退出、删除，新增返回当前项目入口。

项目选择器末尾提供「管理全部项目」。切换项目保持当前页面或页签；请求详情切换时清除旧 Request ID，模型详情清除旧模型和销售服务选择，返回目录。模型体验仍按新项目可用范围初始化。账户页面不随项目切换改变账户归属。全部项目页不假称属于某个项目。

设置页保留基本信息、预算、日志策略，增加独立项目生命周期区域：退出项目、负责人交接和删除项目。所有操作使用原有权限及确认流程；负责人不能直接退出，删除确认名称等校验保留。项目概览增加开通模型、创建 Key、查看详细用量快捷操作，按角色禁用写操作。

## 3. 路由、权限与草稿

直接链接仍准确打开对应页签，刷新与浏览器前后退同步页签及侧栏选中状态；项目管理五个子页只高亮一个项目管理入口，企业两个子页只高亮企业管理。现有页面标识继续作为业务页签标识，不扩展重复页面或另建路由兼容层。

项目切换、页签切换、全部项目、企业管理、顶部认证和已有导航统一经过未保存保护；取消后 URL、选择项目、页签、输入和一次性 Key 保持原状。避免页签键盘聚焦自动切换触发草稿丢失，采用手动激活。普通和只读成员保持原权限，不因入口合并扩大可见数据；个人不能渲染企业页面，企业管理不依赖存在项目。

## 4. 修改触点

ProjectConsole.jsx：导航、项目选择器、工作区标题/页签、现有子页复用、设置生命周期入口。AuthExperience.jsx：账号服务增加账号认证。project-console.css：仅作用于工作区标题、页签、子页标题密度，保持原前台样式。导航元数据用于菜单、页签、激活关系和切换目标，针对项目范围与角色边界增加小型回归测试。不改变领域权限、存储结构、后台页面及5.12.0。
