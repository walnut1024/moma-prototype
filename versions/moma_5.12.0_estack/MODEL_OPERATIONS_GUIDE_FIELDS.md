## 关键概念和字段

| 字段中文 | 字段英文 | 定义 | Definition |
| --- | --- | --- | --- |
| 服务商 | Provider | 为平台提供模型服务的厂商或服务平台，例如 OpenAI、阿里云百炼、火山方舟。同一服务商可提供多个模型，并通过多个模型连接接入平台。 | A vendor or platform that supplies model services to MoMA, such as OpenAI, Alibaba Cloud Model Studio or Volcano Engine Ark. One provider can offer multiple models through multiple connections. |
| 租户 | Tenant | 平台上的业务主体，包括政企租户和个人租户。项目、API 密钥、订单、模型授权和账单归属租户。 | The business entity that owns projects, API keys, orders, authorizations and bills. |
| 用户 | User | 可登录平台的个人账号。用户按用户 ID 区分，通过项目中的 API 密钥调用模型服务。个人租户 ID 与用户 ID 分别标识租户和用户。 | An individual account that calls services using project API keys. User IDs and tenant IDs identify different resources. |
| ID | ID | 平台用于查询、管理和关联资源的内部标识。模型服务 ID 与请求中使用的模型 ID 含义不同。 | An internal resource identifier. The service ID identifies the resource, while the model ID selects the service in an API request. |
| 模型连接 | Connection | 平台访问上游模型服务的一套配置，由服务商、服务地址、接口格式、接口端点和上游 API 密钥共同决定，界面中可简称“连接”。一个连接只对应一种接口格式和一个接口端点，例如同一服务商的 OpenAI Chat 和 OpenAI Embeddings 需要两个连接；任一配置不同时，需创建独立的连接。一个连接可接入多个上游模型，以上游模型 ID 区分。 | A configuration MoMA uses to reach an upstream model service. It is defined by the provider, base URL, API format, API endpoint and provider API key. Each connection has one API format and one endpoint, so OpenAI Chat and OpenAI Embeddings from the same provider need two connections. A connection can serve multiple provider models, distinguished by their provider model IDs. |
| 模型 | Model | 模型作者发布的一个具体 AI 模型。型号、版本、精度、发布快照中任何一项不同，就算不同的模型，例如 GLM-5.3 的 BF16 版和 FP8 版是两个模型。同一个模型可以由多个服务商、通过多个连接提供，每个来源记为一条上游模型。用户通过模型服务使用模型，不能直接调用模型。 | A specific AI model published by its author. Models that differ in model, version, precision or release snapshot are different models; for example, the BF16 and FP8 builds of GLM-5.3 are two models. One model can be offered by several providers through several connections, and each source is a separate provider model. Customers use a model through a model service and cannot call it directly. |
| 模型资料 | Model Record | 模型在基础资料中的参考档案，一个模型对应一份，记录模型展示名称、模型编码、作者、系列、精度、类型、输入输出模态、上下文长度等。创建上游模型、模型服务或模型卡片时可复制所需字段；复制后各模块各自维护，修改模型资料不会同步到已保存的记录。 | The reference record for a model in Basic Data, one per model. It stores the display name, model slug, author, family, precision, type, input and output modalities, context length and other details. When you create a provider model, model service or model card, you can copy fields from it. Copied values are then maintained separately, and later changes to the record are not synced. |
| 上游模型 | Provider Model | 某个模型在某个连接上的接入记录，保存上游模型 ID、容量和服务商成本价，测试通过后可启用。上游模型不等于模型：同一个模型经两个连接接入，就是两个上游模型。 | The record of a model on a specific connection. It stores the provider model ID, capacity and provider cost price, and can be enabled after it passes testing. A provider model is not the same as a model: one model onboarded through two connections is two provider models. |
| 模型服务 | Model Service | 平台向用户提供的可调用模型服务，具有统一的模型 ID，通过关联上游模型接入一个或多个上游模型，由路由策略决定每次请求实际调用哪个上游模型。租户订购模型服务，用户通过项目中的 API 密钥调用。 | A callable service MoMA offers to customers under a single model ID. It links to one or more provider models, and its routing strategy decides which one serves each request. Tenants subscribe to model services, and users call them. |
| 关联上游模型 | Linked Provider Model | 模型服务关联的上游模型，记录优先级、权重及在本服务内的启停状态。停用或移除关联上游模型只影响本服务，不改变连接和上游模型本身。 | A provider model linked to a model service, with its priority, weight and enabled state in that service. Disabling or removing it affects only that service, not the connection or the provider model itself. |
| 模型档案 ID | Model Record ID | 系统用于关联同一款模型档案的永久编号。 | A permanent identifier for linking records to the same model. |
| 模型编码 | Model Slug | 模型在平台内唯一的可读编码（接口字段为 canonical_slug），一个编码对应一个模型，例如 glm-5.3、glm-5.3-fp8。不同服务商提供同一个模型时用同一个编码。编码在登记模型资料时填写，创建后不能修改；格式为 1–80 个字符，只能使用小写字母、数字、中划线和点，以小写字母或数字开头。模型编码与模型 ID、上游模型 ID 是三个独立的字段。 | A unique, readable code for a model within the platform (API field canonical_slug), such as glm-5.3 or glm-5.3-fp8. Providers offering the same model share the slug. It is set when the model record is registered and cannot be changed. It is 1–80 characters of lowercase letters, digits, hyphens and periods, starting with a letter or digit. The model slug, model ID and provider model ID are three independent fields. |
| 模型展示名称 | Model Display Name | 用于识别模型的可读名称。模型资料、上游模型和模型卡片各自维护一份，取值可以不同，其中模型卡片上的那一份向用户展示。名称可以重复，调用时使用模型 ID。 | A readable name for a model. The model record, provider model and model card each keep their own copy, which can differ; the copy on the model card is shown to customers. Names can repeat and are not unique identifiers or API call identifiers. |
| 模型中文简介 | Chinese Model Summary | 模型卡片对用户展示的中文简介。 | A Chinese summary shown on the marketplace card. |
| 模型英文简介 | English Model Summary | 模型卡片对用户展示的英文简介。 | An English summary available in the marketplace details. |
| 热度设置 | Popularity Score | 用于模型广场推荐排序的可选非负数值。 | An optional nonnegative score used to rank recommendations. |
| 模型精度 | Model Precision | 模型权重使用的数值精度，例如 BF16。 | The numeric precision of the model weights, such as BF16. |
| 模型标签 | Model Tags | 模型广场维护的展示关键词。 | Display keywords maintained in the marketplace. |
| 模型发布日期 | Model Release Date | 模型作者发布该模型版本的日期。 | The date the model author released this version. |
| 参数量（B） | Parameter Count (B) | 模型的总参数数量，以十亿为单位。1 B 表示 10 亿个参数。 | The total number of model parameters, in billions. 1 B means one billion parameters. |
| 模型作者 | Model Author | 研发或发布模型的组织或团队。 | The organization or team that develops or publishes the model. |
| 模型系列 | Model Family | 同一开发者具有共同技术演进关系的一组模型。 | A group of related models that share a line of technical development from the same author. |
| 模型版本 | Model Version | 区分同一模型系列具体迭代的版本号或发布标识。 | A version number or release identifier for a particular iteration in a model family. |
| 模型类型 | Model Type | 按模型主要用途划分的类别，共七类：语言模型、多模态理解、视觉模型、语音模型、向量模型、重排序模型、其他专用模型。一个模型只属于一个类别；语言模型支持图片或视频输入时，仍归为语言模型。 | The model's primary purpose, one of seven categories: language, multimodal understanding, vision, speech, embedding, reranking, or other specialized models. Each model belongs to one category; a language model that accepts images or video is still a language model. |
| 输入模态 | Input Modalities | 模型能够接收的内容形式，例如文本、图像或音频。 | The forms of content a model accepts, such as text, images or audio. |
| 输出模态 | Output Modalities | 模型能够生成的内容形式，例如文本、图像或视频。 | The forms of content a model can generate, such as text, images or video. |
| 结果类型 | Result Type | 模型返回的结构化结果形式，例如向量、相关性分数或排序结果。 | The structure the model returns, such as a vector, a relevance score or a ranked list. |
| 上下文长度 | Context Length | 单次推理可处理的上下文 Token 上限，具体计算范围以模型接口约定为准。 | The maximum number of context tokens for one inference request. The API defines which tokens count toward the limit. |
| 最大输出 Token 数 | Max Output Tokens | 单次推理允许生成的 Token 数量上限。 | The maximum number of tokens a model can generate for one inference request. |
| 支持的参数 | Supported Parameters | 模型接口接受的请求参数集合，例如 temperature 或 top_p。 | Request parameters accepted by the model API, such as temperature or top_p. |
| 模型描述 | Description | 对模型能力、适用场景及限制的说明。 | A description of the model's capabilities, intended uses and limitations. |
| 服务商 ID | Provider ID | 系统关联服务商档案的永久编号。 | A permanent identifier for the provider record. |
| 服务商名称 | Provider Name | 在基础资料和连接列表中展示的服务商名称。 | The provider's display name in the provider directory and connection list. |
| 服务商编码 | Provider Code | 服务商创建时确定的业务编码，供运营识别和查询。 | A business code assigned when the provider is created. Operators use it to identify and find the provider. |
| 连接 ID | Connection ID | 标识一条共享接入连接的编号，用于定位连接列表中的具体连接。 | An identifier for a shared connection that locates the corresponding entry in the connection list. |
| 连接名称 | Connection Name | 运营人员为连接设置的名称，用于区分同一服务商的不同接入配置。 | An operator-defined name that distinguishes connections for the same provider. |
| 连接类型 | Connection Type | 连接的供给来源，分为第三方模型服务和自有模型推理服务。添加连接时先选择连接类型，再从该类型的服务商中选择。 | The source of a connection's capacity: a third-party model service or a self-hosted inference service. When adding a connection, choose the type first, then a provider of that type. |
| 服务地址 | Base URL | 按服务商文档填写的基础地址，保留路径和版本前缀。模型接入中指上游服务的地址，模型服务中指 MoMA 网关的地址。 | The API base URL, including the provider’s path and version prefix. In Model Onboarding it refers to the upstream service. In Model Services it refers to the MoMA gateway. |
| 接口格式 | API Format | 模型 API 的请求结构、响应格式及调用约定。平台支持 OpenAI Chat、OpenAI Responses、Anthropic Messages、OpenAI Embeddings、Ark Video、DashScope Video、MiniMax Video 等接口格式。 | The request structure, response format and calling conventions of a model API. Supported formats include OpenAI Chat, OpenAI Responses, Anthropic Messages, OpenAI Embeddings, Ark Video, DashScope Video and MiniMax Video. |
| 接口端点 | API Endpoint | 追加在服务地址之后的路径，例如 /chat/completions。模型接入中指上游接口，模型服务中指 MoMA 对外接口。版本前缀写在服务地址中；Anthropic Messages 按其 SDK 约定，服务地址不含版本，接口端点为 /v1/messages。 | The path appended to the base URL, such as /chat/completions. In Model Onboarding it refers to the upstream API. In Model Services it refers to the API MoMA exposes to clients. The version prefix belongs in the base URL. Anthropic Messages is the exception: by its SDK convention the base URL has no version and the endpoint is /v1/messages. |
| 接口版本 | API Version | 上游 API 要求指定的接口规范版本。 | The API specification version required by the upstream provider. |
| 服务区域 | Region | 上游服务提供访问的地理区域。 | The geographic region where the upstream service is available. |
| 认证方式 | Authentication Method | 平台向上游证明调用身份的方式。 | The method MoMA uses to prove its identity to the upstream service. |
| 上游 API 密钥 | Provider API Key | 由服务商签发、供 MoMA 调用上游服务的密钥。 | A key issued by the provider for MoMA to call the upstream service. |
| API 密钥 | API Key | 平台签发给用户的访问密钥，用户在项目中创建，用于调用平台的模型服务。与上游 API 密钥相互独立。 | An access key MoMA issues to users. Users create it in a project to call model services. It is separate from provider API keys. |
| 上游 API 密钥组 | Provider API Key Group | 供连接引用的一组上游 API 密钥。 | A group of provider API keys that connections can reference. |
| 上游模型 ID | Provider Model ID | 上游服务商实际识别的模型标识，保存在上游模型上，通常作为上游 API 请求中 model 参数的值。同一模型在不同连接上的上游模型 ID 可以不同。 | The model identifier the upstream provider recognizes, stored on the provider model and usually sent as the model parameter in upstream requests. The same model can have different provider model IDs on different connections. |
| 容量 | Capacity | 上游模型在上游的额定性能上限，按上游模型单独设置，不从同一模型、同一服务商或共享连接继承。可配置 RPM、TPM，并按需添加并发上限、RPD、TPD、RPS、输入 TPM、输出 TPM、IPM；未配置的指标视为无上限。容量记录上游额定值，不代表实时剩余额度，与对用户的限流配置相互独立。 | The rated upstream limits for a provider model, set per provider model and not inherited from the model, provider or shared connection. You can set RPM and TPM, and add concurrency, RPD, TPD, RPS, input TPM, output TPM or IPM as needed. Unset limits are treated as unlimited. Capacity records rated values, not real-time remaining quota, and is separate from user rate limits. |
| 测试结果 | Test Result | 管理员手动发起连接测试或上游 API 密钥检测得到的结果，分为未测试、通过、失败、已过期，有效期 24 小时。服务地址、上游模型 ID 或上游 API 密钥变化后需要重新测试。测试通过是启用上游模型的前提。 | The result of a connection test or provider API key check started by an administrator: not tested, passed, failed or expired. Results are valid for 24 hours and must be redone after the base URL, provider model ID or provider API key changes. A provider model must pass testing before it can be enabled. |
| 健康度 | Health | 根据最近三个 UTC 自然日的上游调用记录计算的上游模型运行情况，分为健康、异常、样本不足、暂无观测。健康度只用于观测，不改变启停状态。 | How a provider model has performed, based on upstream calls over the last three UTC calendar days: healthy, unhealthy, insufficient data or no data. Health is for monitoring only and does not change enabled states. |
| 连接状态 | Connection Status | 连接的管理开关，表示运营人员已启用或已停用该连接。 | The administrative state of a connection, either enabled or disabled. |
| 已接入模型数 | Connected Model Count | 当前连接中已完成接入的模型数量。 | The number of models connected through the connection. |
| 模型服务名称 | Service Name | 后台用于识别和管理模型服务的名称，与已有名称重复时会提示。用户在模型广场看到的是模型卡片上的模型展示名称。 | The name administrators use to identify and manage a model service. A warning appears if it duplicates an existing name. Customers see the model display name on the model card instead. |
| 模型服务 ID | Model Service ID | 系统标识具体服务记录的永久编号，供广场、销售等模块关联。 | A permanent identifier for a model service record. The marketplace, sales and other modules use it to link to the service. |
| 模型 ID | Model ID | 用户调用 MoMA 时在请求参数 model 中填写的值，由模型服务维护。 | The value a user puts in the model parameter when calling MoMA. The model service maintains it. |
| 模型映射 | Model Mapping | 模型服务与上游模型之间的绑定关系，在模型服务中以关联上游模型维护，决定该服务可以使用哪些上游模型。 | The binding between a model service and provider models, maintained as linked provider models on the service. It determines which provider models the service can use. |
| 关联上游模型状态 | Linked Provider Model Status | 关联上游模型在当前服务中的状态，分为已启用、已停用。已启用且所在连接可用时，才会被路由选中。 | The state of a linked provider model in the current service: enabled or disabled. It can be selected by routing only when enabled and its connection is available. |
| 服务描述 | Service Description | 在模型服务中维护的该服务说明。 | A description maintained on the model service. |
| 路由策略 | Routing Strategy | 模型服务关联多个上游模型时，系统选择本次请求使用哪个上游模型的策略，包括加权随机、最少并发、低延迟优先、按用量分流、成本优先五种。 | How the system chooses which linked provider model serves a request when a model service has several. Five strategies are available: Weighted Random, Least Busy, Lowest Latency, Usage-Based Routing and Lowest Cost. |
| 优先级 | Priority | 上游模型被选择的先后顺序，数值越小越优先。 | The order in which provider models are preferred. Lower numbers have higher priority. |
| 路由权重 | Weight | 加权分流时，同一优先级的可用上游模型之间分配请求的相对权重。 | The relative share of requests assigned to an eligible provider model in the same priority group when weighted routing is used. |
| 故障转移 | Fallbacks | 当前目标调用失败且满足切换条件时，转向允许的备用目标。 | Alternative targets that can be used when the current target fails and switching conditions are met. |
| 重试次数 | Max Retries | 首次尝试失败后，策略允许额外尝试的最大次数。 | The maximum number of additional attempts allowed by the policy after the first attempt fails. |
| 超时时间 | Timeout | 调用策略允许等待的最长时间，具体值需同时标明单位和作用范围。 | The longest wait the call policy allows. The value has a unit and an applicable scope. |
| 服务状态 | Service Status | 模型服务是否受理该模型 ID 的请求，分为服务中、已停服。新建服务为已停服；至少有一个可用的关联上游模型时才能启动服务。服务中但没有可用的关联上游模型时，系统标注“无可用上游模型”。 | Whether a model service accepts requests for its model ID: in service or stopped. New services start stopped and can be started only when at least one linked provider model is available. A service that is in service but has no available linked provider model is marked “No Available Provider Model”. |
| 可见范围 | Visibility Scope | 模型卡片为灰度可见时能看到卡片的用户范围，按租户选择。预告可见和全部可见时对全部用户可见，不使用可见范围。 | The tenants who can see a model card when its visibility is limited. Preview and public cards are visible to everyone and do not use a scope. |
| 模型卡片 | Model Card | 模型广场上对用户展示的单位，一款模型对应一张卡片。卡片维护模型展示名称、中英文简介、图标、类型、模态、标签等展示信息，可关联一个或多个模型服务，并有独立的可见性和可见范围。修改基础资料不会同步到卡片。 | The unit shown to customers in the model marketplace, one card per model. It holds the display name, Chinese and English summaries, icon, type, modalities, tags and other display details. A card can link to one or more model services and has its own visibility and visibility scope. Changes to Basic Data are not synced to cards. |
| 可见性 | Visibility | 模型卡片在模型广场的可见程度，分为不可见、预告可见、灰度可见、全部可见，新建卡片为不可见。预告可见时全部用户可见，但卡片显示“敬请期待”、不能进入详情；灰度可见时，仅可见范围内的用户能看到并进入详情；灰度可见和全部可见须关联至少一个服务中的模型服务。可见性只控制展示，不影响售卖。 | How visible a model card is: hidden, preview, limited or public. New cards are hidden. In preview, everyone sees the card marked “Coming soon” but cannot open details. In limited visibility, only users in the visibility scope can see it and open details. Limited and public cards must link to at least one model service that is in service. Visibility controls display only and does not affect sales. |
| 计费项 | Billing Item | 独立计价的资源项目，例如输入 Token、输出 Token 或缓存读取。 | A resource billed separately, such as input tokens, output tokens or cache reads. |
| 计费单位 | Billing Unit | 单价对应的资源数量单位，例如百万 Token、次、张或秒。 | The quantity a unit price applies to, such as one million tokens, a request, an image or a second. |
| 币种 | Currency | 价格使用的货币代码，例如 CNY 或 USD。 | The currency code used for a price, such as CNY or USD. |
| 服务商成本价 | Provider Cost Price | 平台通过连接向上游采购模型的实际成本，按上游模型和计费单位维护，并保留版本，用于成本和利润核算。以明确配置的金额为准；缺价时保持待核算，不视为零。 | What MoMA actually pays the upstream provider per billing unit, maintained per provider model with version history for cost and margin accounting. Only explicitly configured amounts count; a missing price stays pending and is not treated as zero. |
| 模型刊例价 | Model List Price | 平台对外公布的标准价格，租户订购和调用都按此计费。按模型服务定价，一个模型服务对应一个模型刊例价，所有租户使用同一价格。发布后对新请求生效，已开始的请求和历史用量保留原价格。由商业运营的模型销售维护，与服务商成本价相互独立。 | The published standard price tenants are billed for subscriptions and calls. It is set per model service, one price for all tenants. A newly published price applies to new requests; requests already started and past usage keep the earlier price. It is maintained in model sales under business operations and is separate from the provider cost price. |
| 价格版本 | Price Version | 服务商成本价或模型刊例价在某个生效期内的记录，供历史计费和核算追溯。 | A record of a provider cost price or model list price for a given validity period, kept for historical billing and accounting. |
| 模型售卖 | Model Sale | 仅商业版。模型服务在商业运营中的销售配置，包括模型刊例价、销售对象和售卖状态，一个模型服务对应一条。模型服务须配置售卖并开售后，租户才能订购。 | Commercial edition only. The sales configuration of a model service in business operations, including its list price, sales scope and sales status; one per model service. Customers can subscribe only after the service has a sale configured and is on sale. |
