### 前台两模型一致性验收

- 默认两张模型卡片按发布日期排序；GLM-5.3 的两个服务商服务在详情切换，DeepSeek-V4-Flash-0731 为统一模型服务模式。全部模型保留 Kimi、hy3 及其他历史资料，不能按同名合并身份。
- 详情售价取已发布销售快照，MoMA 渠道直选模式输入/输出为 CNY 3/9 每百万 Token，原厂及统一模型服务模式为 CNY 2/8；未发布草稿、采购成本、凭证及内部地址不得泄露。
- 每个服务的调用 ID、四语言示例与后台一致，在线体验进入所选服务；体验选择器和新回复标明提供方，历史身份不随当前选择变化。未知价格与免费分开，失效授权保留阻断。
- 浏览器实走详情、提供方切换、代码复制、在线体验和返回焦点；用户已有草稿保留，Mock 回复不当作真实上游和计费验证。

### 界面、新人试用与完成判定

- 主路径从模型服务或概览发起，不要求按供应/资料/服务三页手工拼接。四页签、四步骤、面包屑、按钮、运营入门与研发说明分别使用当前目标名称和含义。
- 入门指导按零页面经验验证：只读教程即可指出导航分组、搜索框、结果项、当前模型和下一步按钮；字段有资料来源，前置条件不足有暂停/恢复路径，保存与生效有可观察结果。按[新人试用 T0](MODEL_OPERATIONS_NEWCOMER_TRIAL.md)记录实际求助和阻断，不能用文本存在或代理走查替代真人独立完成。
- 展示资料须核对后台分区与前台对应：公共字段只编辑一次，短简介与详细介绍分开；资料草稿不进入卡片或详情，发布后仍复用原服务身份与客户范围。Logo、正式发布日期、能力/接口属性只显示已知事实，且客户投影不含采购成本、凭证、内部地址与资料核对记录。详情在常见桌面视口和长内容下可读，关闭/体验与键盘操作可达。
- 列表只展示必要服务状态及当前事项；未检查、备用无流量、主动停用与真实异常不可混为一类。概览直接展示统计筛选与数据，不提供当前运营任务汇总块。
- 在 1280×800、1440×900、1920×1080、键盘及文字放大条件下检查受影响页面；主要动作、错误、确认/取消、滚动和返回焦点可达。不把一个页面通过扩展为全站或全浏览器通过。
- 邀请未参与设计、符合背景的运营，提供必要业务信息后执行首次接入和典型维护。记录完成、误选对象/入口、求助、回退、误判生效、输入丢失和实际耗时。依赖主持人解释才能完成的路径不能算独立完成；不预设未经测量的分钟数或提升比例。
- UX01—UX12 的行为断言、受影响界面路径和关键新人任务均具备证据，且无对象误判、生效误判或数据丢失等阻断项，才可声明对应范围验收完成。缺真实运营参与时明确标为待试用，不能由代理自测代签。
- 原型模拟订购和调用仅验证本地规则；真实厂商、认证、生产扣费和负载能力不在本次通过声明内。

- 四页签增量：模型资料默认展示卡片/详情/其他信息并复用共享主档；路由及映射独立维护服务模式、调用 ID 和供应映射；售价发布不能夹带调用 ID；客户范围保留页头入口。任务、缺项、向导返回和共享维护返回须到达实际区域，未保存保护保留。
- 服务模式说明：首次选择和切换弹窗均在未选择时即可阅读两段简短说明，清楚区分用户是否选服务商、调用 ID/价格及平台调度范围；未选择不可提交，选定后仍须确认；切换保留下架和重新配置提醒，取消及放弃修改不改变当前模式。
- 操作记录按时间、操作、对象、操作人、结果展示并分页，不静默截断；新增记录冻结受影响模型集合，不能因后续新关联把历史操作归给无关模型。缺少关联快照的旧记录只依据其明确记录的模型/主档身份归属，不从当前供给关系倒推。失败尝试记录不包含提交参数或密钥，写入失败不修改原业务配置。

路由策略、参与渠道及权重默认只读；每个服务的路由策略单元格（包括“尚未配置”）为路由编辑入口，点击直接编辑对应服务。移除顶部重复按钮及服务商选择弹层，渠道行的编辑入口保留；仅编辑态提供“取消”和“保存并生效”。取消恢复原配置并返回编辑入口；保存经变更核对及现有权限、并发和策略校验后生效并返回只读，失败保留输入。

统一模型服务模式与渠道直选模式售价在“售价管理”Tab 内原位展示及编辑，复用同一价格表；完整显示全部计费项，金额、币种和单位清晰对应。展示态提供“编辑售价”，编辑态提供添加、移除、取消和预览变更；取消恢复当前生效售价，未保存修改仍需确认。价格表业务字段顺序为服务商名称、请求模型名称、计费项、售价、计价单位，末尾保留编辑操作列。统一模型服务模式的服务商名称读取稳定记录 provider-moma 的当前名称；该内置平台服务商在服务商目录置顶，禁止删除。渠道直选模式读取对应服务商的当前名称。请求模型名称读取对外调用标识（统一模型服务模式为模型级 ID，渠道直选模式为对应服务 ID），tooltip 为“用户调用时填写的 Model ID”，在售价页只读，仍在路由及映射维护。售价单元格内保留金额与币种，不新增独立货币列；不展示适用条件输入列及售价历史区域。保留既有条件数据、历史版本及发布校验。

工作区不显示配置检查提示块；页头保留既有配置状态，接入任务继续入口保留。移除页头“维护客户范围”和“平台试调用”按钮；调用验证从“平台试调用”页签进入。渠道列表不常驻“可用”标签；供给检查结果及原因放入渠道详情。渠道详情提供明确的打开入口并保留当前对象上下文；统一模型服务模式与渠道直选模式共用，保留详情字段、权限及原有操作确认，Esc/关闭后焦点回到对应按钮。模型映射列表明确标注“上游模型标识”，对外调用标识 由对应服务统一展示。Radix 表单代理控件不重复绘制。

后台 API 调用指南提供 cURL、Python、Java、Go 示例；各示例独立编辑、取消、保存并生效、复制和格式化所选 JSON。编辑时提供名称明确的“预览”和“输入代码”区域，窄屏与键盘操作保持可达；一次编辑一个示例，前台语言切换保持不变。

模型服务目录创建区仅“新增模型服务”为主按钮，移除“更多模型创建方式”及其接入/批量导入菜单；不再单独显示接入主按钮、批量导入图标或演示范围选择器。目录数量仅在标题显示。演示模型/全部模型切换位于研发说明中的模型服务案例区，使用原有目录查询和未保存守卫，已有记录与当前模型上下文保留。新增服务必须从模型接入中已登记的模型选择，候选与模型接入的模型视图共用供应登记查询，按主档去重；没有供应登记的模型资料不进入候选，已有服务的模型仍显示但禁止重复创建。进入新增服务须保留 catalogue 参数；已有服务的资料仍标记并禁用重复创建。历史与手工资料不删除、不改名、不合并。

新增模型服务标注“已接入模型”为必选，提供“前往模型接入”入口；服务端重新检查主档和当前供应登记关系，关系已移除时拒绝保存，跳转保留未保存保护。 对尚未进入当前服务目录、但已占用内部服务身份的历史主档，创建时原子复用其稳定服务ID并保留独立主档，禁止重复创建；新服务保持未上架和调用关闭，既有供应、价格和路由历史保留。

## 模型运营配置与用户数据保留

- 系统基础目录、历史评审初始差异及当前运营场景分别由 src/mock 内 JSON 定义，构建校验唯一 ID 和跨集合引用；错误配置阻断构建。GLM-5.3 复用 model-glm53 / template-glm-5.3，禁止同编码不同身份的案例静默合入。
- 没有存档时初始化一次；后续只读回存档，不执行旧的自动补齐生成器。删除、手工改名、凭证、采购及售价历史、路由、未发布草稿在刷新和再次准备后不被覆盖或复活。
- modelData 分别标记内置 ID、用户变更 ID、初始配置版本及当前场景 ID；修改内置资源保留内置身份并记录用户修改。没有来源标记的旧记录保持用户已有数据，不按名称归类或清理。
- 基础资料、服务商目录、渠道映射和模型服务共用目录关系。新增手工主档刷新后可在基础资料及新增服务选择器找到；已有服务仍禁止重复创建，全部范围可查历史。
- 前台只使用后台生效资料、售价和明确发布的服务身份；渠道直选模式 MoMA/智谱切换联动调用 ID、四语言指南和体验，统一模型服务模式始终单一入口；未发布草稿与内部采购信息不泄露。
- 配置通过现有 Vite 静态构建，不依赖本机文件接口。Cloudflare 域名与本地域名的用户存档相互独立；本轮不部署，不实现跨浏览器云同步，也不以 Mock 证明真实上游连通或扣费。

## 模型运营阶段2：服务模型映射

- 新增映射只选择当前主档下已检测启用的供给；渠道直选模式不可跨服务商，伪造关联、验证结果和过期修订必须原子拒绝。
- 预览不写数据；保存后不启用、不自动修改路由／价格／上架；服务端核验再启用。新增、名称修改、候选保存／验证／应用／放弃、停用／解除刷新后保留；取消未保存输入不改变原数据。
- 候选未应用前原有效关系和证据继续生效；在用目标不可原位切换。生效路由、草稿（含未参与条目）和未完成任务引用阻断危险操作；解除保留供给及历史。
- 配置核验复用供给检测证据，不是新上游调用；不支持的协议组合应拒绝。真实上游连通、阶段3路由停用恢复及完整上架闭环不在本阶段验收结论内。
- 结果依据见 MODEL_ONBOARDING_PROGRESS.md；独立本地D1流程走查不向生产写入案例。

## 模型运营阶段3：单渠道路由

- 新建默认固定渠道但不预选映射；固定选择一个已启用且通过当前检查的目标。预览展示旧新渠道，确认只变更本服务路由，取消及失败保留原配置；不重写原有其他策略。
- 停用要求服务已停服，市场隐藏不豁免；渠道直选模式支持单组停服并停用路由，不改变其他组。草稿清空需明确确认；映射、凭证、价格和历史保留。
- 恢复重查现供给，失效、停用或已删除映射阻断；有草稿不隐式覆盖。恢复不采纳客户端伪造的替代配置，不自动上架或恢复服务；生成新历史记录，旧记录不变。
- 新请求应命中替换目标，停用后不能回落至其他供给。HTTP／D1验证稳定ID、刷新保留、原子拒绝、重复提交幂等及外键完整性；页面走查配置、替换取消、差异确认、停用／取消／恢复、阻断与刷新、服务商隔离及小屏布局。实际证据见MODEL_ONBOARDING_PROGRESS.md。

## 模型资料表格导入

- 模型资料入口明确为“批量导入模型资料”；上传页只提供 XLSX / UTF-8 CSV，不出现粘贴输入区。填写提示常驻，正文 14px，按填写规则和类型任务分行。
- 下载模板为真实 XLSX，前三列必填项使用红色表头并注明“必填”，第四列视觉任务类型使用橙色表头并注明“视觉模型必填”，其余选填；首行和前三列冻结，附“填写说明”工作表。下载文件原样上传时表头标记能正确识别，说明工作表不计入模型行。模板覆盖资料表单的全部可编辑字段及各类型任务规格；必填规范模型标识、模型名称、模型类型，视觉模型另填图像或视频。可选列可删除或调序；未知/重复表头、缺少必填表头、超出 500 条或 10 MB 拒绝导入，空行后保留真实文件行号。
- 名称、标识、类型以外的未知资料可留空，未知能力不补为“不支持”或 0。校验使用现有资料规则，检查任务适用性、模态、日期、数值、参数 JSON 与支持参数依赖；不适用字段明确报错，不静默丢弃。支持月精度日期及 Excel 日期单元格。
- 上传自动进入预览，展示作者、原厂发布日期、模型类型/任务、输入/输出及逐行错误；可查看全部已填字段、只看问题、下载含完整字段的清单、重新上传。存在错误时须明确勾选跳过问题行才允许导入有效行，全错时不可提交。
- 最终提交沿用既有资料原子事务、权限、修订及失败保护。只新增资料，不覆盖相同标识，不创建服务或供应资源；取消、只读和预览均不写业务数据，提交失败保留预览。导入完成刷新后仍能查看同一份资料。

## 服务映射补齐、密钥优先级与上架操作

- 关联服务商时可以创建全新服务商并返回选择，确认关联后独立维护调用标识。路由编辑不提供接入新渠道；供应模型登记与新渠道配置统一在渠道接入模块完成。
- 在渠道接入完成新渠道保存、检测与明确启用后，返回服务的路由编辑器；选择目标、核对调用关系、确认后原子建立模型映射与路由。保存渠道不自动加入路由或上架。取消保留已明确保存的服务商、登记及渠道。
- API 密钥池按优先级排序，名称在前、短 ID 在后，底层稳定 ID 与引用保留。相邻上移／下移支持边界禁用、刷新保留、修订冲突、角色与写失败保护；服务商中不同 ID 的已存记录不因演示指纹相同而丢失，旧渠道别名保持原维护范围。备用排序不触碰当前调用；切换共享组首位密钥须测试全部引用、明确应用后原子切换。
- 服务操作仅包括灰度上架、正式上架、下架与可见性配置。灰度仅选择当前授权内的有效客户，与实时调用授权取交集；正式上架结束灰度限制并保留原授权。空范围、未授权客户、过期修订、越权和存储失败必须原子拒绝。两种上架复用现有经营检查，不能启用停用中的技术服务。下架与可见性不重写价格或授权；技术启停、归档与平台试调用仍可从各自页面进入。

证据按实际结果记录在 [进度](MODEL_ONBOARDING_PROGRESS.md)，管理端及模拟验证不代表真实上游、生产网关或租户调用端已完成。
