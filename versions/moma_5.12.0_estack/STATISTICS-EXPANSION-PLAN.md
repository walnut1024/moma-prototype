# MoMA 新增统计页面方案

状态：方案，尚未实现或增加导航。范围依据《Token工厂需求清单》与本轮确认；所有与金额相关的指标、费用与成本分析均不纳入；Token 补贴平台、财务管理、消费用户数及消费留存暂缓。

## 现有页面本轮补齐

| 页面 | 本轮范围 |
| --- | --- |
| 运营概览 | 今日新增注册、登录用户、调用活跃用户与 Token 消耗 |
| 用户数据 | 注册/登录/调用活跃趋势、Token 用量趋势、用户 Token 用量排行 |

本轮仅新增调用、Token、身份行为、容量及运行质量相关指标，不修改原有价格和计费功能。消费用户数不以调用活跃人数替代。

## 1. 登录留存分析

- 建议入口：运营 → 运营分析 → 留存分析。首版只处理登录留存、登录回流和沉睡；消费用户与消费留存按本轮决定暂缓。
- 建议用注册日形成用户队列，展示次日、7 日、30 日成功登录留存。分母是该日去重注册用户；分子是对应自然日成功登录的同批用户。观察窗口未完整结束显示“观察中”，不计为零。
- 主体为队列矩阵和所选队列趋势；支持政企/个人身份筛选。点击单元格查看队列人数、留存人数和明确用户 ID。
- 回流建议定义为连续 7 个完整自然日无成功登录后再次登录；沉睡建议定义为截至统计截止连续 30 个完整自然日无成功登录。阈值为待确认的方案值，实施时写入指标说明，不根据无调用推断未登录。
- 数据来自显式注册与成功登录事件。历史事件覆盖不足时显示“历史不足”；用户 ID、租户 ID、Key 所有者互不替代。
- 验收：与用户页注册和登录人数对账；同用户多次登录只计一次；跨月和北京时间零点正确；不完整队列不压低留存率。

## 2. 容量中心

- 建议入口：运营 → 模型运营 → 容量中心；默认只读汇总，配置仍跳转已有渠道容量抽屉。
- 默认按模型分组，可切换按供应商分组，展开具体渠道。支持模型类型、供应商、渠道筛选。
- 列：模型、供应商、渠道、配置 RPM/TPM/并发及其他额定指标；配置未采集明确区分。近 24 小时实际分钟均值、峰值、429 和超时次数从调用事实汇总。
- 额定限额是配置值，实际使用量来自观测，二者不互相补值。仅在明确同一渠道、同一模型、同单位且实际窗口可比较时展示用量/额定限额，不冒称实时剩余额度。
- 验收：同供应商多渠道不合并限额；共用连接不联动覆盖；未配置不显示零或无限；点击详情保留模型及渠道 ID；配置仍经过原事务、权限和修订校验。

## 3. 健康度中心

- 建议入口：运维 → 网关管理 → 健康度中心。共用调用日志的上游尝试事实，运营可通过只读入口查看。
- 默认近 24 小时，支持供应商/渠道/模型与自定义范围。展示上游成功率、失败数、429、超时率、P95 上游耗时和有效样本量，支持进入对应上游尝试日志。
- 首版建议按成功率显示最佳/最差各 5 家，并允许按超时率或 P95 排序。该排序明确称指标排名，不标为综合评分；样本不足的对象独立列出，建议最少 100 次已判定尝试。
- 若必须提供综合分，实施前需要确认各模型的时延目标、成功率目标、权重和最低样本量，再按模型目标归一化后汇总。不能直接把不同模型的原始时延相加评分；没有探测数据时不宣称在线或离线。
- 验收：平台鉴权/配额拒绝不算供应商故障；重试按实际渠道归属；未知结果不进成功率分母；无样本不默认满分；排名与同一范围内的上游尝试事实对账。

## 后续数据接入边界

当前模型详情展示的是当前空间可查看的调用记录。平台公开性能/稳定性大盘需要独立的服务端聚合与公开范围约束，不能把其他客户的原始调用、客户数或采购成本送到浏览器再过滤。该数据接入不在本轮实现。

建议实施顺序：容量中心 → 登录留存分析 → 健康度中心。各页确认数据与口径后独立验收。
