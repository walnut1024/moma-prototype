# 5.12.0 页面当前约束

本文件汇总本版本有效页面与业务约束。模型运营以本页导航和各模块规则为准；实际本地验证及发布边界见[实施台账](MODEL_ONBOARDING_PROGRESS.md)。历史 UX 文档不恢复已移除的入口或旧前置条件。

## 全站 Mock 数据与双面联动

- 5.12.0 初始资源、参考目录和模拟响应统一在 `src/mock/` 配置维护，模型运营和前后台业务交互由 Worker 与 D1 统一持久化，浏览器只保留对话草稿、界面偏好和独立表单演示；详见 [Mock 数据合同](MOCK_DATA.md)。本节替代共享页面中“组织及成员仅保存在独立前台样例”的旧约束，仅适用于本版本。
- 系统初始数据与用户配置分开标记；恢复存档不重放初始生成器、不补回删除资源。手工记录、草稿、订单、历史与未知来源数据保留，旧无归属记录不自动认领。
- 前台 Key、订购、组织及成员、客户智能路由和在线体验记录落到共享业务集合；客户作用域、所有者、修订冲突及存储错误在写入边界校验。后台修改相同记录后，前台经事件、同源标签页更新或聚焦复查读取新值。
- 调用日志、租户用量、平台概览及用户统计从同一请求和显式身份事件派生。未采集 Tokens、费用或时延显示未知；本地回复不构成真实上游或计费证据。图表样例继续使用静态 JSON 配置和原有派生逻辑；不写入 D1。用户侧未迁移模块仍使用浏览器存储，不与 D1 自动双写。
- 前台编辑在打开时冻结修订号，跨标签页更新不得静默覆盖当前输入；冲突保留输入并要求刷新。账号/客户切换清除旧临时表单及明文 Key，已保存筛选视图按身份隔离。关闭 Key 额度后保存/刷新保持不限，相同额度与周期重新启用保留原用量；TPM/QPM 按实际值保存和模拟校验，不豁免客户额度与权限。
- 统计分类匹配实际模型类型，基础模型筛选纳入其服务商服务调用；请求保留发送时调用 ID，未知计量不填零，音频秒数/字符与 Token 分开。不使用固定样例数作为当前套餐权益或剩余额度。
- 动态历史样例只绑定固定初始资源且保留有效归属，不能因新增/编辑 Key、模型或成员而重分配历史；用户真实动作产生的请求独立保留。重复 Request ID 校验 Key、客户、模型及服务归属，冲突不返回原记录，已撤权 Key 不能重放成功。

## 模型运营云端持久化

- `listing`、`providers`、`model-market`、`model-costs`、`model-prices`、`model-templates`、`tariff-dictionary` 使用 `/api/v1/`。模型资料、服务商、密钥组/池、渠道及映射、采购/售价历史、服务、路由、检测与试调用、发布和操作审计均落 D1；筛选和未提交输入保留在浏览器。
- 后端以 HttpOnly 会话确认账号及权限，复用 5.12.0 领域规则；前端提交预期修订和操作 ID。业务变更、模拟状态、回执和审计一次原子保存，成功后才关闭编辑；失败保留输入，未知提交结果先核对原操作，冲突要求载入最新数据。断网不回退为本地保存成功。
- 新 D1 初始化计费字典和参考模型主档。平台管理员在研发说明中显式导入两套模型服务演示案例及其依赖，成功后保持下架。已有工作区启动时读取原数据，导入复用同一主档，记录冲突时整包拒绝。
- 用户侧广场、模型详情、按 Token 用量订购及详情在线调用使用 `/api/v1/market/`。客户身份、渠道订单和调用记录由 D1 校验及保存。旧浏览器存档保持原状；体验页、API Key、组织、智能路由、套餐订单及用量查询读取同一客户空间。体验、网关及扣减只执行模拟。

## 导航与共享页面

- 后台顶栏控件、导航、面包屑、模块页签和模型运营／套餐运营登录采用 Semi Design 原生组件。登录保留账号、密码与原认证流程，错误信息紧邻表单；窄屏可使用导航弹窗，短窗口允许滚动。
- 旧后台通用样式只应用于标记为旧版的页面内容和对应弹层，外壳、新版 Semi 页面及前台保持各自样式。后续页面迁移完成时移除该页面的旧样式标记。
- 后台 2 运营分析为用量数据、用户数据两个同级入口；运营和系统管理员可访问，运维不可访问。运维入口称调用数据，保留 `call-analysis` 路由。模型运营依次为渠道接入、模型服务（默认入口）、模型广场、模型成本、模型售价、模型资料。 各子功能入口在页头标题下展示一条职责说明。模型资料按模型、服务商、计费项、计费单位、货币排列，维护模型与服务商主档和共用字典；模型售价的“计量配置”进入字典页面，切换字典页签保留来源返回路径，面包屑统一归属模型资料。
- 不提供独立 `service-routing` 页面；路由在模型工作区“路由及映射”维护，领域事务、历史配置和数据保留。概览为运营默认首页，不恢复旧独立工作台或安全治理模块。
- 运营导航底部的入门指导分组保留“模型运营”指南（`getting-started`），运维不可访问；接入和维护流程就近提供帮助，不强制先读教程，不因首次登录强制新建。渠道接入不恢复旧使用引导弹窗。
- 面包屑复用版本内 `breadcrumbs.mjs`。向导为“模型运营 > 接入并上架模型”，返回注明来源；任务跳转保留模型、页签、筛选及当前输入，缺失对象不静默替换。普通详情不重复返回按钮；独立订购页返回当前版本订购入口。
- 租户空间、账号认证、调用日志、API Key、客户与后台账号沿用[对应共享页面章节](../../docs/PAGE-SPEC.md)；用户管理、账号管理、Token 生产等模块的保留与入口以本版本规格为准。前台隐藏模型排行，组织及成员/组织操作记录仅政企空间，调用日志不向个人空间渲染。

## 流量运营

- 限流配置页使用 Semi Design 卡片、页签、表格、表单、弹窗、抽屉和反馈组件。运营区「流量运营」下提供「用户限流」「模型限流」两个页签，默认进入用户限流。平台管理员和运营人员可访问。
- 用户列表显示账号名称、账号 ID、账号类型、默认值、生效值、规则来源、一客一策条数和操作。默认值取用户全局默认，生效值取账号通用额度。两个值均包含 RPM 和 TPM。支持按账号名称或 ID 搜索，以及按账号类型筛选。通用额度可单独或批量修改、恢复全局默认，已有一客一策仍按模型匹配。筛选、切换页签和批量操作成功时清空选择。
- 全局默认在 D1 初始化为 60 请求/分钟和 300 万 Tokens/分钟，放在用户列表搜索行，Tooltip 说明继承规则。新账号和没有自定义通用额度的账号使用当前值。
- 点击账号行的一客一策条数打开右侧宽抽屉，显示账号名称和 ID，支持搜索并添加模型、修改额度和移除，统一保存。一个账号的同一模型只能配置一条额度。账号规则优先级依次为一客一策、账号自定义、全局默认。
- 账号行的「限流可视化」打开只读宽抽屉，展示通用额度以及各模型的账号侧额度、命中规则、模型共享上限和最终上限。RPM 和 TPM 分别取两侧较小的值，账号侧额度无法读取时最终上限显示「—」。
- RPM 使用请求/分钟。TPM 固定以百万 Tokens/分钟展示和输入，最多 6 位小数。组合额度在数值旁直接标注 RPM 和百万 TPM。保存时 RPM、TPM 均为正整数。
- 模型限流搜索行沿用用户限流布局，右侧维护「模型默认」，D1 初始值为 600 请求/分钟和 3,000 万 Tokens/分钟。列表展示 D1 模型资料主档的名称、标识、默认值、生效值和规则来源。模型共享上限按主档关联，由调用该模型的账号共用。单模型可覆盖默认或恢复为继承当前默认。
- 页头「变更历史」打开只读抽屉，按时间倒序展示变更时间（北京时间）、变更对象、操作、变更前、变更后和操作人。D1 记录两类默认、账号通用额度、一客一策及单模型覆盖。批量操作按实际改动的账号列出，一客一策按模型列出增改删，恢复默认显示继承关系。旧审计缺失的字段显示「未记录」。
- 两个页签使用同一个后台登录会话读写 D1 限流配置。用户列表复用用户管理的账号 ID，模型关联复用 D1 资料主档 ID。读取失败提示登录或重试，缺失额度显示「—」。保存同时提交配置与审计，校验角色、修订号与幂等标识，失败保留输入。浏览器旧存档保留，当前生效配置以 D1 为准。当前原型范围为配置及规则解析。

## 套餐制作

- 套餐制作和套餐数据复用后台 Semi 页头、卡片、筛选和小尺寸表格。套餐制作包含「套餐列表」和「模型抵扣系数」两个页签，默认进入套餐列表。套餐在独立表单编辑，右侧为购买页预览。抵扣规则按模型分组，在弹窗编辑。离开未保存的表单时可继续编辑或放弃本次修改。
- 运营区「套餐运营」下提供「套餐制作」，平台管理员和运营人员可访问。列表以名称或套餐编号搜索，按套餐形式和状态筛选，统一分页。套餐形式为按周期订阅或一次性资源包，首次保存后只读。套餐类型可选个人版、团队版或平台管理员添加的共享类型。新建、编辑和查看为独立表单，返回保留筛选和页码，离开时保护未保存输入。
- 订阅套餐配置每周期 Token 额度、周期售价、订阅周期、总周期数和余量结转规则。资源包配置每份 Token 总额度、单价和生效后的有效天数。两类共用套餐名称、购买页展示名称、简介、顺序及每位用户累计限购份数。支持订购的用户类型可多选政企用户、个人用户，新建默认全选，发布和上架至少选一项。展示顺序可填 0 至 200 的整数，数值越小越靠前，留空排在最后。购买页预览在大号套餐名称下方显示一行简介，并展示有效期限。
- 按月、季度、年订阅分别按原生效日期加 1、3、12 个日历月推算周期边界，目标月缺少对应日期时取月末，后续仍以原生效日推算。当前套餐制作展示规则，实际订购到期时间由权益系统计算。
- 状态为草稿、待上架、已上架、已下架。新增和编辑表单的「保存」将套餐存为草稿，允许缺少发布必填项。发布从列表发起，校验通过后进入待上架，操作为编辑和上架。仅从未发布的草稿可在列表确认删除，移除后保留审计且编号不复用。上架与下架需确认。已上架套餐只读，修改下架或待上架套餐后需重新发布。下架只停止新订购，已购权益用尽或到期后结束。
- 平台管理员可删除未被套餐引用的自定义类型，删除需确认。内置类型和被任意状态套餐引用的类型不可删除，删除成功后从选项中移除并保留审计。
- 「模型抵扣系数」列表展示已添加的模型，新增选项来自「模型服务」中尚未添加的未归档模型。每个模型默认不允许加入套餐。平台管理员和运营人员可配置「允许加入套餐」、全平台共用的抵扣规则和修改说明。添加及编辑只保存草稿，发布后切换生效版本，待发布期间继续使用当前生效规则。修改历史记录发布版本、时间、操作人、变更前后规则和修改说明。
- 先选择模型，再按该模型当前生效售价中的计费项分别配置抵扣规则。没有生效计费项时提示先配置并发布模型售价。留空的计费项不生成规则，新增模型至少配置一条。切换模型时保护未保存输入。保存和发布均校验计费项归属，已有生效规则保留至新版本发布。规则使用模型主档 ID。同一计费项可不分档，或配置互不重叠的输入 Token 档位。下限不含、上限含，允许留空一端。下限留空从 0 开始，上限留空代表无上限。按单次请求的输入 Token 数判档，整笔使用命中系数。各计费项的实际用量乘以对应系数，再相加得到套餐扣减额度。系数须大于 0、最多两位小数。
- 套餐制作的「支持模型」支持搜索和多选已发布、允许加入套餐且有生效规则的模型。选中后展示当前计费项、档位和系数，套餐只保存模型关联。暂无可选模型时提供模型抵扣系数页签入口。发布和上架至少选一个符合条件的模型。模型仍被套餐引用时，发布规则须保留允许状态和至少一条规则，服务不可归档。被草稿或生效规则引用的计费项不可删除。原模型级系数作为历史值保留。
- 使用说明和使用范围是独立的可选文本，各最多 500 字符。套餐配置、共享类型、操作回执及审计通过 5.12.0 的 D1 接口保存。原浏览器套餐记录保留在原存档。

## 套餐数据

- 运营区「套餐运营」下的「套餐数据」提供一张套餐汇总表。默认全部套餐，支持筛选订阅套餐或资源包。每款套餐一行，依次展示套餐名称、资费ID、新增销售数、累计到期数、额度消耗率（平均值）。资费ID使用现有套餐编号。新增销售数统计所选期间售出的份数，累计到期数统计截至结束日已到期的份数。额度消耗率对当前范围内明细所列且截至结束日已生效的权益，逐份计算累计消耗量除以套餐额度，再取算术平均。无可计算权益显示「—」。已下架套餐仍可查看。筛选沿用[运营时间与事实](#运营时间与事实)的北京时间口径。
- 点击套餐名称进入单款套餐详情，沿用概览时间范围。权益表每份已购权益一行，展示订购时间、套餐 ID、用户 ID、账号名、账号类型、套餐档位、套餐额度、有效期至、状态、已消耗 Tokens、剩余额度和累计成本。套餐 ID 下显示权益编号，同一订单购买多份时分别展示；账号类型支持筛选政企用户和个人用户。演示表纳入期内购买或期内有效的权益。额度以 Tokens 展示，已消耗为按系数扣减的额度；消耗、剩余、状态和累计成本均截至统计结束日，成本缺失显示「待核算」。返回概览保留筛选和列表位置。
- 套餐列表读取 D1，缺失的真实经营数据和权益明细显示「待接入」。独立演示视图按北京时间映射样例日期，超出覆盖范围显示「无演示数据」。演示统计与 D1 套餐及用户侧订购、扣减和权益分开。

## 模型身份与资料

- 术语由 [GLOSSARY](GLOSSARY.md)定义：模型资料、供应关系和销售服务各有职责，资料 ID/模型编码/上游模型标识/对外调用标识 不混用，模型作者不等于服务商；采购参考价、采购价和平台售价分开。完整 URL 称请求地址，Key 按当前绑定渠道表达。
- 模型资料库统一维护当前主档；按稳定 ID、显式关联或精确编码识别模型，不按名称近似合并版本。已有运营资料是主档，旧模板不能成为第二个可编辑来源；服务和供应页面读取同一主档。
- 六类主要用途为语言模型、视觉理解、视觉生成、语音模型、向量模型、重排模型；语言模型可支持图像/视频输入，不能仅因名称含 VL 或具备图像能力改类。既有类型代码、图像/视频任务及计量单位保留。输入/输出模态与向量/相关性等结果类型区分，未知能力/规格保持未填写。
- 资料库保留表格、查看、编辑及删除入口；长内容提供完整值的可访问查看方式，宽度不足时在表格区域滚动。资料列表名称/编码、作者、正式发布日期、类型、适用场景、模态及上下文各有语义；日期来自可核对官方首次发布记录，场景不替换为支持任务。维护分页 20/50/100、默认 20，选择流程保留自己的容量；切换容量只提交一次容量和第一页。
- 基础资料库的共享主档编辑按用途分区：模型卡片维护名称、Logo、类型、输入/输出模态、结果类型、上下文与简短介绍；模型详情维护作者、适用场景、支持语言、任务、资料链接、详细介绍及按类型展示的能力规格；模型编码、系列、版本与发布日期在“其他信息”，技术与接口属性独立展开。共用字段仅维护一次，不新增第二套卡片/详情可编辑主档。售价在独立模型售价维护；模式、关联和对外调用标识 在路由及映射维护；现有模型级客户范围在服务概览维护。
- 前台卡片和详情读取同一份已生效资料：Logo 缺失或存储内容不合法时使用默认图标，图片加载失败时名称仍可读；详情复用卡片公共信息，并显示已填写的长介绍、模型编码、版本/发布日期、能力规格、技术接口属性及资料链接。未知属性不补零或“支持”，正式发布日期与卡片的资料更新时间分开；不把采购价、供应密钥、内部请求地址和资料核对记录投影给客户。点击卡片进入独立详情页，按面包屑、模型介绍与三项参数、服务商报价、API 调用、详细资料组织；返回广场保留当前筛选并恢复原卡片焦点。URL 保留稳定模型与服务 ID，支持刷新和浏览器前进/后退；失效或无权访问时显示不可用，不自动替换为其他服务。
- 渠道直选模式详情每条已上架且对客户可见的渠道服务一行，显示服务商和来源名称。展开可查看已发布计费项、独立对外调用标识，按所选渠道订购或在线调用。统一模型服务模式只有一个平台服务入口。登录、订购状态和调用由 D1 校验；调用区按所选服务同步对外调用标识。
- 前台模型广场按稳定模型 ID 聚合 D1 的有效上架服务，一款模型一张卡片。按发布日期排序，不把渠道直选模式服务计为多个模型；服务商筛选匹配卡片内各服务。渠道直选模式详情可选择渠道服务，售价、调用 ID、订单和在线调用使用同一服务身份；统一模型服务模式使用平台统一售价和调用 ID。售价仅取平台已发布销售快照，明确币种/计量单位，未提交输入、采购价和内部渠道不对客展示。每条调用记录保留当时的渠道、路由和售价引用。
- 主档名称、介绍、图标等在当前表单编辑，预览受影响服务并明确提交后同步引用展示；不因展示文字修改重测连接。类型、能力、模态、任务、版本及深度思考/结构化能力变更走专门影响检查，重验受影响范围；不兼容依赖先修复或明确下架，合格后发布，不直接覆盖在线配置。仅属性顺序变化不误判，稳定身份、权限、修订、存储和焦点保护保留。
- 模型运营初始数据集中于 [Mock 配置](MODEL_OPERATIONS_MOCK_DATA.md)，基础资料、供应管理、模型服务共用稳定引用与目录范围，前台读取后台生效服务。只在没有存档时初始化；已有用户配置、删除记录、凭证、草稿与历史不因刷新或配置更新被补回或覆盖。
- 删除主档须没有供应、服务或活动配置引用，界面禁用与事务校验一致。添加供应模型从主档选择，可原地新增主档并返回选中，不自动登记供应关系或渠道。批量只接受匹配主档的模型，不接受任意未匹配上游 ID，不生成空渠道。
- 对外服务正式资料沿用其现有完整校验；技术接入可以先保存最低身份资料，任务/能力缺失保持待完善，不能据此启用技术服务或上架。资料与服务编码规则的已知差异见 [MODEL_OPERATIONS_TERMS_REVIEW](MODEL_OPERATIONS_TERMS_REVIEW.md)，不靠改名宣称差异已修复。CSV 前两列统一模型编码/模型展示名，不增加旧表头别名。

## 渠道接入

渠道接入页（服务商/模型双视图）、模型渠道表、API 密钥池、接入新模型/新渠道表单、渠道编辑抽屉、密钥池与凭证候选编辑及接入记录续配使用 Semi Design 原生组件和默认样式。保留默认配色、字体、字号、圆角、表单和表格密度，仅设置布局、间距和响应式规则；旧后台样式不覆盖该区域及其弹层。表格合并单元格、脱敏、候选测试与应用等行为按本章既有条款保持。

API 密钥池列表按密钥组展示优先级、密钥名称 / ID、脱敏密钥、当前绑定渠道、状态与操作。名称在前，稳定短编码在后，底层 ID 与引用不改写。上移／下移只交换相邻条目，边界禁用；顺序和版本持久化。备用顺序不改变当前生效密钥；切换有渠道引用的首位密钥先保存候选、展示影响、检测全部引用，明确应用后原子生效。失败保留当前顺序，刷新可继续候选；并发、角色及写失败保护保留。

两条旧演示渠道 supplier-review-CH-001 / supplier-review-CH-002 及其四条初始样例映射不再作为默认数据安装；已有线上记录须核对无供应、路由、模型关联及任务引用后，通过现有删除渠道事务归档。合法手工保存的未关联渠道继续保留，不因状态文案自动清理。


渠道接入页头仅保留添加服务商，移除“接入并上架模型”入口；模型、渠道继续通过服务商详情分别添加。指定的三条 D1 验收服务商及其已下架服务、独占渠道/映射和服务路由经管理员明确确认后逐条原子归档，不按名称前缀清理。保留主档、价格历史、调用与审计；存在非验收业务引用、运行中的服务、未完成任务或新增资源时拒绝归档。


- 渠道接入默认进入服务商视图，视角切换按服务商、模型排列；显式模型视图链接继续进入模型视图。模型工作区提供本模型的供应接入入口；同源查询和 provider/tab 上下文继续复用。资源视角切换与搜索在目录面板内，键盘焦点和空目录可操作，不复制业务记录。
- 服务商详情不展示“服务商更多操作”及其停用弹窗；通过「查看资料」进入模型资料的服务商详情，保留原服务商和页签的返回路径。模型渠道表中的模型展示名仅展示，不提供修改图标、改名弹窗或改名命令；已有服务商登记名称和配置不清空，统一模型资料仍在模型资料模块维护。渠道编辑、测试连接和删除等操作保留。
- 服务商视图仅保留模型渠道、API 密钥池两个页签；主体资料通过编辑入口维护，未知页签显示模型渠道。模型渠道表格依次为模型展示名、渠道、状态、上游模型标识、上游 API 地址、计费项、渠道采购价、计费单位、操作；模型视图复用同一表格，以服务商替换首列并合并同服务商单元格。同一模型跨其渠道和计费项合并模型展示名，同一渠道的状态、标识、地址及操作跨计费项合并；按模型分组分页。模型标识读取当前关联的上游请求标识，API 地址为实际模型调用地址；两列均提供可访问的复制入口，复制完整原值，缺失时显示横线且不提供复制。采购价读取当前采购配置的显式采购金额，或按原目录价及采购折扣计算，不使用渠道刊例价或客户售价；币种随金额显示，零与缺价区分。渠道采购价 tooltip 为“当前平台采购服务商的价格，用于成本及利润分析”。状态沿用真实配置及检测结果，冻结、停用、缺少模型或凭证不可标成可用。表格操作为渠道维度的编辑、测试连接、启用／停用供给、删除渠道；无渠道时渠道列显示“待添加渠道”，该模型行提供接入新渠道和删除模型。删除均先弹窗确认；只要当前服务商/渠道已被模型服务关联（包括仅关联服务商、未上架、下架、停服、停用供给），或仍被当前路由/草稿引用，就必须先解除关联，不能仅下架后直接删。未完成接入/检测任务也阻断删除。删除共享渠道时只移除当前模型关联；最后一个模型关联删除后，渠道资源一并归档，其他模型和历史记录保留。模型必须先删完全部渠道；模型删除只移除当前服务商登记，基础资料保留。后端重新校验所有者、角色及修订，失败不部分删除。编辑抽屉维护共享渠道名称、当前模型标识、API 地址及共享/独立密钥配置，以及当前模型的计费项、采购价、货币、单位和适用条件，一次原子保存；预设接口的完整任务地址须先明确确认识别出的服务根地址；地址或共享密钥组变更先保存待验证配置，再进入现有测试及应用流程，当前地址和密钥保持服务，不覆盖其他未完成候选；采购变更发布立即生效的新版本，保留旧价及其他模型配置，仅改名不产生采购版本；名称同步同渠道关联，标识不改其他模型或服务商，被服务或生效路由引用时阻断标识修改，修改后相关映射需复测和明确启用。测试连接打开当前模型供给的服务端检测任务，支持结果、检查详情、重试和原提交恢复；检测通过后单独启用供给。停用须确认影响，保留采购配置和历史；恢复不自动创建服务或上架。缺少明确接口类型的旧渠道先进入编辑，人工确认协议和地址，再验证应用，不静默改写既有连接。无渠道模型及缺报价仍展示；未关联模型的渠道不能直接发起模型调用测试。原主体资料、资源、采购/刊例价/售价版本、路由、审计与权限保护保留；跨服务商模型视图保留既有资源维护流程。模型展示名只读，统一主档在模型资料中维护。
- 模型资料的名称与编辑入口共用同一个详情抽屉，查看态默认显示模型资料，可切换「供应服务商」反查服务商及渠道数并登记供给，宽度最多 1200px，并适配窄屏。以入口中心位置判断方向：左半屏入口从右侧展开，右半屏入口从左侧展开；切换查看/编辑保留抽屉方向。两态的字段、分组、顺序及单元格位置一致，查看用文本，编辑用控件；视觉任务类型、资料来源两态均展示，规范模型标识保持只读，内部资料 ID 不占业务界面。查看态右上角为编辑，编辑态底部固定取消和保存；取消未保存修改需确认，保存沿用资料影响核对，成功后回到当前资料查看态。表格筛选及滚动保留，关闭后焦点回入口。
- 「模型资料 → 服务商」使用 Semi 原生筛选、列表和分页，列出名称、编码、Logo、供给类型、已登记模型数及操作。点击名称或模型数进入独立详情页，默认显示「供应模型」，第二个页签为「基础资料」。基础资料统一在模型资料新增和编辑，维护主体字段、Logo、简介、官网、文档链接、联系人、联系方式和备注；渠道接入的「添加服务商」前往同一新增表单，「查看资料」进入同一详情页并可返回原服务商及页签。

- 批量导入支持单独建模型或服务商主档、带入当前服务商批量导入并登记、用服务商编码和规范模型标识导入供给关系。逐行预览有效、已有、重复和问题记录，确认跳过问题后分批提交，结果支持下载问题行和单独重试提交失败的行。主档先保存，关系随后登记；关联失败保留主档。重试核对当前资料及关系，已有记录不覆盖。

- 批量导入模型资料只提供表格上传，支持 XLSX、UTF-8 CSV，单文件最多 10 MB、每批最多 500 条；不提供粘贴入口。下载模板为 XLSX，前三列必填项使用红色表头并注明“必填”，第四列视觉任务类型使用橙色表头并注明“视觉模型必填”，其余为选填；冻结首行和前三列，附“填写说明”工作表，表头文字标记可直接导入。模板与资料表单共用字段描述，覆盖基本信息、模态与任务、调用能力、支持参数、技术与来源及各类型专属规格。必填名称、规范模型标识、模型类型；视觉类型另填图像或视频，其他未知资料留空。可删去可选列或调整顺序，重复/未知表头拒绝；空行不改变原文件行号。填写提示常驻展开，使用清晰分行和 14px 正文。读取后进入校验预览，支持逐行查看全部已填字段、下载完整校验清单、筛选与明确跳过问题行、重新上传。校验与资料保存复用类型、日期、数值、默认参数依赖及重复身份规则；不适用字段拒绝而非丢弃。常规模型导入仅创建模型资料，不覆盖已有标识。服务商下钻页的「批量导入并登记」使用同一模板和当前服务商，按规范模型标识复用一致的主档，资料冲突标为待修正，分步保存主档和供给。

- 模型资料列表首列表头为“模型展示名”，按原名称搜索与打开详情；第六列为“模型展示 Logo”，读取同一主档的模型 Logo，以 28px 等比展示，不再展示资料状态。未填写或图片加载失败显示“—”，不补造图标；底层资料状态和其他资料保留。其余字段、排序、分页和编辑/删除保护保持。
- 模型资料维护模型和服务商的统一主档，导航与页面标题为“模型资料”；模型列表保留有效的 17 项主档及后续手工资料。渠道接入的模型视图只显示至少已有一家服务商登记的模型，按稳定主档 ID 聚合去重；没有供应登记的资料不显示，尚无渠道的已登记模型仍显示服务商及待配置状态。点击模型后展示其服务商/渠道、地址、上游标识、状态及采购信息。服务商已有真实渠道时，不再混入同一主档的旧别名空行；真实映射独立保留。模型视图不展示截图中的接入并上架模型、添加服务商、关联服务商、添加渠道四个页头按钮。资料归档和已有配置、价格及历史保留规则不变。服务商视图、模型视图和侧栏数量使用同一有效供应模型集合，均按主档 ID 合并别名；每条渠道保留原模型编码、映射 ID、标识和采购配置，编辑/删除仍定位原映射。同一主档的旧空行不重复计数。归档资料的历史供应登记及其渠道不混入当前列表，不误标为未关联渠道，原记录保留；真正未关联模型的渠道仍展示。删除模型登记须检查该主档在当前服务商下全部别名的渠道、服务及任务引用，全部渠道删除后一次移除所有别名的有效登记，保留主档、历史和其他服务商。
- 服务商详情提供“接入新模型”“接入新渠道”，对应弹窗同名。接入新模型使用可搜索多选下拉，来源为“模型资料 → 模型”，显示类型、发布日期和已添加状态；每次最多 5 个，已登记项不可重复选择。只提交主档稳定 ID，服务端重新校验存在性、重复、所有者、权限与修订，原子登记关系，不新建主档、渠道、服务或售价。缺少模型时跳转“维护模型资料”，保留未保存保护。服务商详情固定当前服务商；模型视图只作已有供应关系的聚合展示。
- 内置目录由 src/data/builtin-model-catalogue.json 定义本次指定的 17 个国产模型。新工作区初始化；已有 D1 通过明确的管理员命令增量安装，每批最多 5 个。仅新增缺失主档，或更新与旧初始配置业务字段完全一致的默认名称、类型和日期；忽略初始化时间差异，任何其他修改和草稿均保留。明确 existingId 或唯一完整编码匹配，不按相似名称合并。安装记录与用户修改分开，重复安装不恢复已删除记录；已有库通过管理员显式清理命令原子保存目录归档 ID，不替换模型、服务商、渠道、密钥或价格集合；不补造能力、采购价、凭证或上游标识。
- 添加服务商只登记主体，不强制创建连接或密钥。从模型资料新增服务商时录入唯一编码，创建后只读，已有编码不重写；主体名称、供给类型、联系人等沿用当前校验。备注可简短、最多 2000 字，不恢复至少 140 字的旧限制。
- 添加供应模型仅登记服务商与主档的关系，不代表可调用。无渠道可移除当前关系，保留主档及其他服务商；重新登记不恢复旧渠道。两视图资源、价格和操作同源。
- 供应模型详情维护服务商声明的参数、默认值、范围、必填及组合限制，能力明确支持、不支持或未确认；声明不替代统一主档或渠道验证。复制创建须选择目标服务商与主档，只复制声明，不复制渠道、密钥、测试、服务或路由；不能覆盖已有供应关系，重新登记保留该关系原有历史。
- 刊例价独立属于服务商×模型×渠道，维护计费项、适用条件、单位、币种、生效/到期时间及不可变发布版本。零价与缺价分开，已发布版本保留；新版本到期不恢复被替代旧价。刊例价发布不修改渠道采购价、客户售价和历史成本，也不修改其他渠道刊例价。旧模型级刊例价历史保留查阅，不自动复制到渠道。
- 添加与编辑渠道共用接入字段、共享／独立密钥控件。渠道维护模型、名称、上游标识、协议、地址与凭证，不编辑采购成本；成本摘要打开模型成本列表并定位同一供给来源。新增可无成本，不生成零价；旧成本与历史原样保留。共享密钥新增、独立密钥留空保留、取消及失败输入保护继续有效；地址／凭证变化原子保存候选，测试后明确应用，不覆盖有效连接或已有候选。明文不进入存档、审计或产物。
- 添加渠道只选择当前服务商已有模型，必填名称、上游标识、支持的协议、完整 API 地址和有效密钥。共享密钥默认使用当前首组，可明确选择独立密钥；提交只含掩码和指纹。渠道和关联一次原子保存，不自动测试、启用供给、创建服务或上架；成本独立配置，缺失不等于零。
- 渠道保存不自动测试；明确测试后按有效证据和固定影响范围启用技术供给。技术资格与客户可用分别判断；首次任务最终提交、备用准备及日常应用遵守各自目标，不因“下一步”隐式变更共享资源。已知接口不兼容阻断，未知路径不误判，未保存配置不复用旧证据。
- 首次上架向导继续使用其接入表单和原子保存；服务商详情的模型登记与渠道添加按上述两个入口处理，不恢复已移除的合并创建按钮。可用性及最近测试来自现有渠道证据，不新增持续探测或实时遥测。
- 请求地址使用完整 HTTP/HTTPS URL，保留当前第三方 HTTPS/自有 HTTP(S)、禁止嵌入凭证及不允许的查询/片段校验；不将裸域名或基础 `/v1` 冒充模型接口，不重复拼接路径。已配置的多协议地址保持独立测试结果，次协议通过不能替代主地址健康。
- 相同接口、凭证与上游 ID 不能靠不同名称/来源标签重复创建。旧无 ID 关联稳定读取，不回填/丢弃记录；编辑某渠道不能误删其他渠道。调用配置变化使相关验证失效，单纯名称/成本变更不误清验证；共享影响须确认。
- 模型视图及渠道模型明细按真实映射展示计费项；服务商模型及渠道表展示各模型渠道的当前有效刊例价；能力声明通过“配置”中的当前模型配置维护。金额保留零值、缺失、单位、币种和条件；地址可查看完整值。行操作与对应对象明确关联，关联状态来自精确供应映射，不把健康状态当关联。
- 停用、删除或解除先检查服务及已发布路由引用，提示真实影响；全局停用与当前路由摘除分开。保存渠道不自动改服务映射、售价、路由或上架。旧报价、密钥、价格历史和审计保留。
- 默认样例与官方参考资料不证明真实供应关系、可用性或价格。已有记录不为凑数量重置；显式加载参考目录只补缺失记录，保留自定义资料与已关联模型。一次性案例删除/修改后不自动复活，历史本地授权不能再次用于改写用户浏览器。

## 密钥与维护

- 密钥库与租户 API Key 独立。只保存掩码、SHA-256 去重指纹及引用元数据，明文不进入草稿、存储、审计、日志或产物；不宣称已接服务端凭证库。
- 产品继续使用 API 密钥，不改名 API 凭证。服务商密钥页维护密钥资产和分组；渠道的密钥池维护多条绑定、启用状态和 1–100 优先级，数值小者优先，同级按列表顺序。旧专属、默认及共享组引用不自动转换；移除“设为主要”入口，已有组顺序保留。
- 渠道列表和渠道模型展示健康状态；健康与启用分开。逐渠道模型、逐密钥检测，结果展示时间、HTTP 状态、耗时和失败原因，支持确认、取消和重试。结果有效期为 24 小时；地址、模型映射、密钥版本变化要求复测；单 Key 通过不代表整个密钥池正常。检测只写诊断历史，不修改启用、映射、路由或价格；本地结果标识“模拟检测”。
- 密钥池变更走候选配置→逐条测试全部启用密钥→明确应用，校验全部必要模型及服务影响；单 Key 通过不能替代其他 Key，失败、过期、待完成及不匹配回执均不放行。未关联模型须先接入模型再验证。本批不新增自动轮询、额度调度或熔断冷却。
- 密钥按实际渠道引用聚合，长 ID 可换行；没有密钥不伪造占位记录，不把未关联旧渠道作为整个模型目录的错误。添加/替换不回显原文，沿用可见 ASCII、长度、重复和数量校验，保存只提交脱敏信息。
- 正常轮换与撤销分开：正常轮换不自动撤销旧 Key；专属渠道和共享组按实际引用范围处理，不能误改其他渠道。替换/删除等影响动作保留确认、稳定身份/关联规则及验证失效处理，相关细节见[接入规格第 23 节](MODEL_ONBOARDING_SPEC.md#23-目录外接入与日常维护简化2026-10-31)。
- 渠道配置和测试可打开已有添加密钥弹窗，父表单当前输入保留。测试切换密钥组仅作用本次检查，明确修改渠道配置才持久化；测试结果单一呈现，接口不匹配优先于旧通过记录。测试/调用明确提示用量确认，保留取消、重试和失败恢复。
- 地址和 Key 维护先保存候选并测试，通过后仍需明确应用；失败保留当前配置。历史恢复入口共用固定范围和有效性校验，不保留绕过检查的旧结果直达路径；不因测试成功自动启用、改路由或上架。
- 成功、超时等模拟场景选择只在地址参数 `devtools=1` 的研发视图显示，普通业务页面隐藏；测试结果保留实际来源，不将本地 Mock 记为真实上游证据。

## 模型服务与调用路由

- 模型服务演示包提供 GLM-5.3（渠道直选模式）和 DeepSeek-V4-Flash-0731（统一模型服务模式）。导入后从模型服务目录查看案例，历史工作区继续读取已有案例及用户新增资源。检测和平台试调用结果显示实际证据来源，模拟结果标明「模拟检测」或「模拟试调用」。
- 模型服务采用对象清单与内联工作区，包含接入中、未上架、已上架及已下架模型；稳定关联避免任务和服务重复显示为两款模型。保留名称/ID、类型/模式/状态筛选与批量能力；不存在或被过滤对象显示原因和返回入口。
- 后台模型广场按模型展示及维护广场展示许可。统一模式按模型上架或下架，渠道直选模式勾选渠道服务，也可勾选一家服务商的全部渠道。 列表支持按模型展示名或编码搜索，并组合筛选模型类型、上架状态与广场展示设置。查询和筛选保存在 URL，修改条件后回到第一页。 列表和卡片共用查询、分页及操作。供给信息按服务商分组，默认显示服务商和渠道数量，列表可展开渠道明细。卡片统一标题、简介、参数与供给摘要区高度，默认展示最多三家服务商，居中弹窗查看全部服务商及渠道。卡片展示模型标识、简介、输入和输出类型、上下文、作者及售价。统一服务模式展示明确的生效平台售价，按条件计价时标明按计费项定价；渠道直选模式标明按渠道服务定价。渠道直选仅展示已关联服务商，暂无渠道时标记待关联；模型广场默认使用卡片视图，切换到列表时在 URL 保存视图。 列表和卡片默认按全局序号排列。卡片通过右上角把手拖动到当前页的其他卡片位置，支持键盘拖动。列表可拖动当前页的序号，也可点击序号直接输入目标位置。筛选不改变序号。顺序保存到工作区，由模型运营权限与修订校验控制。前台广场和详情读取 D1 中已发布、已启用且对当前客户可见的服务；灰度服务只对获准客户返回。
- 服务工作区依次为服务概览、路由及映射、故障转移、调用指南、操作记录。页头保留模型身份，在模型名下用 Semi 状态标签展示服务状态和可见性；服务状态为正式上架、已下架或灰度上架，可见性为用户不可见、用户可见或灰度用户可见。可见性独立读取展示开关与灰度阶段，沿用未配置展示开关时用户可见的语义；下架不清除灰度配置。售价／销售入口带稳定服务 ID 跳入模型售价；原价格编辑删除。跨页保留来源对象、页签与筛选；任务入口定位现有资源，缺失对象明确报错，未保存输入有离开保护。
- 服务概览为默认页签，展示唯一资料引用，以及服务提供方、对外调用标识、成本和售价摘要与定向跳转；移除用途、操作两列及修改用途弹窗，不展示技术启停或归档按钮，不重复列出技术／销售状态。模型资料只能从资料模块维护；调用标识仍在服务上下文维护。统一模型服务模式用途为模型级，渠道直选模式用途绑定具体服务；服务调用校验客户状态、既有授权和密钥权限。
- 每个模型只有一种服务模式：`standard` 为统一模型服务模式，模型级统一售价；`provider` 为渠道直选模式，每个渠道服务独立维护对外调用标识、售价、路由和上架阶段，可与同服务商的其他来源复用连接。采购价在模型成本维护，平台售价在模型售价维护。
- 选择及切换服务模式的弹窗用两段短说明，从用户选择、调用 ID/价格和平台调度范围解释两种模式，不使用大对照表；未选择也能阅读，且与模式提示共用文案。选择与切换仍保留既有下架、重配、未保存和权限保护。
- 未上架模型可未选模式；关联渠道及上架前必须选择，未选时显示配置空态，不展示旧渠道或推断默认。已选模式只读，独立入口显式确认切换；确认切换以一次事务完成下架、服务关联重置、路由/草稿失效和价格代际递增，资源及历史保留，取消不写。切回旧模式不能使旧价格复活。
- 路由及映射选择已检测并启用的同款模型供给并维护调用 ID；模型售价独立编辑价格及销售设置。任务间不得夹带未提交输入，不创建虚假资源、不自动参加调度；采购变更不改变已发布售价。
- 「路由及映射」在路由表下方展示模型映射列表。路由行的「模型映射」定位到对应服务，渠道直选可在页内切换渠道服务。新增、编辑和预览在同一层抽屉完成。无可选供给时在列表旁区分可用供给均已关联和缺少已验证并启用的供给，后一种情况提供渠道接入入口。备用映射及候选变更在列表预览、验证、应用、停用或解除，保留引用、主档、服务商和协议校验。
- “新增映射”以 Semi 原生组件展示模型服务、服务模式和对外调用标识。统一模型服务模式可选择服务商，渠道直选模式只读显示当前服务商。按服务商筛选同一主档下已验证并启用、且没有现有或待应用映射引用的渠道模型供给。切换服务商清空已选供给及上游模型标识。上游模型标识由所选供给带出，单一适用平台接口直接显示，映射名称选填并默认使用渠道名称。
- 映射预览只展示两侧请求；服务端验证复用当前供给检测证据并核验标识、路径和协议，不发起新用量，不替代平台试调用。新增映射待验证且未启用；在用映射只改名；未引用映射的供给变更保存为候选，原有效配置持续保留，验证后明确应用或放弃。生效与草稿路由全部条目、未完成任务阻断停用／解除及目标切换；供应侧删除检查候选引用。保留旧有效关系、价格、凭证元数据和历史；不重放初始数据或无提示改写已有关系。
- 新服务商可从“关联服务商及渠道”创建并返回选择。先确认关联，再保存调用标识并选择主渠道。路由编辑只选择当前模型下已有且检测启用的渠道，不提供“接入新渠道”或内联登记流程。供应模型登记、渠道地址、协议、上游标识与密钥统一在渠道接入模块维护；完成检测并明确启用后，回到服务路由编辑选择目标，经预览原子建立映射并生效。保存渠道不自动加入路由或上架。
- 灰度上架须在有效销售对象中指定客户；正式上架解除灰度限制。渠道直选模式按所选渠道检查当前采购价、售价、技术启用和验证结果。下架目标渠道立即拒绝新订单和新调用，保留其历史及技术配置。仍有已上架渠道时保留模型卡片。可见性只控制广场展示，不授予调用权限。
- 模型成本、模型售价的列表、详情或抽屉使用 Semi Design 原生样式，表单与弹层保留权限、修订冲突和未保存保护。列表按模型展示名、服务商和成本/销售状态组合筛选，保留搜索、重置和来源返回路径；按模型主档稳定引用合并模型展示名单元格，同名不同模型不得合并。列表不分页，固定表头、局部横向和纵向滚动；成本和售价均按每条计费项展示价格、计费单位和货币，按渠道模型关联或服务合并相应单元格，缺价不显示零。
- 切换服务模式使用三个连续步骤：确认下架该模型、确认清除模型映射及路由、重新设置服务模式。前两步分别显式勾选确认，最后调用既有原子重置/下架事务；此前当前配置保持生效，中途取消保留配置，提交失败保留草稿。保留原模式价格历史、资料及接入资源，不将旧售价自动复制到新模式。
- 模型运营字段按[字段命名与归属](MODEL_OPERATIONS_FIELD_DICTIONARY.md)统一，供应商/服务提供方的界面称谓统一为服务商；规范模型标识、对外调用标识、上游模型标识分别对应主档、客户请求、上游请求，不更改协议键和用户历史记录。
- 模型服务目录、服务概览、路由及映射、故障转移、调用指南、操作记录，以及新建服务、路由/映射编辑与上架配置，使用 Semi Design 原生组件和默认样式。保留默认配色、字体、字号、圆角、表单和表格密度，仅设置布局、间距和响应式规则；旧后台样式不覆盖该区域及其弹层。服务目录展示名称、状态、模式、配置状态与调用标识；各页签保留 URL 状态，页签栏使用换行布局。工作区宽屏左右分栏，窄屏上下排列。路由表按服务合并提供方、调用标识与策略，操作列固定在右侧，按钮单列纵排，表格局部横向滚动；点击策略或渠道操作打开当前服务的 Semi 抽屉，保留选中渠道提示、未保存守卫、版本冲突和核对后生效流程。服务操作提供技术启用或停用及归档。归档确认列出未满足的条件，成功后定位已归档服务，可从服务操作恢复；服务概览不提供技术启停和归档按钮；启用及上架检查可打开验证弹窗，展示模拟请求和试算结果。成本、售价与接入资源仍通过原有稳定引用跳转，不在服务页面复制主档。
- 路由及映射的路由表呈现：服务提供方、对外调用标识、路由策略、上游渠道、上游模型标识、操作。同一服务的提供方、调用标识和策略跨渠道合并单元格；统一模型服务模式显示当前平台内置服务商，渠道直选模式按各服务商服务分组，展示主渠道，省略路由策略列。上游渠道按行展示，权重靠右，ID 左侧提供复制图标。操作列直接提供编辑路由、编辑调用标识、模型映射、停用或恢复路由，以及渠道直选模式下的服务商停服/恢复、符合条件时解绑；按服务合并操作单元格，编辑路由打开宽抽屉，入口位于屏幕右侧时从左侧打开，反之从右侧打开。对外调用标识 tooltip：“用户调用左侧的模型。平台将请求转发给右侧的上游模型。”
- 编辑路由及映射时，直接选择同一模型资料对应、已检测并启用的供应渠道，自动读取上游标识和支持的平台接口，不重复填写地址、密钥或采购价。统一模型服务模式可跨服务商，新增的渠道直选服务只使用当前绑定的渠道。新目标的映射建立、检查、启用与路由发布在单个事务内提交；预览只读，复用供给检测证据，不发送请求，不隐式改变销售、停服或上架状态。保存失败、取消、权限变化或修订冲突保留草稿及原有效配置。现有映射 ID、未应用变更、未选中的备用映射、历史运行参数和路由历史保留；已有复杂映射维护从主表操作列的“模型映射”进入。
- 统一模型服务模式只提供五种路由策略：加权随机路由（simple-shuffle，默认）、最少并发路由（least-busy）、最低 TPM 路由（usage-based-routing-v2）、最低延迟路由（latency-based-routing）、最低成本路由（cost-based-routing）。不支持固定渠道，单渠道使用 100% 权重。新建的渠道直选服务绑定已选择的主渠道，界面不提供路由策略设置。原内部策略键保留稳定引用，配置标识通过同一策略字典展示和发布；已有不再适用的统一模式策略只读保留历史，重新保存须明确改选，不静默转换用户配置。
- 路由抽屉只维护策略、所选渠道、权重及策略必要参数；新路由不预选目标，权重合计须为 100%。故障转移在独立页签保存。统一模型服务模式在参与路由的渠道中转移。新建的渠道直选服务不向其他可单独订购的渠道故障转移。保存生成新配置版本，保留主渠道和策略，并要求重新验证。预览展示差异和调用关系，确认后原子生效。停用/恢复路由从主表直接进入确认，不再嵌套于抽屉：停用前须停服，隐藏不能代替停服；清空草稿，保留映射和历史。恢复校验最后发布配置，有草稿时先明确编辑发布，不自动恢复服务或上架。调用标识、模型映射和服务商停服/解绑同样从主表进入，权限、依赖、影响确认和未保存保护保持。
- RPM / TPM 限额未配置时不推断为零；已配置限额必须有实际分钟用量，达到限额的渠道不参与分配。最低成本只比较相同计费项、条件、单位和货币，保留输入/输出/合计比较口径。
- 缺乏所选策略所需真实延迟、并发、分钟 Token 用量或可比成本时不能发布；协议转换仅支持已实现映射，不增加任意 URL 转换。回滚重新验证并生成新版本，历史保留；渠道加入服务不自动加入活动策略。
- 缺项在相关区域展示并提供直接修复入口；最终验证汇总当前资料、模式、采购/售价、范围、路由与发布证据。服务生命周期、任务进度、未发布修改和供应健康分开，列表只呈现必要状态，不以页码或勾选冒充完成。
- 模型服务负责技术验证、启用、停用与归档。技术启用检查资料、模式、调用标识、连接、映射、路由及当前平台验证证据，无需成本和售价。模型售价负责发布售价、设置销售对象，渠道直选服务可单独调整当前渠道服务的展示。模型广场负责统一服务或各渠道服务的灰度上架、正式上架和下架，以及模型整体展示许可。下架保留技术启用状态，停用保留销售配置。

## 保存、发布与恢复

- 后台不提供草稿保存、恢复或丢弃入口。编辑输入仅在当前页面保留；测试验证连接配置，不自动启用或上架。预览展示本任务差异、范围和阻塞项；明确发布或应用后才切换对应有效版本。
- 售价发布成功后立即作用于后续新请求，含已有订购客户；已开始请求及历史保留原价格快照，内部重试不换新售价。客户展示、后台及客户调用使用同一有效版本，不提供预约调价和专属协议价。
- 地址、密钥、路由、资料、售价和客户范围按相关任务独立提交；任何发布不得顺带应用其他任务输入。保存或发布失败保留当前输入和旧有效配置。
- 离开未提交页面只提供放弃本次修改／继续编辑；刷新不恢复未提交输入。历史未发布记录原样保留，不自动应用或作为新编辑的起点；报价历史可沿用后明确提交新版本。
- 超时或结果未知先核对同一操作结果再重试；冲突显示差异并保留输入，不自动覆盖。刷新恢复已保存安全内容并重查依赖，不承诺恢复未保存输入或明文 Key。
- 操作成功后持续显示真实对象、版本和生效时间，不只使用短暂通知。不可执行时说明具体缺项或权限原因，原型不伪造成功。

## 运营时间与事实

- 运营概览、用量和用户数据统一提供今日、昨日、近 7 天、近 30 天和自定义。昨日默认/重置，近 7/30 天截至昨日；自定义可选至今日、最多 365 天，禁止未来日期。北京时间今日及包含今日的范围只统计截至当前时刻的已发生事实，不补未来时段或外推全天；环比按上一等长期间的相同进度计算，用户页今日注明对比昨日同时段。图表、明细、客户下钻和导出使用同一范围；客户下钻页顶部提供同样的快捷时间、自定义范围及重置，默认继承来源日期，切换同步更新指标、模型用量和最近调用；范围写入 URL 并保留客户身份，刷新及浏览器前进后退保持一致，返回用户数据时按 URL 还原范围；保存视图恢复时重算快捷日期，自定义保留具体日期并限制至今日。月活来自明确成功登录身份事件，用户去重不能从 tenant/Key 推断；注册/构成/详情同源。租户和运维日期规则独立。
- 请求先按 requestId 取最终修订再筛选；模型/服务商/渠道来自真实关联，用户来自显式 userId、客户来自 tenantId，不能互相替代。已删除端点仍以稳定 ID 列入未归属，缺计量为待确认/断点，零值保留，非 Token 单位不相加。
- 派生 usage-demo 在读取时按北京时间自然日/小时重建，工作日、昼夜、客户和模型分布有差异，完成时段刷新/跨日稳定。调用、Token、占比、分层必须对账，关联 ID 有效；不持久化或重置用户业务记录，非派生请求和异常计量保留。

- 两张趋势均提供合计/按模型类型/服务商/模型/客户展示菜单；Token 总/输入/输出在筛选行。多选不自动切换展示维度，正常/放大/保存恢复共用真实 trends 状态，不再强制 Token 合计；复制筛选保留目标展示方式。
- 同维度并集、跨维度交集；选择服务商保存 provider ID 并包含以后渠道，选择部分渠道保存 endpoint 集合，不自动升级为整家。曲线默认周期前五，显隐不改变范围合计；缺计量断点，不补未来零值，坐标/提示统一万/亿及图例顺序、小时区间。
- 模型浮层提供搜索、类型和全选，类型只过滤候选，跨搜索/类型选择保留；确认提交，取消/Escape 放弃本次选择。服务商/用户提供搜索与全选；服务商原地展开渠道，箭头和复选分开，搜索命中组自动展开，父选中表示全部渠道，半选清晰，页脚说明整家和单渠道数量。
- 浮层只滚动内容，页脚可达；同名对象附 code/ID，可访问名称一致。用户筛选保留仅看已选/清空。曲线设置保留搜索/全选/重置/说明、选择数量、叠加合计和同步；长列表滚动时操作保持可达。
- 次数占比按最终请求数、调用量占比按所选 Token 口径；分组可切模型类型/服务商/模型/客户。类型全部展示，高基数前五＋其他＋未归属，完整清单可查看；分组总量与当前卡片分母一致，空结果不画虚假 0% 圆环。
- 客户分层按每客户周期调用次数统计客户数；Token 分段按每次完整计量请求输入＋输出统计调用数，真实零与待确认分开，未知客户单列，非 Token 不进分段。明细只按客户/模型，不恢复按供给；导出/搜索/排序基于本表筛选，数值原始精度保留。
- 保存视图沿用 `admin-usage-analysis-composition`，含六区域条件及趋势/占比设置；旧 scope 原记录保留，不自动迁移或执行旧隐藏筛选。URL model/user 下钻明确带入，tenant 不转为 user。旧已删卡片不从存储布局恢复。
- 用量数据六区使用 Semi 卡片、筛选、表格和弹窗，图表使用 ECharts。图例仅显示当前曲线，完整候选留在设置中。保留图表导航、布局保存和明细导出，宽表在表内滚动。

## 概览、用户与调用数据

- 概览六卡为注册用户、月活、请求次数、Token 总量、日均 Token、最大小时峰值消耗；保留环比信息，按可用宽度组织展示，窄屏可读可操作。小时峰值来自所选期间同源自然小时的最大值，多日仍取单小时，未结束小时不外推。移除分钟均值/分钟峰值与成功率卡，不新增月累计指标。
- 客户/模型 Token 排行与两张调用次数排行集中概览，基于完整集合和相同时间范围排序；次数排行分母为平台总调用数。客户 Top 10 与查看全部均为排名、客户、Token 用量、占比，不恢复周期变化列；详情下钻保留。构成图和趋势不显示附表入口，其他页面图表默认行为不变。
- 用户数据继续沿用[身份事件与客户明细契约](../../docs/PAGE-SPEC.md#后台导航与运营分析)，概览和用户页的注册/月活口径一致。
- 运维默认进入「运行分析 → 调用数据」。「网关管理」下的调用日志和服务监控各自有独立入口和地址。告警管理、事件处理、服务质量报告由服务监控的「更多」进入，仍按原权限访问。
- 三页共用「服务商 / 渠道」二级级联多选。可在不同服务商间混选整家与具体渠道。选中整家时包含该服务商的全部渠道及渠道未采集的记录，选中具体渠道时按服务商和渠道 ID 的组合匹配。调用数据和客户请求日志使用最终归属，服务监控和上游尝试日志使用每次尝试的实际归属。下钻在当前组合内缩小范围，分组和明细仍可分别使用服务商与渠道。
- 调用数据按唯一客户 Request ID 统计，默认今日。提供近 1 小时、近 24 小时、近 7 天、近 30 天、自定义范围及适用的分钟、小时、天、周粒度。短窗口按实际请求时间分桶，近 7 天和近 30 天沿用之前的完整自然日范围。筛选包括租户、模型类型、对外调用标识和服务商 / 渠道，保存视图保留完整组合。
- 概览展示请求数、最终失败率及失败数、P95 总耗时、输入/输出/总 Token，有有效样本时展示 P95 首 Token 时延。失败率以已判定成功或失败的请求为分母，已取消、进行中和未采集单列。优先使用已记录的最终状态，缺失时使用可判定的 HTTP 状态，保留无 HTTP 响应和未采集的区别。Token 不叠加缓存等子项，首包与首 Token 各用自身采集值。
- 调用数据图表为请求量趋势堆叠柱、耗时趋势折线、输入/输出 Token 堆叠柱、失败状态码横向条形及输入长度分段柱。请求趋势、时延趋势、Token 趋势、失败状态码及分组表支持按实际时间、分组或状态下钻到客户请求日志。展开图表数据可用键盘执行相同下钻。
- 调用日志默认客户请求视图，每行一个 Request ID。筛选含时间、请求 ID、模型、对外调用标识、用户、租户、请求来源、API 密钥名称、服务商 / 渠道、最终结果和状态码。
- 客户请求列表、详情主要字段与 CSV 按排障顺序排列。请求与结果依次为请求 ID、开始时间、模型标识、请求状态、状态码、总耗时（ms）、首包延迟（ms）。路由归属依次为供应商名称、渠道名称、供应商 ID、渠道 ID。用量依次为总 Token、输入 Token、输出 Token。调用方依次为请求来源、用户名称、用户 ID、API 密钥名称、API 密钥 ID、API 密钥（脱敏）。模型标识优先读取请求记录的对外调用标识，缺失时显示登记的模型标识。API 密钥 ID 使用已有密钥标识，密钥值仅使用脱敏结果。请求 ID 列固定在左侧，点击查看详情并可复制。详情另展示已记录的错误及链路。
- 上游尝试视图按逐次派发记录筛选和分页，含父请求 ID、尝试序号与时间、服务商/渠道/端点、上游模型及请求 ID、结果、HTTP 状态、耗时、错误及回退原因，能打开父请求详情。CSV 使用当前视图和筛选结果，保留脱敏和缺失口径。
- 服务监控默认近 24 小时，按实际派发且有时间的上游尝试统计，支持服务商 / 渠道、端点、对外调用标识筛选及服务商/渠道/端点对比。尝试量、失败率、P95 耗时用折线，429/超时/回退用分组柱，RPM/TPM 容量图以双折线展示均值和实际单分钟峰值。点趋势或对比行带时间、归属及适用异常条件进入上游尝试日志。平均速率除以实际观察分钟，缺失采集字段显示未采集或横线。旧尝试无时间时仍在父请求详情及 ID 查询中可查，不参与时序。原型从 D1 读取模拟请求及保留期内的计量事实。

## Token 生产

- 保留集群纳管、模型部署、制品镜像、生产观测；制品镜像是独立入口，内部模型制品/基础镜像/运行时镜像分类保持，部署不再重复模块切换栏。
- 部署为列表、全页三步编辑与详情；模型权重/挂载路径和运行时镜像分别校验，不能把基础镜像或权重当运行时。目标/就绪副本独立，缺少历史观测显示未知，不编造监控、日志、自动扩缩容或滚动发布。
- 生命周期通过部署事务原子同步集群分配、部署状态和端点；停止/失败只释放一次，重启复用端点。失败/停止可修复重建，待处理任务不能更新；扩缩容不增加配置版本。回滚保留完整旧配置，当前及回滚权重/镜像引用受保护。
- 部署不自动发布销售服务或改供应/价格；仍为生命周期模拟，状态及端点关系保存在 D1。详细规格见[模型部署设计](../../docs/admin-v2/MODEL-DEPLOYMENT-DESIGN-5120.md)，布局与验收沿用[后台通用约束](../../docs/PAGE-SPEC.md#后台视觉实施与验收)。

路由及映射不再提供“查看调用示例”，调用内容统一在 “调用指南”页签 维护。普通服务在统一路由编辑抽屉中选择渠道并建立映射，先保存、验证，再明确启用；不自动参与路由。

路由策略、参与渠道及权重默认只读，提供各路由功能区域的“编辑”入口，点击后修改；仅编辑态提供“取消”和“保存并生效”。取消恢复原配置并返回编辑入口；保存经变更核对及现有权限、并发和策略校验后生效并返回只读，失败保留输入。

统一模型服务模式与渠道直选模式售价在“模型售价 → 服务售价详情 → 售价配置”展示及编辑，复用同一价格表；完整显示全部计费项，金额、币种和单位清晰对应。展示态提供“编辑售价”，编辑态提供添加、移除、取消和预览变更；取消恢复当前生效售价，未保存修改仍需确认。价格表合并重复服务商和对外调用标识，字段顺序为服务商名称、对外调用标识、计费项、售价、货币、计费单位，查看态不显示空操作列，编辑态提供移除操作。统一模型服务模式的服务商名称读取稳定记录 provider-moma 的当前名称；该内置平台服务商在服务商目录置顶，禁止删除。渠道直选模式读取对应服务商的当前名称。对外调用标识读取对外调用标识（统一模型服务模式为模型级 ID，渠道直选模式为对应服务 ID），tooltip 为“用户调用时填写的 Model ID”，在售价页只读，仍在路由及映射维护。金额与币种分别维护，编辑态展示当前路由的采购成本参照，不自动推算不可比的利润；不展示适用条件输入列；历史在独立变更记录页签展示。保留既有条件数据、历史版本及发布校验。

工作区不显示配置检查提示块；页头保留既有配置状态，接入任务继续入口保留。客户范围从服务概览维护，调用验证从启用或上架检查进入。渠道列表不常驻“可用”标签；供给检查结果及原因放入渠道详情。渠道详情提供明确的打开入口并保留当前对象上下文；统一模型服务模式与渠道直选模式共用，保留详情字段、权限及原有操作确认，Esc/关闭后焦点回到对应按钮。模型映射列表明确标注“上游模型标识”，对外调用标识 由对应服务统一展示。Radix 表单代理控件不重复绘制。

后台“调用指南”提供 cURL、Python、Java、Go 示例；各示例独立编辑、取消、保存并生效、复制和格式化所选 JSON。编辑时提供名称明确的“预览”和“输入代码”区域，窄屏与键盘操作保持可达；一次编辑一个示例，前台语言切换保持不变。

模型服务目录创建区仅“新增模型服务”为主按钮，移除“更多模型创建方式”及其接入/批量导入菜单；不再单独显示接入主按钮、批量导入图标或演示范围选择器。目录数量仅在标题显示。演示模型/全部模型切换位于研发说明中的模型服务案例区，使用原有目录查询和未保存守卫，已有记录与当前模型上下文保留。新增服务必须从渠道接入中已登记的模型选择，候选与渠道接入的模型视图共用供应登记查询，按主档去重；没有供应登记的模型资料不进入候选，已有服务的模型仍显示但禁止重复创建。进入新增服务须保留 catalogue 参数；已有服务的资料仍标记并禁用重复创建。历史与手工资料不删除、不改名、不合并。

新增模型服务只读展示引用的模型卡片，缺少正式服务必需资料时通过“维护模型资料”补全后返回；不在新建服务页另填名称、类型和能力。服务模式及对外调用标识在创建时填写。渠道检测后的“前往服务管理”打开该主档的已有服务；没有服务则直接预选该模型进入创建，不静默展示另一款模型。新增模型服务标注“已接入模型”为必选，提供“前往渠道接入”入口；服务端重新检查主档和当前供应登记关系，关系已移除时拒绝保存，跳转保留未保存保护。 对尚未进入当前服务目录、但已占用内部服务身份的历史主档，创建时原子复用其稳定服务ID并保留独立主档，禁止重复创建；新服务保持未上架和调用关闭，既有供应、价格和路由历史保留。

## 模型运营维护交互

- 模型资料基础字段默认展开，高级模态任务、能力、参数和来源分组收起；查看编辑用同一类型名称与上下文单位。编辑共享卡片前提示影响服务。
- 接入模型内联搜索多选，一次提交后可继续接入渠道。接入渠道可新建或复用当前服务商已有连接，复用只新增模型关系，不改共享地址、密钥或其他模型成本。采购项优先显示对应类型常用项，保留全部搜索。
- 路由引用区分当前使用、配置保留引用和路由草稿；固定路由编辑可移出未参与条目，预览确认后释放引用。停用或解除映射保留引用保护，并可直接前往处理。停用服务商服务须明确当前模型、服务商及调用标识，不能误指整个服务商。
- 调用标识维护先下架停服，核对原值与新值并确认客户迁移；保持规范身份、记录ID及历史，不创建自动别名。归档服务须无活动路由、草稿、映射、服务商和未完成任务；可按已归档筛选并恢复，恢复保持下架停服。
- 字典中文名和单位优先，英文与内部标识为辅助；密钥紧急动作位于更多操作中并明确影响。操作记录支持搜索、类型筛选和安全的旧新值摘要；旧记录无快照时明确缺失，不回填虚构值，不展示凭证。

## 模型成本与模型售价

- 两个列表保留原搜索，增加模型展示名、服务商及状态独立筛选并按交集组合；成本状态为已配置、待配置、已失效，售价使用列表已有销售状态（未上架、在售、灰度在售、已停售、服务不可用、不可销售、不销售）。模型及服务商选项按稳定 ID 去重，不按展示名合并；统一模型服务模式归属内置平台服务商。选项读取当前列表有效记录，筛选不写业务数据。变更筛选或重置回到第一页，重置清除搜索及三个筛选但保留来源模型上下文；筛选和页码写入 URL，刷新及详情面包屑返回保留。无匹配结果显示空态，不自动替换所选对象。

- 模型成本按服务商、渠道及模型关联展示有效渠道采购价和适用条件。操作列仅有「编辑」，直接打开对应来源的采购价抽屉；采购版本、生效／到期时间和历史在抽屉查看。编辑复用采购版本事务。零价与缺价分开，调价不追改旧请求及价格快照，不清除技术证据。
- 成本、售价、渠道和资料通过同一 D1 读写边界；直接 URL、刷新、权限、冲突及失败输入保护与原模块一致。新增对象不因缺价落入另一套本地存储。
- 模型售价按统一模型服务模式或服务商服务的稳定 ID 定位；详情依次为售价配置、销售设置、变更记录。失效价格不作为生效价，不回退复活旧版本；切换服务模式保留历史并隔离代际。
- 内部服务不要求售价且不销售；变更用途必须停服、停售并核对商业依赖。无法核对时阻断，不自动收费、退费或重写权益。
- 管理端模拟记录保留调用时来源、成本版本及计量依据；无成本待核算，内部验证无订单／订阅／销售费用；同操作 ID 重放不重复写版本、请求或费用。
