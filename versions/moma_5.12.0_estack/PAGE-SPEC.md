# 5.12.0 页面当前约束

本文件汇总本版本有效页面与业务约束。模型运营按[五模块执行计划](MODEL_OPERATIONS_REORGANIZATION_PLAN.md)实施；实际本地验证及发布边界见[实施台账](MODEL_ONBOARDING_PROGRESS.md)。历史 UX 文档不恢复已移除的入口或旧前置条件。

## 全站 Mock 数据与双面联动

- 5.12.0 初始资源、参考目录和模拟响应统一在 `src/mock/` 配置维护，管理端模型运营运行数据由 Workers + D1 统一持久化，其他模块通过版本内浏览器业务存储关联；详见 [Mock 数据合同](MOCK_DATA.md)。本节替代共享页面中“组织及成员仅保存在独立前台样例”的旧约束，仅适用于本版本。
- 系统初始数据与用户配置分开标记；恢复存档不重放初始生成器、不补回删除资源。手工记录、草稿、订单、历史与未知来源数据保留，旧无归属记录不自动认领。
- 前台 Key、订购、组织及成员、客户智能路由和在线体验记录落到共享业务集合；客户作用域、所有者、修订冲突及存储错误在写入边界校验。后台修改相同记录后，前台经事件、同源标签页更新或聚焦复查读取新值。
- 调用日志、租户用量、平台概览及用户统计从同一请求和显式身份事件派生。未采集 Tokens、费用或时延显示未知；本地回复不构成真实上游或计费证据。图表样例继续使用静态 JSON 配置和原有派生逻辑；不写入 D1。租户侧和其他未迁移模块仍使用浏览器存储，不与 D1 自动双写。
- 前台编辑在打开时冻结修订号，跨标签页更新不得静默覆盖当前输入；冲突保留输入并要求刷新。账号/客户切换清除旧临时表单及明文 Key，已保存筛选视图按身份隔离。关闭 Key 额度后保存/刷新保持不限，相同额度与周期重新启用保留原用量；TPM/QPM 按实际值保存和模拟校验，不豁免客户额度与权限。
- 统计分类匹配实际模型类型，基础模型筛选纳入其服务商服务调用；请求保留发送时调用 ID，未知计量不填零，音频秒数/字符与 Token 分开。不使用固定样例数作为当前套餐权益或剩余额度。
- 动态历史样例只绑定固定初始资源且保留有效归属，不能因新增/编辑 Key、模型或成员而重分配历史；用户真实动作产生的请求独立保留。重复 Request ID 校验 Key、客户、模型及服务归属，冲突不返回原记录，已撤权 Key 不能重放成功。

## 模型运营云端持久化

- `listing`、`providers`、`model-costs`、`model-prices`、`model-templates`、`tariff-dictionary` 使用 `/api/5120/`。模型资料、服务商、密钥组/池、渠道及映射、采购/售价历史、服务、路由、检测与试调用、发布和操作审计均落 D1；筛选和未提交输入保留在浏览器。
- 后端以 HttpOnly 会话确认账号及权限，复用 5.12.0 领域规则；前端提交预期修订和操作 ID。业务变更、模拟状态、回执和审计一次原子保存，成功后才关闭编辑；失败保留输入，未知提交结果先核对原操作，冲突要求载入最新数据。断网不回退为本地保存成功。
- 仓库 JSON 只作为首次导入与只读参考来源；已有 D1 不因刷新、发布或切换演示范围重置。完整历史静态模型集合保留原 ID，默认仍展示两个运营案例；旧版价格按原记录保留，不能补造当前生效价格或检查证据。
- 本期仅管理端模型运营切换。用户浏览器旧存档保持原状，不隐式导入、合并或删除；租户侧订购、体验、计费及后台统计继续沿用原范围，不能把管理端 D1 模拟当作真实上游或租户网关。

## 导航与共享页面

- 后台顶栏控件、导航、面包屑、模块页签和模型运营登录采用 Semi Design 原生组件。登录保留账号、密码与原认证流程，错误信息紧邻表单；窄屏可使用导航弹窗，短窗口允许滚动。
- 旧后台通用样式只应用于标记为旧版的页面内容和对应弹层，外壳、新版 Semi 页面及前台保持各自样式。后续页面迁移完成时移除该页面的旧样式标记。
- 后台 2 运营分析为用量数据、用户数据、供给数据、经营数据四个同级入口；运营和系统管理员可访问，运维不可访问。运维入口称调用数据，保留 `call-analysis` 路由。模型运营依次为渠道接入、模型服务（默认入口）、模型成本、模型售价、模型资料。模型资料保留模型、计费项、计价单位、货币四个页签，分别维护模型主档和共用字典；模型成本、模型售价的“计量配置”均进入同一字典页面，切换字典页签保留来源返回路径，面包屑统一归属模型资料。
- 不提供独立 `service-routing` 页面；路由在模型工作区“渠道与路由”维护，领域事务、历史配置和数据保留。概览为运营默认首页，不恢复旧独立工作台或安全治理模块。
- 运营导航底部的入门指导分组保留“模型运营”指南（`getting-started`），运维不可访问；接入和维护流程就近提供帮助，不强制先读教程，不因首次登录强制新建。渠道接入不恢复旧使用引导弹窗。
- 面包屑复用版本内 `breadcrumbs.mjs`。向导为“模型运营 > 接入并上架模型”，返回注明来源；任务跳转保留模型、页签、筛选及当前输入，缺失对象不静默替换。普通详情不重复返回按钮；独立订购页返回当前版本订购入口。
- 租户空间、账号认证、调用日志、API Key、客户与后台账号沿用[对应共享页面章节](../../docs/PAGE-SPEC.md)；用户管理、账号管理、Token 生产等模块的保留与入口以本版本规格为准。前台隐藏模型排行，组织及成员/组织操作记录仅政企空间，调用日志不向个人空间渲染。

## 流量运营

- 限流配置页使用 Semi Design 原生卡片、页签、表格、表单、弹窗和反馈样式。页面样式只设置布局、间距与响应式宽度，旧后台样式不覆盖此区域。
- 运营区「流量运营」下的「限流配置」提供「用户限流」「模型限流」两个页签，默认打开用户限流。平台管理员和运营人员可访问。用户列表显示账号名称、账号 ID、账号类型、RPM、TPM、规则来源和操作，支持搜索账号名称或 ID 以及按账号类型筛选。
- 用户列表筛选区上方以紧凑的配置栏展示全局默认 RPM、TPM，支持就地编辑。新账号和没有自定义通用额度的账号使用当前全局默认值。缺失限流值显示为未配置。
- 「操作 → 编辑」弹窗仅提供单账号 RPM、TPM。勾选账号后可在弹窗中批量修改 RPM、TPM，或恢复全局默认。额度提交保留已存模型特例。筛选、切换页签和批量操作成功时清空选择。已有配置按模型特例、账号自定义、全局默认的顺序生效。
- 模型列表从本地业务工作区的模型资料主档取数，分别展示模型名称、模型标识、RPM、TPM、配置状态和操作。RPM 和 TPM 在模型行内编辑。模型共享上限按主档关联，由所有账号共享，与账号限流独立。限流值须为正整数。
- 配置使用版本内浏览器业务存储，复用后台角色、修订冲突、操作审计和离开前保护。当前原型范围为配置及规则解析。

## 模型身份与资料

- 术语由 [GLOSSARY](GLOSSARY.md)定义：模型资料、供应关系和销售服务各有职责，资料 ID/模型编码/上游模型标识/对外调用标识 不混用，模型作者不等于服务商；采购参考价、采购价和平台售价分开。完整 URL 称请求地址，Key 按当前绑定渠道表达。
- 模型资料库统一维护当前主档；按稳定 ID、显式关联或精确编码识别模型，不按名称近似合并版本。已有运营资料是主档，旧模板不能成为第二个可编辑来源；服务和供应页面读取同一主档。
- 六类主要用途为语言模型、视觉理解、视觉生成、语音模型、向量模型、重排模型；语言模型可支持图像/视频输入，不能仅因名称含 VL 或具备图像能力改类。既有类型代码、图像/视频任务及计量单位保留。输入/输出模态与向量/相关性等结果类型区分，未知能力/规格保持未填写。
- 资料库保留表格、查看、编辑及删除入口；长内容提供完整值的可访问查看方式，宽度不足时在表格区域滚动。资料列表名称/编码、作者、正式发布日期、类型、适用场景、模态及上下文各有语义；日期来自可核对官方首次发布记录，场景不替换为支持任务。维护分页 20/50/100、默认 20，选择流程保留自己的容量；切换容量只提交一次容量和第一页。
- 基础资料库的共享主档编辑按用途分区：模型卡片维护名称、Logo、类型、输入/输出模态、结果类型、上下文与简短介绍；模型详情维护作者、适用场景、支持语言、任务、资料链接、详细介绍及按类型展示的能力规格；模型编码、系列、版本与发布日期在“其他信息”，技术与接口属性独立展开。共用字段仅维护一次，不新增第二套卡片/详情可编辑主档。售价在独立模型售价维护；模式、关联和对外调用标识 在渠道与路由维护；现有模型级客户范围归调用授权页签，页头不再编辑范围。
- 前台卡片和详情读取同一份已生效资料：Logo 缺失或存储内容不合法时使用默认图标，图片加载失败时名称仍可读；详情复用卡片公共信息，并显示已填写的长介绍、模型编码、版本/发布日期、能力规格、技术接口属性及资料链接。未知属性不补零或“支持”，正式发布日期与卡片的资料更新时间分开；不把采购价、供应密钥、内部请求地址和资料核对记录投影给客户。点击卡片进入独立详情页，按面包屑、模型介绍与三项参数、服务商报价、API 调用、详细资料组织；返回广场保留当前筛选并恢复原卡片焦点。URL 保留稳定模型与服务 ID，支持刷新和浏览器前进/后退；失效或无权访问时显示不可用，不自动替换为其他服务。
- 渠道直选模式详情每家服务商一行，展开显示全部已发布计费项、对外调用标识 及体验入口；统一模型服务模式只有平台统一模型服务模式一行。API 调用区按获取 API Key、调用模型服务两步组织，渠道直选模式可切换服务商并同步代码示例。密钥由既有 API Key 页面维护，不在详情复制维护表；没有订单依据不展示“已订购”，没有实际平台发布时间不冒用模型发布日期。可见性、客户授权、发布验证及任务准入条件保留。
- 前台模型广场按稳定模型 ID 聚合卡片；已有演示集时默认只展示 GLM-5.3（渠道直选模式）和 DeepSeek-V4-Flash-0731（统一模型服务模式），“全部模型”保留其他已授权服务。按发布日期排序，不把渠道直选模式服务计为多个模型；服务商筛选匹配卡片内各服务。渠道直选模式详情可选择提供方，售价、调用 ID、调用示例和在线体验使用同一服务身份；统一模型服务模式使用平台统一售价和调用 ID。售价仅取平台已发布销售快照，明确币种/计量单位，未提交输入、采购价和内部渠道不对客展示。调用示例与后台复用生成规则；体验选择器和新回复显示提供方，历史回复保留当时身份。
- 主档名称、介绍、图标等在当前表单编辑，预览受影响服务并明确提交后同步引用展示；不因展示文字修改重测连接。类型、能力、模态、任务、版本及深度思考/结构化能力变更走专门影响检查，重验受影响范围；不兼容依赖先修复或明确下架，合格后发布，不直接覆盖在线配置。仅属性顺序变化不误判，稳定身份、权限、修订、存储和焦点保护保留。
- 模型运营初始数据集中于 [Mock 配置](MODEL_OPERATIONS_MOCK_DATA.md)，基础资料、供应管理、模型服务共用稳定引用与目录范围，前台读取后台生效服务。只在没有存档时初始化；已有用户配置、删除记录、凭证、草稿与历史不因刷新或配置更新被补回或覆盖。
- 删除主档须没有供应、服务或活动配置引用，界面禁用与事务校验一致。添加供应模型从主档选择，可原地新增主档并返回选中，不自动登记供应关系或渠道。批量只接受匹配主档的模型，不接受任意未匹配上游 ID，不生成空渠道。
- 对外服务正式资料沿用其现有完整校验；技术接入可以先保存最低身份资料，任务/能力缺失保持待完善，不能据此启用技术服务或上架。资料与服务编码规则的已知差异见 [MODEL_OPERATIONS_TERMS_REVIEW](MODEL_OPERATIONS_TERMS_REVIEW.md)，不靠改名宣称差异已修复。CSV 前两列统一模型编码/模型展示名，不增加旧表头别名。

## 渠道接入

渠道接入页（服务商/模型双视图）、模型渠道表、API 密钥池、接入新模型/新渠道表单、渠道编辑抽屉、密钥池与凭证候选编辑及接入记录续配使用 Semi Design 原生组件和默认样式。保留默认配色、字体、字号、圆角、表单和表格密度，仅设置布局、间距和响应式规则；旧后台样式不覆盖该区域及其弹层。表格合并单元格、脱敏、候选测试与应用等行为按本章既有条款保持。

API 密钥池列表按密钥组展示优先级、密钥名称 / ID、脱敏密钥、当前绑定渠道、状态与操作。名称在前，稳定短编码在后，底层 ID 与引用不改写。上移／下移只交换相邻条目，边界禁用；顺序和版本持久化。备用顺序不改变当前生效密钥；切换有渠道引用的首位密钥先保存候选、展示影响、检测全部引用，明确应用后原子生效。失败保留当前顺序，刷新可继续候选；并发、角色及写失败保护保留。

两条旧演示渠道 supplier-review-CH-001 / supplier-review-CH-002 及其四条初始样例映射不再作为默认数据安装；已有线上记录须核对无供应、路由、模型关联及任务引用后，通过现有删除渠道事务归档。合法手工保存的未关联渠道继续保留，不因状态文案自动清理。


渠道接入页头仅保留添加服务商，移除“接入并上架模型”入口；模型、渠道继续通过服务商详情分别添加。指定的三条 D1 验收服务商及其已下架服务、独占渠道/映射和服务路由经管理员明确确认后逐条原子归档，不按名称前缀清理。保留主档、价格历史、调用与审计；存在非验收业务引用、运行中的服务、未完成任务或新增资源时拒绝归档。


- 渠道接入默认进入服务商视图，视角切换按服务商、模型排列；显式模型视图链接继续进入模型视图。模型工作区提供本模型的供应接入入口；同源查询和 provider/tab 上下文继续复用。资源视角切换与搜索在目录面板内，键盘焦点和空目录可操作，不复制业务记录。
- 服务商详情不展示“服务商更多操作”及其停用弹窗；保留独立的服务商资料编辑入口。模型渠道表中的模型展示名仅展示，不提供修改图标、改名弹窗或改名命令；已有服务商登记名称和配置不清空，统一模型资料仍在模型资料模块维护。渠道编辑、测试连接和删除等操作保留。

## 密钥与维护

- 密钥库与租户 API Key 独立。只保存掩码、SHA-256 去重指纹及引用元数据，明文不进入草稿、存储、审计、日志或产物；不宣称已接服务端凭证库。
- 产品继续使用 API 密钥，不改名 API 凭证。服务商密钥页维护密钥资产和分组；渠道的密钥池维护多条绑定、启用状态和 1–100 优先级，数值小者优先，同级按列表顺序。旧专属、默认及共享组引用不自动转换；移除“设为主要”入口，已有组顺序保留。
- 渠道列表和渠道模型展示健康状态；健康与启用分开。逐渠道模型、逐密钥检测，结果展示时间、HTTP 状态、耗时和失败原因，支持确认、取消和重试。结果有效期为 24 小时；地址、模型映射、密钥版本变化要求复测；单 Key 通过不代表整个密钥池正常。检测只写诊断历史，不修改启用、映射、路由或价格；本地结果标识“模拟检测”。
- 密钥池变更走候选配置→逐条测试全部启用密钥→明确应用，校验全部必要模型及服务影响；单 Key 通过不能替代其他 Key，失败、过期、待完成及不匹配回执均不放行。未关联模型须先接入模型再验证。本批不新增自动轮询、额度调度或熔断冷却。
- 密钥按实际渠道引用聚合，长 ID 可换行；没有密钥不伪造占位记录，不把未关联旧渠道作为整个模型目录的错误。添加/替换不回显原文，沿用可见 ASCII、长度、重复和数量校验，保存只提交脱敏信息。
- 正常轮换与撤销分开：正常轮换不自动撤销旧 Key；专属渠道和共享组按实际引用范围处理，不能误改其他渠道。替换/删除等影响动作保留确认、稳定身份/关联规则及验证失效处理，相关细节见[接入规格第 23 节](MODEL_ONBOARDING_SPEC.md#23-目录外接入与日常维护简化2026-10-31)。
- 渠道配置和测试可打开已有添加密钥弹窗，父表单当前输入保留。测试切换密钥组仅作用本次检查，明确修改渠道配置才持久化；测试结果单一呈现，接口不匹配优先于旧通过记录。测试/调用明确提示用量确认，保留取消、重试和失败恢复。
- 地址和 Key 维护先保存候选并测试，通过后仍需明确应用；失败保留当前配置。历史恢复入口共用固定范围和有效性校验，不保留绕过检查的旧结果直达路径；不因测试成功自动启用、改路由或上架。
- 成功、超时等模拟场景选择只在地址参数 `devtools=1` 的研发视图显示，普通业务页面隐藏；测试结果保留实际来源，不将本地 Mock 记为真实上游证据。

## 模型服务与调用路由

- 新工作区模型运营默认展示 GLM-5.3（渠道直选模式）和 DeepSeek-V4-Flash-0731（统一模型服务模式）两个对比案例，以及用户新增/修改的资源。“全部模型”与深链保留历史系统案例。没有来源标记的旧存档按用户已有数据保留；已配置完成无需常驻大块成功提示，配置缺口保留明确处理入口。
- 模型服务采用对象清单与内联工作区，包含接入中、未上架、已上架及已下架模型；稳定关联避免任务和服务重复显示为两款模型。保留名称/ID、类型/模式/状态筛选与批量能力；不存在或被过滤对象显示原因和返回入口。
- 销售展示由模型售价的销售设置维护 `marketVisible`，未配置时沿用原可见性语义；同一模型共用展示开关。展示、技术启停、销售状态和调用授权独立，保存展示不改技术状态、价格、路由、调用范围或历史；复用角色、修订、原子保存和未提交保护。此轮仅验管理端，不据此宣称前台 D1 联动。
- 服务工作区依次为服务概览、渠道与路由、故障转移、调用授权、调用指南、平台试调用、操作记录。页头保留模型身份，在模型名下用 Semi Badge 展示服务状态和可见性；服务状态为正式上架、已下架或灰度上架，可见性为用户不可见、用户可见或灰度用户可见。可见性独立读取展示开关与灰度阶段，沿用未配置展示开关时用户可见的语义；下架不清除灰度配置。售价／销售入口带稳定服务 ID 跳入模型售价；原价格编辑删除。跨页保留来源对象、页签与筛选；任务入口定位现有资源，缺失对象明确报错，未保存输入有离开保护。
- 服务概览为默认页签，展示唯一资料引用、调用范围，以及服务提供方、对外调用标识、成本和售价摘要与定向跳转；移除用途、操作两列及修改用途弹窗，不展示技术启停或归档按钮，不重复列出技术／销售状态。模型资料只能从资料模块维护；调用标识仍在服务上下文维护。统一模型服务模式用途为模型级，渠道直选模式用途绑定具体服务；调用授权沿用模型级全部／指定有效客户，不增加企业成员、用户 Key 或多层授权。
- 每个模型只有一种服务模式：`standard` 为统一模型服务模式，模型级统一售价；`provider` 为渠道直选模式，各显式关联服务商有独立对外调用标识、售价及路由，同服务商多个渠道共用售价。采购价在供应侧维护，平台售价在服务侧维护；不恢复逐渠道平台零售价或两种模式同时生效。
- 选择及切换服务模式的弹窗用两段短说明，从用户选择、调用 ID/价格和平台调度范围解释两种模式，不使用大对照表；未选择也能阅读，且与模式提示共用文案。选择与切换仍保留既有下架、重配、未保存和权限保护。
- 未上架模型可未选模式；关联渠道及上架前必须选择，未选时显示配置空态，不展示旧渠道或推断默认。已选模式只读，独立入口显式确认切换；确认切换以一次事务完成下架、服务关联重置、路由/草稿失效和价格代际递增，资源及历史保留，取消不写。切回旧模式不能使旧价格复活。
- 渠道与路由选择已检测并启用的同款模型供给并维护调用 ID；调用授权页内编辑、预览并提交客户范围；模型售价独立编辑价格及销售设置。任务间不得夹带未提交输入，不创建虚假资源、不自动参加调度；采购变更不改变已发布售价。
- 映射和路由保持一个 Tab 和一个日常编辑流程。当前调用关系表不再重复展示独立映射管理表。已有未参与路由的备用映射、候选变更及其预览、验证、应用、停用、解除能力保留在“主表 → 模型映射”，不自动应用或清理。引用、同一资料主档、服务商隔离和协议兼容检查继续有效。
- “新增映射”以 Semi 原生组件展示模型服务、服务模式和对外调用标识。统一模型服务模式可选择服务商，渠道直选模式只读显示当前服务商。按服务商筛选同一主档下已验证并启用、且没有现有或待应用映射引用的渠道模型供给。切换服务商清空已选供给及上游模型标识。上游模型标识由所选供给带出，单一适用平台接口直接显示，映射名称选填并默认使用渠道名称。
- 映射预览只展示两侧请求；服务端验证复用当前供给检测证据并核验标识、路径和协议，不发起新用量，不替代平台试调用。新增映射待验证且未启用；在用映射只改名；未引用映射的供给变更保存为候选，原有效配置持续保留，验证后明确应用或放弃。生效与草稿路由全部条目、未完成任务阻断停用／解除及目标切换；供应侧删除检查候选引用。保留旧有效关系、价格、凭证元数据和历史；不重放初始数据或无提示改写已有关系。
- 新服务商可从“关联服务商及渠道”创建并返回选择。先确认关联，再保存调用标识并选择主渠道。路由编辑只选择当前模型下已有且检测启用的渠道，不提供“接入新渠道”或内联登记流程。供应模型登记、渠道地址、协议、上游标识与密钥统一在渠道接入模块维护；完成检测并明确启用后，回到服务路由编辑选择目标，经预览原子建立映射并生效。保存渠道不自动加入路由或上架。
- 灰度上架须明确指定当前调用授权内的有效客户，独立保存灰度范围；实际生效范围与当前调用授权取交集，授权缩小时不扩大灰度。正式上架解除灰度限制，沿用当前调用授权。两者复用经营上架检查与原子事务，要求技术服务已启用、成本售价及验证有效；下架停止销售，技术状态独立保留。可见性只控制广场展示，不授予调用权限。
- 模型成本、模型售价及其详情、编辑、预览、历史使用 Semi Design 原生样式，表单与弹层保留权限、修订冲突和未保存保护。列表按模型展示名、服务商和成本/销售状态组合筛选，保留搜索、重置和来源返回路径；按模型主档稳定引用合并模型展示名单元格，同名不同模型不得合并。列表不分页，固定表头、局部横向和纵向滚动；售价按每条计费项展示售价、计价单位和货币，服务级单元格跨计费项合并，缺价不显示零。
- 切换服务模式使用三个连续步骤：确认下架该模型、确认清除模型映射及路由、重新设置服务模式。前两步分别显式勾选确认，最后调用既有原子重置/下架事务；此前当前配置保持生效，中途取消保留配置，提交失败保留草稿。保留原模式价格历史、资料及接入资源，不将旧售价自动复制到新模式。
- 模型运营字段按[字段命名与归属](MODEL_OPERATIONS_FIELD_DICTIONARY.md)统一，供应商/服务提供方的界面称谓统一为服务商；规范模型标识、对外调用标识、上游模型标识分别对应主档、客户请求、上游请求，不更改协议键和用户历史记录。
- 模型服务目录、服务概览、渠道与路由、故障转移、调用授权、调用指南、平台试调用、操作记录，以及新建服务、路由/映射编辑、开放范围与上架配置，使用 Semi Design 原生组件和默认样式。保留默认配色、字体、字号、圆角、表单和表格密度，仅设置布局、间距和响应式规则；旧后台样式不覆盖该区域及其弹层。服务目录展示名称、状态、模式、配置状态与调用标识；各页签保留 URL 状态，宽屏左右分栏，窄屏上下排列。路由表按服务合并提供方、调用标识与策略，操作列固定在右侧，局部横向滚动；点击策略或渠道操作打开当前服务的 Semi 抽屉，保留选中渠道提示、未保存守卫、版本冲突和核对后生效流程。服务操作提供灰度上架、正式上架、下架、可见性配置；服务概览不提供技术启停和归档按钮；平台试调用在同名页签内执行，展示模拟请求和试算结果。成本、售价与接入资源仍通过原有稳定引用跳转，不在服务页面复制主档。
- 渠道与路由用一张关系表呈现：服务提供方、对外调用标识、路由策略、上游渠道、上游模型标识、操作。同一服务的提供方、调用标识和策略跨渠道合并单元格；统一模型服务模式显示当前平台内置服务商，渠道直选模式按各服务商服务分组，展示主渠道，省略路由策略列。上游渠道按行展示，权重靠右，ID 左侧提供复制图标。操作列直接提供编辑路由、编辑调用标识、模型映射、停用或恢复路由，以及渠道直选模式下的服务商停服/恢复、符合条件时解绑；按服务合并操作单元格，编辑路由打开宽抽屉，入口位于屏幕右侧时从左侧打开，反之从右侧打开。对外调用标识 tooltip：“用户调用左侧的模型。平台将请求转发给右侧的上游模型。”
- 编辑渠道与路由时，直接选择同一模型资料对应、已检测并启用的供应渠道，自动读取上游标识和支持的平台接口，不重复填写地址、密钥或采购价。统一模型服务模式可跨服务商，渠道直选模式仅当前服务商。新目标的映射建立、检查、启用与路由发布在单个事务内提交；预览只读，复用供给检测证据，不发送请求，不隐式改变销售、停服或上架状态。保存失败、取消、权限变化或修订冲突保留草稿及原有效配置。现有映射 ID、未应用变更、未选中的备用映射、历史运行参数和路由历史保留；已有复杂映射维护从主表操作列的“模型映射”进入。
- 统一模型服务模式只提供五种路由策略：加权随机路由（simple-shuffle，默认）、最少并发路由（least-busy）、最低 TPM 路由（usage-based-routing-v2）、最低延迟路由（latency-based-routing）、最低成本路由（cost-based-routing）。不支持固定渠道，单渠道使用 100% 权重。渠道直选模式为每个服务商服务单选一个主渠道，界面不提供路由策略设置。原内部策略键保留稳定引用，配置标识通过同一策略字典展示和发布；已有不再适用的统一模式策略只读保留历史，重新保存须明确改选，不静默转换用户配置。
- 路由抽屉只维护策略、所选渠道、权重及策略必要参数；新路由不预选目标，权重合计须为 100%。故障转移在独立页签保存。统一模型服务模式在参与路由的渠道中转移。渠道直选模式启用故障转移时，从同服务商选择一个已验证并启用的备用渠道，主渠道不可用或失败时才尝试备用渠道。保存生成新配置版本，保留主渠道和策略，并要求重新验证。预览展示差异和调用关系，确认后原子生效。停用/恢复路由从主表直接进入确认，不再嵌套于抽屉：停用前须停服，隐藏不能代替停服；清空草稿，保留映射和历史。恢复校验最后发布配置，有草稿时先明确编辑发布，不自动恢复服务或上架。调用标识、模型映射和服务商停服/解绑同样从主表进入，权限、依赖、影响确认和未保存保护保持。
- RPM / TPM 限额未配置时不推断为零；已配置限额必须有实际分钟用量，达到限额的渠道不参与分配。最低成本只比较相同计费项、条件、单位和货币，保留输入/输出/合计比较口径。
- 缺乏所选策略所需真实延迟、并发、分钟 Token 用量或可比成本时不能发布；协议转换仅支持已实现映射，不增加任意 URL 转换。回滚重新验证并生成新版本，历史保留；渠道加入服务不自动加入活动策略。
- 缺项在相关区域展示并提供直接修复入口；最终验证汇总当前资料、模式、采购/售价、范围、路由与发布证据。服务生命周期、任务进度、未发布修改和供应健康分开，列表只呈现必要状态，不以页码或勾选冒充完成。
- 模型服务提供技术验证、启用／停用；模型售价提供售价发布、销售对象、展示与上架／停售。技术启用检查资料、模式、身份、连接、映射、路由、有效客户范围及当前平台证据，不要求成本或售价。上架另检查技术已启用及经营服务有效成本／售价和销售对象；停售不停服，停服保留销售配置但阻断新增上架，恢复重新检查。

## 接入模型与模型运营指南

- 入门指导「模型运营」分为使用场景、渠道接入、模型服务、模型成本、模型售价、模型资料、日常维护七篇短指导，每次仅展示当前一篇；`getting-started?guide=...` 支持直达、刷新及前进后退，篇内补充内容按需展开。

- 模型资料默认按原厂发布日期从新到旧排列，同日期保持原顺序；缺失日期置末，仅到月份的原值不补造具体日期。不更改持久化记录顺序。

- 调用授权、销售对象与售价分别编辑、预览及确认。调用授权使用原模型级有效客户集合；销售对象为独立 `salesScope`，未设置时只读引用原调用范围，保存销售设置不修改调用授权。模型内经营服务共用销售对象和展示／销售状态，售价仍按统一或具体服务商服务归属。
- 技术启用弹窗列出资料、身份、连接、映射、路由、范围与平台证据，可前往缺项配置。销售上架在模型售价另行确认当前成本、售价、技术启用与销售对象。后台技术验证可缺价格，成本待核算、销售费用不适用；价格变化不清除技术证据，连接／能力／路由变化需重验。

## 保存、发布与恢复

- 后台不提供草稿保存、恢复或丢弃入口。编辑输入仅在当前页面保留；测试验证连接配置，不自动启用或上架。预览展示本任务差异、范围和阻塞项；明确发布或应用后才切换对应有效版本。
- 售价发布成功后立即作用于后续新请求，含已有订购客户；已开始请求及历史保留原价格快照，内部重试不换新售价。客户展示、后台及客户调用使用同一有效版本，不提供预约调价和专属协议价。
- 地址、密钥、路由、资料、售价和客户范围按相关任务独立提交；任何发布不得顺带应用其他任务输入。保存或发布失败保留当前输入和旧有效配置。
- 离开未提交页面只提供放弃本次修改／继续编辑；刷新不恢复未提交输入。历史未发布记录原样保留，不自动应用或作为新编辑的起点；报价历史可沿用后明确提交新版本。

渠道与路由不再提供“查看调用示例”，调用内容统一在 “调用指南”页签 维护。普通服务在统一路由编辑抽屉中选择渠道并建立映射，先保存、验证，再明确启用；不自动参与路由。

路由策略、参与渠道及权重默认只读，提供各路由功能区域的“编辑”入口，点击后修改；仅编辑态提供“取消”和“保存并生效”。取消恢复原配置并返回编辑入口；保存经变更核对及现有权限、并发和策略校验后生效并返回只读，失败保留输入。

统一模型服务模式与渠道直选模式售价在“模型售价 → 服务售价详情 → 售价配置”展示及编辑，复用同一价格表；完整显示全部计费项，金额、币种和单位清晰对应。展示态提供“编辑售价”，编辑态提供添加、移除、取消和预览变更；取消恢复当前生效售价，未保存修改仍需确认。价格表合并重复服务商和对外调用标识，字段顺序为服务商名称、对外调用标识、计费项、售价、货币、计价单位，查看态不显示空操作列，编辑态提供移除操作。统一模型服务模式的服务商名称读取稳定记录 provider-moma 的当前名称；该内置平台服务商在服务商目录置顶，禁止删除。渠道直选模式读取对应服务商的当前名称。对外调用标识读取对外调用标识（统一模型服务模式为模型级 ID，渠道直选模式为对应服务 ID），tooltip 为“用户调用时填写的 Model ID”，在售价页只读，仍在渠道与路由维护。金额与币种分别维护，编辑态展示当前路由的采购成本参照，不自动推算不可比的利润；不展示适用条件输入列；历史在独立变更记录页签展示。保留既有条件数据、历史版本及发布校验。

工作区不显示配置检查提示块；页头保留既有配置状态，接入任务继续入口保留。移除页头“维护客户范围”和“平台试调用”按钮；调用验证从“平台试调用”页签进入。渠道列表不常驻“可用”标签；供给检查结果及原因放入渠道详情。渠道详情提供明确的打开入口并保留当前对象上下文；统一模型服务模式与渠道直选模式共用，保留详情字段、权限及原有操作确认，Esc/关闭后焦点回到对应按钮。模型映射列表明确标注“上游模型标识”，对外调用标识 由对应服务统一展示。Radix 表单代理控件不重复绘制。

后台“调用指南”提供 cURL、Python、Java、Go 示例；各示例独立编辑、取消、保存并生效、复制和格式化所选 JSON。编辑时提供名称明确的“预览”和“输入代码”区域，窄屏与键盘操作保持可达；一次编辑一个示例，前台语言切换保持不变。

模型服务目录创建区仅“新增模型服务”为主按钮，移除“更多模型创建方式”及其接入/批量导入菜单；不再单独显示接入主按钮、批量导入图标或演示范围选择器。目录数量仅在标题显示。演示模型/全部模型切换位于研发说明中的模型服务案例区，使用原有目录查询和未保存守卫，已有记录与当前模型上下文保留。新增服务必须从渠道接入中已登记的模型选择，候选与渠道接入的模型视图共用供应登记查询，按主档去重；没有供应登记的模型资料不进入候选，已有服务的模型仍显示但禁止重复创建。进入新增服务须保留 catalogue 参数；已有服务的资料仍标记并禁用重复创建。历史与手工资料不删除、不改名、不合并。

新增模型服务只读展示引用的模型卡片，缺少正式服务必需资料时通过“维护模型资料”补全后返回；不在新建服务页另填名称、类型和能力。服务模式及对外调用标识在创建时填写。渠道检测后的“前往服务管理”打开该主档的已有服务；没有服务则直接预选该模型进入创建，不静默展示另一款模型。新增模型服务标注“已接入模型”为必选，提供“前往渠道接入”入口；服务端重新检查主档和当前供应登记关系，关系已移除时拒绝保存，跳转保留未保存保护。 对尚未进入当前服务目录、但已占用内部服务身份的历史主档，创建时原子复用其稳定服务ID并保留独立主档，禁止重复创建；新服务保持未上架和调用关闭，既有供应、价格和路由历史保留。

## 模型运营维护交互

- 模型资料基础字段默认展开，高级模态任务、能力、参数和来源分组收起；查看编辑用同一类型名称与上下文单位。编辑共享卡片前提示影响服务。
- 接入模型内联搜索多选，一次提交后可继续接入渠道。接入渠道可新建或复用当前服务商已有连接，复用只新增模型关系，不改共享地址、密钥或其他模型成本。采购项优先显示对应类型常用项，保留全部搜索。
- 路由引用区分当前使用、配置保留引用和路由草稿；固定路由编辑可移出未参与条目，预览确认后释放引用。停用或解除映射保留引用保护，并可直接前往处理。停用服务商服务须明确当前模型、服务商及调用标识，不能误指整个服务商。
- 调用标识维护先下架停服，核对原值与新值并确认客户迁移；保持规范身份、记录ID及历史，不创建自动别名。归档服务须无活动路由、草稿、映射、服务商和未完成任务；可按已归档筛选并恢复，恢复保持下架停服。
- 字典中文名和单位优先，英文与内部标识为辅助；密钥紧急动作位于更多操作中并明确影响。操作记录支持搜索、类型筛选和安全的旧新值摘要；旧记录无快照时明确缺失，不回填虚构值，不展示凭证。

## 模型成本与模型售价

- 两个列表保留原搜索，增加模型展示名、服务商及状态独立筛选并按交集组合；成本状态为已配置、待配置、已失效，售价使用列表已有销售状态（未上架、在售、灰度在售、已停售、服务不可用、不可销售、不销售）。模型及服务商选项按稳定 ID 去重，不按展示名合并；统一模型服务模式归属内置平台服务商。选项读取当前列表有效记录，筛选不写业务数据。变更筛选或重置回到第一页，重置清除搜索及三个筛选但保留来源模型上下文；筛选和页码写入 URL，刷新及详情面包屑返回保留。无匹配结果显示空态，不自动替换所选对象。

- 模型成本按服务商、渠道及模型关联定位，不把多个来源合为未经定义的单一成本。详情展示有效成本、版本、生效／到期时间和历史；编辑复用采购版本事务。零价与缺价分开，调价不追改旧请求及价格快照，不清除技术证据。
- 成本、售价、渠道和资料通过同一 D1 读写边界；直接 URL、刷新、权限、冲突及失败输入保护与原模块一致。新增对象不因缺价落入另一套本地存储。
- 模型售价按统一模型服务模式或服务商服务的稳定 ID 定位；详情依次为售价配置、销售设置、变更记录。失效价格不作为生效价，不回退复活旧版本；切换服务模式保留历史并隔离代际。
- 内部服务不要求售价且不销售；变更用途必须停服、停售并核对商业依赖。无法核对时阻断，不自动收费、退费或重写权益。
- 管理端模拟记录保留调用时来源、成本版本及计量依据；无成本待核算，内部验证无订单／订阅／销售费用；同操作 ID 重放不重复写版本、请求或费用。
