# 5.12.0 页面当前约束

- 个人、企业和后台统一使用 `#/auth/login`。验证成功后按账号身份及角色进入空间或后台工作区，只有原地址在当前权限范围内时才恢复；后台所有模块共用服务端会话，不保留模块登录页或登录弹窗。401 返回统一登录并保留原路径，403 显示权限拒绝；退出及账号切换撤销旧会话。

本文件汇总本版本有效页面与业务约束。模型运营以本页导航和各模块规则为准；实际本地验证及发布边界见[实施台账](MODEL_ONBOARDING_PROGRESS.md)。历史 UX 文档不恢复已移除的入口或旧前置条件。

## 全站 Mock 数据与双面联动

- 5.12.0 初始资源、参考目录和模拟响应统一在 `src/mock/` 配置维护，私有化发布使用 Workers + D1 保存模型运营、模型目录、订购、项目配置与调用记录。本地演示使用版本内浏览器业务存储；详见 [Mock 数据合同](MOCK_DATA.md)。本节替代共享页面中“组织及成员仅保存在独立前台样例”的旧约束，仅适用于本版本。
- 系统初始数据与用户配置分开标记；恢复存档不重放初始生成器、不补回删除资源。手工记录、草稿、订单、历史与未知来源数据保留，旧无归属记录不自动认领。
- 前台 Key、订购、组织及成员、客户智能路由和在线体验记录落到共享业务集合；客户作用域、所有者、修订冲突及存储错误在写入边界校验。后台修改相同记录后，前台经事件、同源标签页更新或聚焦复查读取新值。
- 「智能路由」提供「智能匹配」「模型预设」两个项目级页签。智能匹配首页只展示 Auto Router，企业管理员、当前项目管理员或个人本人从「路由设置」独立配置、保存和生效 `moma/auto`、`moma/performance`、`moma/cost`。「项目分流」在当前项目的「项目设置」中维护。预设有独立详情、编辑、API 调用和版本历史，切换历史版本须重新校验当前资格，调用 ID 保持稳定。启用的 Auto Router 和预设可从详情进入文本生成试用。智能匹配、模型预设的保存、版本、停用、试用、API 示例及调用均绑定同一项目；企业切项目切换配置并退出原项目的预设详情或编辑，个人固定唯一默认项目。各项目可独立使用相同调用 ID，API 按 Bearer 密钥所属项目解析，不接受客户端覆盖项目。项目管理员维护项目智能匹配；普通成员可查看已生效智能匹配及自己的模型预设，保留自有预设维护权，不能访问未加入项目。候选范围同时受项目模型权限、空间授权、订购及 Key 权限限制。后台读取与调用模拟使用同一项目归属和权限，路由审计记录项目 ID；保留稳定 ID、草稿、版本及调用历史。
- 从项目概览的「项目分流」进入「项目设置 → 项目分流」。项目管理员或企业管理员可编辑，已分配项目的普通成员可查看。API Key 条件引用同项目的有效 Key ID，用户标签条件匹配 `metadata._user`。按规则顺序选取目标服务，未命中使用默认服务，备用模型服务按保存顺序尝试，最多五个。私有化发布的调用示例保留 `project@策略标识`，配置与模拟调用使用客户工作区。
- 调用日志、租户用量、平台概览及用户统计从同一请求和显式身份事件派生。未采集 Tokens、费用或时延显示未知；本地回复不构成真实上游或计费证据。图表样例继续使用静态 JSON 配置和原有派生逻辑；不写入 D1。用户侧未迁移模块仍使用浏览器存储，不与 D1 自动双写。
- 前台编辑在打开时冻结修订号，跨标签页更新不得静默覆盖当前输入；冲突保留输入并要求刷新。账号/客户切换清除旧临时表单及明文 Key，已保存筛选视图按身份隔离。关闭 Key 额度后保存/刷新保持不限，相同额度与周期重新启用保留原用量；TPM/QPM 按实际值保存和模拟校验，不豁免客户额度与权限。
- 用户面项目选择、项目管理和项目分流复用 Semi Design 的页签、操作控件、表单与浮层。窄屏表格在当前面板内滚动，关闭分流编辑前确认未保存的修改。
- 模型广场筛选、搜索、详情操作和订购确认使用 Semi Design。窄屏筛选在抽屉打开，关闭时保留筛选条件并将焦点还给入口。
- 文本生成的输入、参数与新建确认，以及体验共用的模型选择弹窗使用 Semi Design。模型选择保留供应商、类型、计费方式和可体验条件，并沿用项目调用权限。客户账单使用 Semi 表格，用户面共用分页保留原有页容量。
- 文本、图片及视频体验的推荐提示沿用 Semi 填充与文本色；文本推荐在中等宽度显示三列、窄屏显示两列，保留完整提示词填入。新建对话与账号认证的主要入口使用实色按钮。体验参数使用业务名称与必要范围，不重复展示接口字段名。用户面弹窗限制在视口内，项目名称的必填错误在表单内中文提示。订购费用与确认区排在协议之后，不遮挡表单。
- 账号菜单、登录空间选择、密码找回、邀请与个人或企业认证使用 Semi Design。认证保持字段校验、协议链接和分步提交，错误保留在原表单中。
- 密码找回与修改复用登录页的品牌区和表单容器，保留验证码、密码校验与返回路径。
- 空间总览、用量统计、调用观测与调用日志共用 Semi 筛选和视图保存。调用日志使用 Semi 表格和请求详情抽屉，保留筛选导出、详情 JSON 和既有脱敏规则。
- 用户面空列表保留记录数，零条时隐藏分页操作。订购表格按服务、订单及订阅的原始 ID 标识行，刷新不重复。项目表格铺满当前面板并在窄屏局部滚动，日志长服务标识在列表中限两行并提供完整悬停值。组织操作时间按北京时间显示。
- 图片生成、视频生成、语音识别和模型对比使用 Semi 操作控件、参数弹窗与输入框。窄屏时对比列在当前面板内横向滚动，保留同步输入、独立参数和会话权限。
- 组织及成员、批量添加和 API Key 使用 Semi 表格、筛选、表单及浮层。批量添加保留校验和结果步骤，明文 Key 仅在创建或重置成功时交接。
- 统计分类匹配实际模型类型，基础模型筛选纳入其服务商服务调用；请求保留发送时调用 ID，未知计量不填零，音频秒数/字符与 Token 分开。不使用固定样例数作为当前套餐权益或剩余额度。
- 动态历史样例只绑定固定初始资源且保留有效归属，不能因新增/编辑 Key、模型或成员而重分配历史；用户真实动作产生的请求独立保留。重复 Request ID 校验 Key、客户、模型及服务归属，冲突不返回原记录，已撤权 Key 不能重放成功。

## 前台项目管理

- 账号是登录身份，客户/租户是资源和结算主体，空间是进入该主体的控制台视图，项目固定归属一个空间。组织部门和企业成员属于企业空间；项目只引用本企业的部门及成员。同一账号可加入多个企业，也可拥有一个个人空间。多空间从账号菜单切换，单空间不显示切换入口。
- 企业侧栏依次为顶部独立入口（空间总览、模型广场，不显示公共入口标题）、模型使用、订购与费用、管理设置。当前项目选择器只放在模型使用区，四类体验、智能路由、API 密钥及用量观测随项目变化；顶部独立入口、订购与费用、管理列表保持空间范围。模型体验及用量观测保留独立原入口。保留现有导航字号、图标、留白和选中样式。个人隐藏项目选择器，自动使用唯一默认项目。
- 个人侧栏顶部独立入口为概览、模型广场；模型使用含四类体验、智能路由、API 密钥及用量观测；订购与费用含模型订购、订购与账单，最后为使用设置。没有企业管理和项目生命周期入口。企业普通成员可查看授权项目及只读组织目录，密钥维护需项目管理权；订购与费用、企业操作记录仅空间管理员可见，服务端不向普通成员返回企业组织审计或可邀请账号目录。个人固定唯一默认项目的前后台写入约束继续有效。
- 文本、图片、视频、语音体验以及用量统计、调用观测、调用日志均为独立页面入口；组织及成员与操作记录、模型订购与订购及账单分别进入，不再额外合并为页签。保留页面原有业务分类页签；模型订购的按Token用量计费、Token Plan订阅、Coding Plan订阅页签仅将展示名称改为「按量计费」「套餐订阅」「资源包」，内部计费标识、订单记录及过滤逻辑保持不变。账号认证、空间切换和退出登录统一从右上角账号菜单进入；模型广场、模型详情和模型订购页面不再显示独立账号/退出广场状态条。
- 私有化站点可在「平台管理 → 站点配置」选择「企业内用」或「工厂外营」。内用提供本企业空间及授权模型，后台入口为「本企业」，前台按项目使用模型。工厂外营开放多个政企客户及个人客户，政企开户容量与部署方式分别校验。企业内外共用组织与项目权限，部门用于项目归属及成员查找。
- 工厂工作区由企业管理员或个人客户本人按当前空间订购有效按量服务。企业订购生效后在本空间项目分配相应模型；个人默认项目直接继承已开通模型。订单归属空间，调用费用按请求归属项目，通过前后台同一组记录查询订单及用量账单。企业内用在后台按调用时项目主责部门归集成本。
- 个人注册及后台开户原子创建一个默认项目并记录 defaultProjectId，前台命令和后台事务均拒绝增加、替换、重命名、转移或独立改变默认项目状态。历史单项目记录保留原始名称及 ID，以「默认项目」显示；异常记录明确报错，不自动合并或删除。企业管理员可新建并管理本企业项目，「组织及成员」可授予员工创建项目权限。创建人获得项目管理员角色，可从本企业有效成员中添加项目成员、变更角色和移除。项目管理员退出或被移除前须保留另一位有效项目管理员。普通项目成员可使用已分配项目；个人项目由本人管理。
- 项目管理可进入项目概览及设置；独立模型体验、API Key 和模型观测入口按当前项目使用。项目设置包含成员、模型权限、预算与日志、项目分流。个人使用设置省略成员，模型范围不可独立开关。企业项目设置支持编辑资料、主责部门、停用、启用和删除。停用或删除拒绝新调用，删除后保留原始项目 ID、调用、Key 关联和审计。退出仅撤销本人的项目成员关系。
- 企业新项目逐个开通模型。已有项目缺少项目级配置时继承当前空间授权。项目管理员在空间授权范围内开通模型和配置每模型 RPM／TPM，限制跨项目内全部 Key 与在线体验。空间撤权即时阻断项目调用。项目路由按规则匹配或选择默认模型，备用模型也需通过项目与 Key 权限检查。
- 项目累计人民币预算支持设置预警百分比和超限停止按量调用。按量 Key 支持独立累计人民币预算，Token Plan Key 支持独立套餐抵扣 Token 预算。所有手工 Key 可设置到期时间。未确认费用单列；无法核算受硬预算约束的新调用时返回错误。套餐购买费用归订购空间。
- Key 在指定项目创建、编辑、启用、停用、重置和删除。用户控制台「API 密钥 → 订阅套餐」按项目 ID 与订阅 ID 独立管理每份订阅的密钥，同名套餐不合并；模型选项取项目和本套餐允许范围的交集。编辑、重置、删除不得改变其他订阅的密钥，不得把已有密钥转入另一订阅或按量范围。创建与重置的密钥只在一次性交接弹窗显示，关闭即清除。列表显示掩码，历史和操作记录保留稳定 Key ID。托管体验 Key 按项目自动使用，隐藏明文和维护操作。
- 模型广场详情点「在线体验」先校验当前空间订购或授权，再使用当前可访问项目；唯一项目自动进入，多项目未选择时弹窗选择。企业空间未订购时管理员可订购，普通成员提示联系企业管理员；内用缺少授权提示管理员。项目未分配模型时项目管理员进入项目设置授权，普通成员提示联系项目管理员。个人绑定默认项目。模型详情、文本、图片、视频、语音及模型对比发送时绑定项目。配置、调用资格、订单及会话由各自写入边界校验。留存开关默认仅保存日志元数据，开启后新请求可保存脱敏输入输出，仅项目管理员查看，CSV 不含正文。对话历史沿用账号访问规则。
- 概览按北京时间展示请求数、Token、费用和成功率及上期同进度对比。单日按 10 分钟、多日按天显示请求与费用趋势；模型与 API Key 按调用费用或请求数展示 Top 5。配置摘要直达预算、模型权限、项目分流及 Key；用量、日志及请求详情保留项目范围。

## 前台用量统计

- 入口为「空间总览」和「当前项目 → 调用观测 → 用量统计」，默认打开「概览」。空间总览汇总当前可见项目，项目入口的热力图、用量分析及导出使用同一项目范围。顶部提供语言、多模态理解、视觉、语音、向量、排序六类模型页签。概览在筛选上方展示近 365 个北京时间自然日的 Token 用量活动。按日每格一天，按周每格一周（周一为起点，首尾按区间截取），累计每格为从区间起点至当天的累计。零值和无计量分别标识。
- 下方「用量分析」首层显示时间、计费方式和项目，筛选仅影响用量分析区。「更多筛选」的调用方组包括 API Key 和调用用户，模型页签增加模型范围组。已选条件持续显示实际日期和生效的细筛条件。项目和计费方式约束 Key，项目、计费方式及 Key 约束已记录的调用用户。政企管理员可筛选调用用户，未记录调用人归入「未识别用户」。变更上级条件会清除失效的下级条件，切换日期保留查询对象。保存视图保留页签和有效筛选。
- 概览指标包括调用次数、调用模型数、调用成功次数及成功率、调用失败次数、已计量 Token、平均每次 Token 和调用费用。桌面宽度允许时排成一行，数量达到 1 万或 1 亿时按对应中文单位缩写，悬停显示原值。Token Plan 显示已记录的套餐抵扣。平均每次 Token 仅以有 Token 计量的调用为分母。订购模型数取当前空间有效订单中关联的模型，按模型去重，说明中展示模型类别分布。
- 概览的用量分析并列展示 Token 构成和已订购模型用量占比，下一行展示单模型用量趋势。模型占比及趋势只统计当前有效订购模型在所选范围的已计量 Token，前五单列、其余合并。趋势单日按小时、多日按天，自定义日期最多 31 天。
- 概览底部展示模型、项目、API Key 三个榜单。三榜共用排序指标，默认按调用次数排序，费用按同一币种比较，各用量榜仅统计有相应计量的调用。切换排序只更新榜单。点模型进入对应页签并选中该模型，点项目或 Key 在概览收窄范围。类别未知的调用仍计入概览调用次数。
- 模型页签保留汇总条、双列趋势和右侧图表导航。选定模型 ID 后展示适用的 Token 构成，采集到上游缓存命中量时展示 Prompt 缓存分析。命中率以同一批请求的输入 Token 为分母，命中 Token 计入输入。语言和多模态理解统计输入、输出及适用的缓存分项，向量和排序只展示有计量的输入 Token。视觉分开显示图片张数、视频时长及已计量 Token，语音识别时长与合成字符数分别统计。
- 年度活动和用量分析复用同一请求去重和 Token 计量规则，分别按各自范围统计。用量分析基础时间桶为北京时间单日 10 分钟、多日按天，含今日时统计至快照时间。CSV 导出当前页签的筛选范围，概览导出按各模型的实际类别标记。仅在本地开发链接 `?page=usage-statistics&usageDemo=1` 使用独立模拟请求。

## 模型运营云端持久化

- `listing`、`providers`、`model-market`、`model-costs`、`model-prices`、`model-templates`、`tariff-dictionary` 使用 `/api/5120/`。模型资料、服务商、密钥组/池、渠道及映射、采购/售价历史、服务、路由、检测与试调用、发布和操作审计均落 D1；筛选和未提交输入保留在浏览器。
- 后端以 HttpOnly 会话确认账号及权限，复用 5.12.0 领域规则；前端提交预期修订和操作 ID。业务变更、模拟状态、回执和审计一次原子保存，成功后才关闭编辑；失败保留输入，未知提交结果先核对原操作，冲突要求载入最新数据。断网不回退为本地保存成功。
- 新 D1 初始化计费字典和参考模型主档。平台管理员在研发说明中显式导入两套模型服务演示案例及其依赖，成功后保持下架。已有工作区启动时读取原数据，导入复用同一主档，记录冲突时整包拒绝。
- 私有化发布的客户身份、渠道订单、项目 Key 和各在线体验的项目调用由 D1 校验及保存。项目配置与统计按「前台项目管理」执行。原型调用使用模拟上游。

## 导航与共享页面

- 后台顶栏控件、导航、面包屑、模块页签采用 Semi Design 原生组件。登录保留账号、密码与原认证流程，错误信息紧邻表单；窄屏可使用导航弹窗，短窗口允许滚动。
- 桌面后台侧栏默认展开，可用底部按钮收起为图标栏。收起时保留当前菜单高亮、菜单名称提示与运营／运维切换。展开和收起不改变当前页面或输入，切换后台页面时保留侧栏状态。
- 旧后台通用样式只应用于标记为旧版的页面内容和对应弹层，外壳、新版 Semi 页面及前台保持各自样式。后续页面迁移完成时移除该页面的旧样式标记。
- 后台 2 运营分析为用量数据、用户数据两个同级入口；运营和系统管理员可访问，运维不可访问。运维入口称调用数据，保留 `call-analysis` 路由。模型运营依次为渠道管理、模型服务（默认入口）、模型广场、模型售价、模型资料。面包屑中的「模型运营」仅为分组文本，不链接到同级的模型服务；具体页面的父路径仍保留筛选与分页。 各子功能入口在页头标题下展示一条职责说明。模型资料按模型、计费项、计费单位、货币排列，维护模型主档和共用字典；模型售价的“计量配置”进入字典页面，切换字典页签保留来源返回路径，面包屑统一归属模型资料。
- 不提供独立 `service-routing` 页面；路由在模型工作区“路由及映射”维护，领域事务、历史配置和数据保留。概览为运营默认首页，不恢复旧独立工作台或安全治理模块。
- 运营导航底部的入门指导分组保留“模型运营”指南（`getting-started`），运维不可访问；接入和维护流程就近提供帮助，不强制先读教程，不因首次登录强制新建。渠道管理不恢复旧使用引导弹窗。
- 后台面包屑由 `breadcrumbs.mjs` 生成。一级分组链接到该分组默认入口，「模型运营」打开「模型服务」。详情页的上一级链接保留列表筛选和分页，当前项显示为文本。模型详情显示所选模型，点击「模型服务」退出详情并保留目录筛选。向导为「模型运营 → 接入并上架模型」，返回注明来源。任务跳转保留模型、页签、筛选及当前输入，缺失对象不静默替换。普通详情不重复返回按钮。独立订购页返回当前版本订购入口。
- 租户空间、账号认证、调用日志、API Key、客户与后台账号沿用[对应共享页面章节](../../docs/PAGE-SPEC.md)；用户管理、账号管理、Token 生产等模块的保留与入口以本版本规格为准。前台隐藏模型排行，组织及成员、组织操作记录仅在企业空间提供。个人空间从项目详情查看该项目的调用日志。

## 私有化站点配置

- 「平台管理 → License 管理」显示部署规格、状态、有效期及功能范围。内用版隐藏商业运营分组并拒绝商业路由和写入。商业版到期后保留历史查看，写入端拒绝新增订单、开售、售价与销售对象变更及套餐命令。已有订单以原调用权限核验。绑定 License 后，站点配置不显示运营方式切换。
- 商业运营包含「模型销售」「客户管理」「订购与账单」「套餐管理」「经营分析」。售价维持统一服务按模型、渠道直选按服务的现有定价方式。经营分析按账期汇总后台已记账的出账与实收金额。

- 私有化构建通过 `VITE_MOMA_PRIVATE_SITE=1` 开启「平台管理 → 站点配置」，仅平台管理员可访问。公开部署的常规构建默认关闭。
- 「基础配置」维护后台与用户控制台顶栏的共用 Logo、平台名称、浏览器标题和 Favicon，以及登录与企业认证共用的品牌插图。平台名称同步到登录品牌区及已有的认证页品牌页脚。图片支持本地上传（单张 512 KB）、HTTP/HTTPS 链接、预览和恢复默认。
- 「协议管理」通过「用户协议」「隐私政策」切换文档，每次展示一个宽版编辑区，支持正文、HTTP/HTTPS 外部链接、草稿预览和分别恢复默认。两份协议通过「保存协议」一起发布。每份协议有可复制、无需登录的站点地址，认证及邀请沿用同一地址。公开阅读只读取已保存的服务端配置，未配置正文或链接时读取对应内置模板。
- 基础配置使用版本专属的浏览器本地存储。协议发布由系统管理员经同源接口写入原型数据存储，比较修订号，保存失败保留草稿。首次发布前可在编辑器带入当前浏览器已有的自定义协议，保存后对外生效。两类配置都以站点为范围。

## 平台审计日志

- 「平台管理 → 审计日志」仅向系统管理员开放。列表和详情使用当前后台账号的服务端会话，未登录回统一登录入口，通过角色校验后返回原页。通过 `/api/5120/audit-logs` 读取已有 D1 审计事件，覆盖发布服务路由、轮换共享密钥和批量停用所选模型渠道供给。
- 页面使用 Semi Design。列表展示北京时间、操作人、模块、动作、对象与结果，按时间与事件 ID 倒序，按游标前后翻页。默认近 7 天，支持时间、动作、结果、对象或记录 ID 搜索，以及按操作人和对象类型筛选。自定义日期按北京时间查询。
- 点击动作打开右侧详情抽屉。详情展示操作 ID、配置提交结果、前后值、目标与关联对象。发布路由记录生效配置版本，轮换记录共享组版本和首位密钥 ID，批量停用按供给关联展示逐项结果。密钥明文、掩码、指纹、完整配置、内部地址和请求体排除在返回字段外。
- 新事件在同一业务事务的已有 D1 审计行保存字段摘要。旧记录只展示能从历史证据确认的对象、动作和结果，缺失显示「未记录」。配置提交属于原型证据，网关实际生效须由独立执行回执确认。

## 流量运营

- 限流配置页使用 Semi Design 卡片、页签、表格、表单、弹窗、抽屉和反馈组件。运营区「流量运营」下提供「用户限流」「模型限流」两个页签，默认进入用户限流。平台管理员和运营人员可访问。
- 用户列表显示账号名称、账号 ID、账号类型、默认值、生效值、规则来源、一客一策条数和操作。默认值取用户全局默认，生效值取账号通用额度。两个值均包含 RPM 和 TPM。支持按账号名称或 ID 搜索，以及按账号类型筛选。通用额度可单独或批量修改、恢复全局默认，已有一客一策仍按模型匹配。筛选、切换页签和批量操作成功时清空选择。
- 全局默认在 D1 初始化为 60 请求/分钟和 300 万 Tokens/分钟，放在用户列表搜索行，Tooltip 说明继承规则。新账号和没有自定义通用额度的账号使用当前值。
- 点击账号行的一客一策条数打开右侧宽抽屉，显示账号名称和 ID，支持搜索并添加模型、修改额度和移除，统一保存。一个账号的同一模型只能配置一条额度。账号规则优先级依次为一客一策、账号自定义、全局默认。
- 账号行的「限流可视化」打开只读宽抽屉，展示通用额度以及各模型的账号侧额度、命中规则、模型共享上限和最终上限。RPM 和 TPM 分别取两侧较小的值，账号侧额度无法读取时最终上限显示「—」。
- RPM 使用请求/分钟。TPM 固定以百万 Tokens/分钟展示和输入，最多 6 位小数。组合额度在数值旁直接标注 RPM 和百万 TPM。保存时 RPM、TPM 均为正整数。
- 模型限流搜索行沿用用户限流布局，右侧维护「模型默认」，D1 初始值为 600 请求/分钟和 3,000 万 Tokens/分钟。列表展示 D1 模型资料主档的名称、标识、默认值、生效值和规则来源。模型共享上限按主档关联，由调用该模型的账号共用。单模型可覆盖默认或恢复为继承当前默认。
- 页头「变更历史」打开只读抽屉，按时间倒序展示变更时间（北京时间）、变更对象、操作、变更前、变更后和操作人。D1 记录两类默认、账号通用额度、一客一策及单模型覆盖。批量操作按实际改动的账号列出，一客一策按模型列出增改删，恢复默认显示继承关系。旧审计缺失的字段显示「未记录」。
- 两个页签使用同一个后台登录会话读写 D1 限流配置。用户列表复用用户管理的账号 ID，模型关联复用 D1 资料主档 ID。读取失败提示登录或重试，缺失额度显示「—」。保存同时提交配置与审计，校验角色、修订号与幂等标识，失败保留输入。浏览器旧存档保留，当前生效配置以 D1 为准。当前原型范围为配置及规则解析。

## 套餐制作

- 套餐制作和套餐数据复用后台 Semi 页头、卡片、筛选和小尺寸表格。套餐制作包含「套餐列表」和「模型抵扣系数」两个页签，默认进入套餐列表。套餐在独立表单编辑，右侧为购买页预览。抵扣规则按模型分组，在弹窗编辑。离开未保存的表单时可继续编辑或放弃本次修改。
- 运营区「套餐运营」下提供「套餐制作」，平台管理员和运营人员可访问。列表以名称或套餐编号搜索，按套餐形式和状态筛选，统一分页。套餐形式为按周期订阅或一次性资源包，首次保存后只读。套餐类型可选个人版、团队版或平台管理员添加的共享类型。新建、编辑和查看为独立表单，返回保留筛选和页码，离开时保护未保存输入。
- 订阅套餐配置每周期 Token 额度、周期售价、订阅周期、总周期数和余量结转规则。资源包配置每份 Token 总额度、单价和生效后的有效天数。两类共用套餐名称、购买页展示名称、简介、顺序及每位用户累计限购份数。支持订购的用户类型可多选政企用户、个人用户，新建默认全选，发布和上架至少选一项。展示顺序可填 0 至 200 的整数，数值越小越靠前，留空排在最后。购买页预览在大号套餐名称下方显示一行简介，并展示有效期限。
- 按月、季度、年订阅分别按原生效日期加 1、3、12 个日历月推算周期边界，目标月缺少对应日期时取月末，后续仍以原生效日推算。当前套餐制作展示规则，实际订购到期时间由权益系统计算。
- 状态为草稿、待上架、已上架、已下架。新增和编辑表单的「保存」将套餐存为草稿，允许缺少发布必填项。发布从列表发起，校验通过后进入待上架，操作为编辑和上架。仅从未发布的草稿可在列表确认删除，移除后保留审计且编号不复用。上架与下架需确认。已上架套餐只读，修改下架或待上架套餐后需重新发布。下架只停止新订购，已购权益用尽或到期后结束。
- 平台管理员可删除未被套餐引用的自定义类型，删除需确认。内置类型和被任意状态套餐引用的类型不可删除，删除成功后从选项中移除并保留审计。
- 「模型抵扣系数」列表展示已添加的模型，新增选项来自「模型服务」中尚未添加的未归档模型。每个模型默认不允许加入套餐。平台管理员和运营人员可配置「允许加入套餐」、全平台共用的抵扣规则和修改说明。添加及编辑只保存草稿，发布后切换生效版本，待发布期间继续使用当前生效规则。修改历史记录发布版本、时间、操作人、变更前后规则和修改说明。
- 先选择模型，再按该模型当前生效售价中的计费项分别配置抵扣规则。没有生效计费项时提示先配置并发布模型售价。留空的计费项不生成规则，新增模型至少配置一条。切换模型时保护未保存输入。保存和发布均校验计费项归属，已有生效规则保留至新版本发布。规则使用模型主档 ID。同一计费项可不分档，或配置互不重叠的输入 Token 档位。下限不含、上限含，允许留空一端。下限留空从 0 开始，上限留空代表无上限。按单次请求的输入 Token 数判档，整笔使用命中系数。各计费项的实际用量乘以对应系数，再相加得到套餐扣减额度。系数须大于 0、最多两位小数。
- 套餐制作的「支持模型」支持搜索和多选已发布、允许加入套餐且有生效规则的模型。选中后展示当前计费项、档位和系数，套餐只保存模型关联。暂无可选模型时提供模型抵扣系数页签入口。发布和上架至少选一个符合条件的模型。模型仍被套餐引用时，发布规则须保留允许状态和至少一条规则，服务不可归档。被草稿或生效规则引用的计费项不可删除。原模型级系数作为历史值保留。
- 使用说明和使用范围是独立的可选文本，各最多 500 字符。套餐配置、共享类型、操作回执及审计通过 5.12.0 的 D1 接口保存。原浏览器套餐记录保留在原存档。

## 套餐数据

- 运营区「套餐运营」下的「套餐数据」提供一张套餐汇总表。默认全部套餐，支持筛选订阅套餐或资源包。每款套餐一行，依次展示套餐名称、资费ID、新增销售数、累计到期数、额度消耗率（平均值）。资费ID使用现有套餐编号。新增销售数统计所选期间售出的份数，累计到期数统计截至结束日已到期的份数。额度消耗率对当前范围内明细所列且截至结束日已生效的权益，逐份计算累计消耗量除以套餐额度，再取算术平均。无可计算权益显示「—」。已下架套餐仍可查看。筛选沿用[运营时间与事实](#运营时间与事实)的北京时间口径。
- 点击套餐名称进入单款套餐详情，沿用概览时间范围。权益表每份已购权益一行，展示订购时间、套餐 ID、用户 ID、账号名、账号类型、套餐档位、套餐额度、有效期至、状态、已消耗 Tokens、剩余额度和累计成本。套餐 ID 下显示权益编号，同一订单购买多份时分别展示；账号类型支持筛选政企用户和个人用户。演示表纳入期内购买或期内有效的权益。额度以 Tokens 展示，已消耗为按系数扣减的额度；消耗、剩余、状态和累计成本均截至统计结束日，成本缺失显示「待核算」。返回概览保留筛选和列表位置。
- 套餐列表读取 D1，缺失的真实经营数据和权益明细显示「待接入」。独立演示视图按北京时间映射样例日期，超出覆盖范围显示「无演示数据」。演示统计与 D1 套餐及用户侧订购、扣减和权益分开。

## 模型身份与资料

- 术语由 [GLOSSARY](GLOSSARY.md)定义：模型资料、供应关系和销售服务各有职责，资料 ID/模型编码/上游模型调用标识/模型调用标识 不混用，模型作者不等于服务商；采购参考价、采购价和平台售价分开。完整 URL 称请求地址，Key 按当前绑定渠道表达。
- 模型资料提供参考内容，最终展示信息由模型广场维护。按稳定 ID、显式关联或精确编码识别模型，不按名称近似合并版本。四模块的永久 ID 展示、字段归属及批量导入导出遵守[身份与导入契约](MODEL_OPERATIONS_IDENTITIES.md)，复用存量 ID，不改写已有引用。

## 渠道管理

服务商列表操作只保留编辑与删除，删除流程及风险确认统一使用「删除」文案，保留原两步关联检查、软归档和历史保护；服务商名称继续作为详情入口。服务商详情及其 JSON 页不提供「批量维护」，渠道表原有批量操作保持；模型渠道的单条、批量删除入口统一称「删除模型渠道」，沿用关联检查、停服下架与风险确认，不物理删除模型资料和历史。API 密钥池原「检测」操作称「测试连接」，校验行为保持。渠道名称支持预设选择及输入自定义值，输入新值后提供明确的「添加自定义渠道名称」操作。渠道 JSON 读取当前保存状态，独立汇总服务商、模型登记、连接与模型渠道数量；已删除渠道不进入当前渠道行，仍保留的模型登记照常导出，不把登记数当作有效渠道数。

模型渠道行的原「配置」入口统一称「编辑」，沿用同一编辑抽屉与保存/验证校验。新增渠道的「模型」选项使用名称与模型编码组合展示（名称 · 编码），选择仍按稳定模型 ID 定位并联动模型编码，不合并存储。渠道名称可选择官方、自营、转售或输入自定义名称；新建默认自营，切换模型不覆盖手工名称；编辑沿用存量名称，连接名称字段仍独立。容量表下方的「添加容量指标」打开复选弹窗，可一次选择多项后「添加所选项」；已添加指标勾选禁选，取消不修改容量草稿，添加保留已有数值；RPM/TPM、单位转换、保存校验、修订冲突和取消保护不变。

服务商总表将「服务商」和「服务商编码」拆成独立两列，服务商 ID 不在列表显示；名称下钻、编码复制和按 ID／名称／编码搜索保留，永久 ID 的存储、关联、详情与 JSON 查询不变。模型总表及服务商下钻的模型渠道、待配置模型、已登记模型抽屉和模型详情供应服务商表，继续按原有方式合并名称与编码展示；模型表头为「模型」，名称在上、编码在下，保留编码复制、详情、分组及其他永久 ID 列。

渠道管理页（「服务商视图」「模型视图」双视图）、模型渠道表、API 密钥池、接入新模型/新渠道表单、渠道编辑抽屉、密钥池与凭证候选编辑及接入记录续配使用 Semi Design 原生组件和默认样式。保留默认配色、字体、字号、圆角、表单和表格密度，仅设置布局、间距和响应式规则；旧后台样式不覆盖该区域及其弹层。表格合并单元格、脱敏、候选测试与应用等行为按本章既有条款保持。

渠道管理的服务商总表页头仅提供「录入服务商」，不提供「创建渠道」。新渠道从服务商详情的「新增接入」维护。录入使用 1280px 宽抽屉，小屏不超出视口，仅保留表单，不提供 JSON 导入或模式页签。API 密钥输入占位提示 sk-xxx，此提示不限制其他服务商密钥前缀。服务商图标显示 PNG、JPEG、WebP 且不超过 512 KB 的格式要求，URL 输入提示 http:// 或 https://；既有格式、大小与地址校验保持。表单包含服务商名称、服务商编码、供给类型、多个 Base URL、多个 API 密钥、服务商图标、官网和 300 字描述。名称、编码和供给类型必填，供给类型为第三方推理服务或自有推理服务；编码创建后不可修改。地址逐条添加，作为待配置渠道地址保存；密钥逐条添加，最多 20 条；明确选择默认 API 密钥组或新建命名密钥组，本次密钥按输入顺序加入所选组。默认组与命名组、密钥 ID 及优先级和服务商 API 密钥池同源；后续分组、排序、轮换仍在密钥池维护。只提交并持久化掩码与指纹。图标支持上传 PNG、JPEG、WebP 或填写 URL，最大 512 KB。主体、地址及密钥一次原子保存，失败保留输入。服务商列表增加供给类型，地址与密钥数量读取同一渠道地址和密钥池；官网和描述在资料详情查看及编辑。供应模型在服务商详情另行登记或批量导入；新地址保持待验证，不自动启用或上架。同编码服务商移除后可重新录入，沿用主体稳定 ID，旧渠道及价格版本保留归档，新渠道须重新验证，不自动恢复旧服务。

服务商和单条模型渠道均使用两步移除弹窗。第一步仅检查关联，列出受影响的模型服务、调用标识、渠道、启用和正式/灰度上架状态；点击「停服并下架受影响渠道」后才实际停用所选渠道服务并下架。统一服务的剩余路由通过校验且已发布配置重新验证后可继续服务，否则停服并下架；其他渠道不受影响。活动及草稿路由退出目标渠道，旧版本和失效草稿保留历史。未完成检测、接入任务或仍有网关路由/故障转移引用时阻止下一步，并说明需处理对象。第一步已执行的停服、下架不会因取消移除而自动恢复。

- 模型服务和渠道管理共用「API 密钥来源」控件，可选「服务商密钥池」或「渠道专属密钥」。使用服务商密钥池时，通过「API 密钥组」选择分组，并可在服务商详情的「API 密钥池」中管理。添加与编辑渠道共用这些接入字段。渠道维护模型、名称、上游标识、协议、地址与凭证。采购成本在渠道管理的模型总表按模型、服务商和渠道维护。新增可无成本，不生成零价；旧成本与历史原样保留。共享密钥新增、独立密钥留空保留、取消及失败输入保护继续有效；地址／凭证变化原子保存候选，测试后明确应用，不覆盖有效连接或已有候选。明文不进入存档、审计或产物。
- 添加渠道只选择当前服务商已有模型。表单直接填写渠道名称、上游模型调用标识、上游协议、上游 API 地址和 API 密钥来源。上游协议下拉按顺序提供「OpenAI 兼容 API（Chat Completions）」「OpenAI 兼容 API（Responses）」「Anthropic Messages API」。两种 OpenAI 接口分别保存类型，并使用各自路径、请求字段及响应解析。非对话模型沿用对应 OpenAI 任务接口；已保存的任务端点和业务数据保留。标准接口填写服务根地址。密钥可选服务商密钥池的分组或渠道专属密钥，提交的密钥字段只含掩码和指纹。渠道和关联一次原子保存。测试、启用、创建服务和上架各有独立入口。成本独立配置，缺失不等于零。
- 渠道保存不自动测试；明确测试后按有效证据和固定影响范围启用技术供给。技术资格与客户可用分别判断；首次任务最终提交、备用准备及日常应用遵守各自目标，不因“下一步”隐式变更共享资源。已知接口不兼容阻断，未知路径不误判，未保存配置不复用旧证据。
- 首次上架向导继续使用其接入表单和原子保存；服务商详情仍分别登记模型和添加渠道。可用性及最近测试来自现有渠道证据，不新增持续探测或实时遥测。
- 请求地址使用完整 HTTP/HTTPS URL，保留当前第三方 HTTPS/自有 HTTP(S)、禁止嵌入凭证及不允许的查询/片段校验；不将裸域名或基础 `/v1` 冒充模型接口，不重复拼接路径。已配置的多协议地址保持独立测试结果，次协议通过不能替代主地址健康。
- 相同接口、凭证与上游 ID 不能靠不同名称/来源标签重复创建。旧无 ID 关联稳定读取，不回填/丢弃记录；编辑某渠道不能误删其他渠道。调用配置变化使相关验证失效，单纯名称/成本变更不误清验证；共享影响须确认。
- 模型视图及渠道模型明细按真实映射展示计费项；服务商模型及渠道表展示各模型渠道的当前有效刊例价；能力声明通过“配置”中的当前模型配置维护。金额保留零值、缺失、单位、币种和条件；地址可查看完整值。行操作与对应对象明确关联，关联状态来自精确供应映射，不把健康状态当关联。
- 停用、删除或解除先检查服务及已发布路由引用，提示真实影响；全局停用与当前路由摘除分开。保存渠道不自动改服务映射、售价、路由或上架。旧报价、密钥、价格历史和审计保留。
- 默认样例与官方参考资料不证明真实供应关系、可用性或价格。已有记录不为凑数量重置；显式加载参考目录只补缺失记录，保留自定义资料与已关联模型。一次性案例删除/修改后不自动复活，历史本地授权不能再次用于改写用户浏览器。

## 密钥与维护

- 密钥库与租户 API Key 独立。只保存掩码、SHA-256 去重指纹及引用元数据，明文不进入草稿、存储、审计、日志或产物；不宣称已接服务端凭证库。
- 产品继续使用 API 密钥，不改名 API 凭证。服务商密钥页维护密钥资产和分组；渠道的密钥池维护多条绑定、启用状态和 1–100 优先级，数值小者优先，同级按列表顺序。旧专属、默认及共享组引用不自动转换；移除“设为主要”入口，已有组顺序保留。
- 渠道列表和渠道模型展示健康状态；健康与启用分开。逐渠道模型、逐密钥检测，结果展示时间、HTTP 状态、耗时和失败原因，支持确认、取消和重试。结果有效期为 24 小时；地址、模型映射、密钥版本变化要求复测；单 Key 通过不代表整个密钥池正常。检测只写诊断历史，不修改启用、映射、路由或价格；本地结果标识“模拟检测”。
- 密钥池变更走候选配置→逐条测试全部启用密钥→明确应用，校验全部必要模型及服务影响；单 Key 通过不能替代其他 Key，失败、过期、待完成及不匹配回执均不放行。未关联模型须先接入模型再验证。本批不新增自动轮询、额度调度或熔断冷却。
- 密钥按实际渠道引用聚合，长 ID 可换行；没有密钥不伪造占位记录，不把未关联旧渠道作为整个模型目录的错误。添加/替换不回显原文，沿用可见 ASCII、长度、重复和数量校验，保存只提交脱敏信息。
- 正常轮换与撤销分开：正常轮换不自动撤销旧 Key；专属渠道和共享组按实际引用范围处理，不能误改其他渠道。替换/删除等影响动作保留确认、稳定身份/关联规则及验证失效处理，相关细节见[接入规格第 23 节](MODEL_ONBOARDING_SPEC.md#23-目录外接入与日常维护简化2026-10-31)。
- 渠道配置只选择服务商密钥组并显示可用数量、主要密钥脱敏值及状态。「管理密钥池」进入服务商 API 密钥池并定位所选组，离开前沿用未保存保护，已有渠道可返回配置。渠道专属密钥随渠道提交。渠道配置与测试不再内联添加共享密钥。测试切换密钥组仅作用本次检查，明确修改渠道配置才持久化；测试结果单一呈现，接口不匹配优先于旧通过记录。测试/调用明确提示用量确认，保留取消、重试和失败恢复。
- 地址和 Key 维护先保存候选并测试，通过后仍需明确应用；失败保留当前配置。历史恢复入口共用固定范围和有效性校验，不保留绕过检查的旧结果直达路径；不因测试成功自动启用、改路由或上架。
- 成功、超时等模拟场景选择只在地址参数 `devtools=1` 的研发视图显示，普通业务页面隐藏；测试结果保留实际来源，不将本地 Mock 记为真实上游证据。

- 模型服务列表操作列及服务操作菜单提供「删除」。确认前检查启停、上架、路由、草稿、映射和未完成任务，存在订单、调用或套餐引用时拒绝删除并提示归档或先处理引用。删除后移出服务目录，保留模型资料、渠道、价格、路由及审计历史；再次添加同一模型复用稳定 ID，并重新选择服务模式，旧价格与路由不自动生效。

## 模型服务与调用路由

- 模型服务演示包提供 GLM-5.3（渠道直选模式）和 DeepSeek-V4-Flash-0731（统一模型服务模式）。导入后从模型服务目录查看案例，历史工作区继续读取已有案例及用户新增资源。检测和平台试调用结果显示实际证据来源，模拟结果标明「模拟检测」或「模拟试调用」。
- 模型服务采用对象清单与内联工作区，包含接入中、已启动及已停止的服务。稳定关联避免任务和服务重复显示为两款模型。保留名称/ID、类型/模式/服务状态筛选；不提供「查看归档」和「批量维护」入口，已有归档记录不清除。
- 「新增模型服务」打开「批量新增模型服务」弹窗，通过可搜索多选下拉选择渠道管理中已登记的模型，按主档稳定 ID 去重，每批最多 5 个；已创建服务或名称冲突的项不可选。名称及类型直接读取所选模型，不提供名称输入或类型选择。本批共用一种服务模式，只提交模型主档 ID 与模式，服务端重新核对登记、重复和权限，原子创建。单个创建后进入路由及映射，多个创建后返回模型服务列表。失败保留选择及模式，取消保留未保存保护；不自动关联渠道、启用或上架。
- 后台模型广场以稳定模型资料 ID 聚合卡片，默认列表，支持卡片视图、搜索、类型和展示状态筛选、分页及序号调整。查询、筛选和视图保存在 URL。基础列为模型、类型、关联服务、可见范围和展示状态。已有服务的展示卡片保留原序号和内容。更多操作保留模型 JSON 与服务商、渠道详情。
- 可从已登记模型新建未上架卡片。模型身份、编码和类型只读，同一模型只建一张卡片。展示名、简介及图标独立维护。保存后可以关联同一模型的既有服务；关联按模型服务永久 ID 保存。解除正在展示的关联前，须先从展示清单移除。
- 上架与调整上架选择已启动的关联服务并确认可见范围。范围可选全部用户或指定组织、项目。商业版还可配置指定客户。命中任一范围即可查看。组织覆盖本级及下级部门；项目范围要求当前成员具有项目访问权，并选中该项目。卡片下架只隐藏广场展示。商业版在「商业运营 → 模型销售」配置售价、共享销售对象并办理开售、灰度开售和停售。停售暂停新订购，已有订单和调用沿用原服务权限。D1 广场按已验证成员身份投影可见内容。
- 服务工作区默认打开「路由及映射」，其后为「故障转移」「操作记录」。页头在模型名下显示「已启动」或「已停止」。渠道直选有至少一个已启动的模型调用标识时，页头显示「已启动」，各渠道行显示对应标识的服务状态。售价／销售入口带稳定服务 ID 跳入模型售价。跨页保留来源对象、页签与筛选；任务入口定位现有资源，缺失对象明确报错，未保存输入有离开保护。
- 模型服务详情不提供「查看模型资料」入口，模型资料仍在独立资料库维护。成本和售价入口在路由操作菜单中，分别定位当前模型和渠道服务。服务调用继续校验客户状态、既有客户范围、授权和密钥权限。
- 每个模型只有一种服务模式：`standard` 为统一模型服务模式，模型级统一售价；`provider` 为渠道直选模式，每个渠道服务独立维护模型调用标识、售价、路由和上架阶段，可与同服务商的其他来源复用连接。采购价在渠道管理的模型总表维护，平台售价在模型售价维护。
- 统一模型服务模式沿用服务的模型调用标识，可在路由及映射中维护。渠道直选模式在关联渠道后设置各渠道服务的模型调用标识。
- 服务模式首次保存后固定。「路由及映射」使用标题字号展示「服务模式：统一模型服务模式」或「服务模式：渠道直选模式」。尚无有效模式的历史服务可首次选择，关联渠道及上架前须完成配置。服务端拒绝改写已保存的有效模式。
- 路由及映射选择已检测并启用的同款模型供给并维护调用 ID；模型售价独立编辑计费项及价格。任务间不得夹带未提交输入，不创建虚假资源、不自动参加调度；采购变更不改变已发布售价。
- 「路由及映射」在对应渠道行展示对外协议／接口路径和上游地址。渠道直选表格依次展示渠道、模型调用标识、对外协议/接口路径、路由策略、上游模型调用标识、上游接口地址、操作。路由策略按模型调用标识展示。已配置的固定策略显示「固定渠道」，从未配置时显示「尚未配置」，已停用时显示最近一次策略并标注「已停用」。同一渠道有多个已配置接口时逐项对齐。地址可复制，长地址可悬停查看全文。点「查看映射」可在详情抽屉核对转发方式。附加接口选自该渠道已配置的兼容地址，和模型映射一并核对、保存与验证。原型展示地址配置，附加接口的网关调用待实现。未被路由引用的映射可从渠道行的更多操作进入编辑。验证、启用、停用、解除及候选变更操作从对应渠道的更多操作进入。存在可用且尚未关联的供给时提供「新增映射」，统一模式的入口位于表格上方。渠道直选在表格上方仅提供「选择已有渠道」，关联当前模型已启用的渠道；统一模式通过「编辑路由」选择合格渠道。模型服务不提供新建接入入口；需先在渠道管理完成登记、配置、检测和启用，再返回关联。
- “新增映射”以 Semi 原生组件展示模型服务、服务模式和模型调用标识。统一模型服务模式可选择服务商，渠道直选模式只读显示当前服务商。按服务商筛选同一主档下已验证并启用、且没有现有或待应用映射引用的渠道模型供给。切换服务商清空已选供给及上游模型调用标识。上游模型调用标识由所选供给带出，单一适用平台接口直接显示，映射名称选填并默认使用渠道名称。
- 映射预览只展示两侧请求；服务端验证复用当前供给检测证据并核验标识、路径和协议，不发起新用量，不替代平台试调用。新增映射待验证且未启用；在用映射只改名；未引用映射的供给变更保存为候选，原有效配置持续保留，验证后明确应用或放弃。生效与草稿路由全部条目、未完成任务阻断停用／解除及目标切换；供应侧删除检查候选引用。保留旧有效关系、价格、凭证元数据和历史；不重放初始数据或无提示改写已有关系。
- 渠道直选通过「选择已有渠道」关联当前模型已有渠道，不在弹窗创建服务商。未选服务商时提示先选择；不存在当前模型渠道时明确提示未接入，已停用、未验证或已关联的渠道展示具体原因并禁选。候选按当前模型永久身份和服务商定位，保留原后端关联校验；不跨模型关联或恢复已删除渠道。缺少渠道或需要处理时可新页签打开当前服务商的渠道管理，原服务页状态保留。确认关联后保存模型调用标识，再配置渠道路由。路由编辑只选择当前模型下已有且检测启用的渠道，不提供“新增接入”或内联登记流程。供应模型登记在渠道管理维护，模型服务内的接入表单复用渠道管理的字段和校验。检测并启用后，编辑路由选择供给，经预览原子建立映射并生效。保存渠道不自动加入路由或上架。
- 灰度上架须在有效销售对象中指定客户；正式上架解除灰度限制。渠道直选模式按所选渠道检查当前采购价、售价、技术启用和验证结果。下架目标渠道立即拒绝新订单和新调用，保留其历史及技术配置。仍有已上架渠道时保留模型卡片。可见性只控制广场展示，不授予调用权限。
- 渠道成本、模型售价的列表、详情或抽屉使用 Semi Design 原生样式，表单与弹层保留权限、修订冲突和未保存保护。列表按模型展示名、服务商和成本/销售状态组合筛选，保留搜索、重置和来源返回路径；按模型主档稳定引用合并模型展示名单元格，同名不同模型不得合并。列表不分页，固定表头、局部横向和纵向滚动；成本和售价均按每条计费项展示价格、计费单位和货币，按渠道模型关联或服务合并相应单元格，缺价不显示零。
- 模型运营字段按[字段命名与归属](MODEL_OPERATIONS_FIELD_DICTIONARY.md)统一，供应商/服务提供方的界面称谓统一为服务商；模型编码、模型调用标识、上游模型调用标识分别对应主档、客户请求、上游请求，不更改协议键和用户历史记录。

## 保存、发布与恢复

- 后台不提供草稿保存、恢复或丢弃入口。编辑输入仅在当前页面保留；测试验证连接配置，不自动启用或上架。预览展示本任务差异、范围和阻塞项；明确发布或应用后才切换对应有效版本。
- 售价发布成功后立即作用于后续新请求，含已有订购客户；已开始请求及历史保留原价格快照，内部重试不换新售价。客户展示、后台及客户调用使用同一有效版本，不提供预约调价和专属协议价。
- 地址、密钥、路由、资料、售价和客户范围按相关任务独立提交；任何发布不得顺带应用其他任务输入。保存或发布失败保留当前输入和旧有效配置。
- 离开未提交页面只提供放弃本次修改／继续编辑；刷新不恢复未提交输入。历史未发布记录原样保留，不自动应用或作为新编辑的起点；报价历史可沿用后明确提交新版本。
- 超时或结果未知先核对同一操作结果再重试；冲突显示差异并保留输入，不自动覆盖。刷新恢复已保存安全内容并重查依赖，不承诺恢复未保存输入或明文 Key。
- 操作成功后持续显示真实对象、版本和生效时间，不只使用短暂通知。不可执行时说明具体缺项或权限原因，原型不伪造成功。

## 运营时间与事实

- 运营概览、用量和用户数据统一提供今日、昨日、近 7 天、近 30 天和自定义。昨日默认/重置，近 7/30 天截至昨日；自定义可选至今日、最多 365 天，禁止未来日期。北京时间今日及包含今日的范围只统计截至当前时刻的已发生事实，不补未来时段或外推全天；环比按上一等长期间的相同进度计算，用户页今日注明对比昨日同时段。图表、明细、客户下钻和导出使用同一范围；客户下钻页顶部提供同样的快捷时间、自定义范围及重置，默认继承来源日期，切换同步更新指标、模型用量和最近调用；范围写入 URL 并保留客户身份，刷新及浏览器前进后退保持一致，返回用户数据时按 URL 还原范围；保存视图恢复时重算快捷日期，自定义保留具体日期并限制至今日。月活来自明确成功登录身份事件，用户去重不能从 tenant/Key 推断；注册/构成/详情同源。租户和运维日期规则独立。
- 请求先按 requestId 取最终修订再筛选；模型/服务商/渠道来自真实关联，用户来自显式 userId、客户来自 tenantId，不能互相替代。已删除端点仍以稳定 ID 列入未归属，缺计量为待确认/断点，零值保留，非 Token 单位不相加。

模型服务列表提供实际模型调用标识、API 路径、协议与完整端点的核对和复制，不再提供后台调用示例编辑页签。

点击「模型服务」先进入列表。以一个模型服务永久 ID 为一行，渠道直选的同一模型不同服务独立显示，不再合并名称或操作。列顺序：模型服务名称 / ID、模型调用标识、API 路径、API 协议、关联的渠道、模型编码、模型服务状态、API 端点、操作（详情｜删除）。名称与永久 ID 同列，ID 不因名称或调用值变更而变化，支持完整复制及悬停查看；未关联渠道、尚未形成具体服务的配置项显示待配置，不补造服务 ID。关联渠道按实际模型映射或渠道直选关联定位，展示服务商名称（渠道名称）和完整渠道 ID，不用连接 ID 替代。渠道或端点有多项时首项加数量，点击查看全部。API 路径含方法与路径，协议逐项对应，端点为平台对外完整地址；仅展示真实开放的接口，不把上游地址或仅声明的接口当成已开放平台端点。模型服务状态为已启动／已停止，与销售上架独立。第一列和操作列固定，表格局部横向滚动；每批展示 20 条服务，计数以服务为单位，待配置项单列计数。搜索覆盖服务名、永久 ID、调用标识、模型编码及关联渠道名称/ID，筛选命中具体服务行。详情定位所选服务的路由及渠道上下文，面包屑返回恢复筛选、已展示数量和滚动位置。删除以所选模型服务永久 ID 定位，只处理该调用入口；校验启停、上架、路由/草稿、订单/调用及套餐引用，确认后移出列表，其他服务、模型资料和历史记录保留。列表、详情和 JSON 页均不提供模型服务批量维护；详情页签为路由及映射、故障转移、操作记录，不提供调用指南。

列表和详情页头均可打开「批量新增模型服务」弹窗。模型通过可搜索多选下拉选择渠道管理中已登记的模型，每批最多 5 个；触发器只显示首个标签和剩余数量，剩余项可展开查看，另显示已选数量，不因多选撑高或截断整个控件。服务模式为统一模型服务模式或渠道直选模式，各提供可悬停或键盘聚焦的说明：统一模式由平台在合格渠道间调度；渠道直选由用户指定渠道服务，在选定范围内调用。名称、类型从所选模型读取。保存后模式固定，原子创建且不自动关联渠道、启用或上架；失败保留选择，取消保留未保存保护。具体规则见本章模型服务批量创建条款。

从渠道检测或接入任务进入服务管理时，按明确的主档引用打开已有服务；若需新建，沿用该主档与类型。主档缺项时显示「维护模型资料」入口。服务端核对供应登记和重复服务，保留已有稳定 ID、资料、供应、价格和路由历史。

## 模型运营维护交互

- 模型资料基础字段默认展开，高级模态任务、能力、参数和来源分组收起；查看编辑用同一类型名称与上下文单位。编辑共享卡片前提示影响服务。
- 接入模型内联搜索多选，一次提交后可继续接入渠道。接入渠道可新建或复用当前服务商已有连接，复用只新增模型关系，不改共享地址、密钥或其他模型成本。采购项优先显示对应类型常用项，保留全部搜索。
- 路由引用区分当前使用、配置保留引用和路由草稿；固定路由编辑可移出未参与条目，预览确认后释放引用。停用或解除映射保留引用保护，并可直接前往处理。停用服务商服务须明确当前模型、服务商及模型调用标识，不能误指整个服务商。
- 模型调用标识编辑按实际阻塞原因分别提示停服、灰度/正式下架；已停止但仍上架时只要求下架，未上架不表述为已下架。父服务停止但渠道仍保留启用配置时明确渠道停用要求，沿用现有校验及权限。路由及映射页不显示「模型映射与流量路由」重复标题，保留配置路由、服务启停及操作记录。
- 模型调用标识维护先下架停服，核对原值与新值并确认客户迁移；保持规范身份、记录ID及历史，不创建自动别名。归档服务须无活动路由、草稿、映射、服务商和未完成任务；归档记录及恢复条件保留，不提供列表归档入口；恢复保持下架停服。
- 字典中文名和单位优先，英文与内部标识为辅助；密钥紧急动作位于更多操作中并明确影响。操作记录支持搜索、类型筛选和安全的旧新值摘要；旧记录无快照时明确缺失，不回填虚构值，不展示凭证。

## 渠道成本与模型售价

- 两个列表保留原搜索，增加模型展示名、服务商及状态独立筛选并按交集组合；成本状态为已配置、待配置、已失效，售价使用列表已有销售状态（未上架、在售、灰度在售、已停售、服务不可用、不可销售、不销售）。模型及服务商选项按稳定 ID 去重，不按展示名合并；统一模型服务模式归属内置平台服务商。选项读取当前列表有效记录，筛选不写业务数据。变更筛选或重置回到第一页，重置清除搜索及三个筛选但保留来源模型上下文；筛选和页码写入 URL，刷新及详情面包屑返回保留。无匹配结果显示空态，不自动替换所选对象。

- 渠道管理的模型总表、服务商详情和模型详情渠道表的「成本」共用同一有效采购记录与单元格，使用一个展示列，每条渠道占一行，多个计费项在同一成本单元格内横向排列，以分号分隔，窄屏按可用宽度换行；每个计费项按名称、适用条件、价格、币种及单位组合展示，例如「输入 Token：1.00 元/百万 Token」。人民币显示元，其他币种按记录显示。成本设置表单及数据库分别保存计费项、金额、币种、单位和条件。模型总表展示有效采购价、币种及适用条件。「成本设置」按当前渠道打开 960 px 宽抽屉，标题显示渠道名称及成本设置，顶部显示服务商与模型。每条渠道分别维护计费项、条件、币种、价格、单位及历史版本；首次无采购配置时为空。下一步预览发布配置生效及到期时间，确认成功后刷新当前表格。复用采购版本事务、角色、修订冲突、失败输入保护与未保存保护。零价与缺价分开，调价不追改旧请求及价格快照，不清除技术证据。
- 成本、售价、渠道和资料通过同一 D1 读写边界；直接 URL、刷新、权限、冲突及失败输入保护与原模块一致。新增对象不因缺价落入另一套本地存储。
- 模型总表在「服务商及渠道」后展示「容量」列，与当前渠道行对应；服务商和模型详情的渠道明细共用相同容量单元格及设置抽屉。容量只展示已配置指标：零项显示「未配置」，一至两项直接显示数值和单位，超过两项显示前两项及「更多 N 项」，浮层只列剩余指标。「容量设置」独立放在渠道操作中。缺失值不代表零或无限。容量设置使用 960 px 抽屉，分别维护 RPM、TPM，并按需添加并发上限、RPD、TPD、RPS、输入 TPM、输出 TPM、IPM；TPM、输入 TPM 和输出 TPM 以百万 Token/分钟展示和填写，最多 6 位小数，保存时精确换算为 Token/分钟正整数；其他指标须为正整数。容量按渠道稳定关联 ID 独立保存到当前渠道的 `capacityLimits`，不从同模型、同服务商或共享连接继承或联动。保存沿用 D1 事务、权限、修订冲突、失败保留输入和未保存保护；查看及取消不写入，容量变化不清除连接测试、报价或路由。这里记录上游额定限额，不代表实时剩余额度或网关限流执行。
- 模型售价按统一模型服务模式或服务商服务的稳定 ID 定位；详情仅保留售价配置、变更记录；不提供销售设置、查看关联成本或查看服务与路由入口，售价金额下不展示采购成本提示。变更记录仅展示当前服务的计费项与售价版本，含价格版本 ID、版本号、生效时间、计费项、金额、单位和币种，不混入上架、可见性、渠道、路由或销售范围操作。完整审计记录保留在原存储与模型服务操作记录中。既有销售范围及经营校验不变；失效价格不作为生效价，历史价格按原服务及代际查阅。
- 内部服务不要求售价且不销售；变更用途必须停服、停售并核对商业依赖。无法核对时阻断，不自动收费、退费或重写权益。
- 管理端模拟记录保留调用时来源、成本版本及计量依据；无成本待核算，内部验证无订单／订阅／销售费用；同操作 ID 重放不重复写版本、请求或费用。

- 管理端模型字段按实际归属命名：主档业务身份为「模型编码」，客户调用参数为「模型调用标识」，渠道上游调用参数为「上游模型调用标识」，内部主档键为「资料 ID」。主档/服务/目录别名的可读名称用「模型展示名」，名称取值和归属保留；模型服务名称独立。广场与部署中渠道直选模式展示实际渠道服务 callId，不使用父模型的 modelId 替代。限流模型目录读取主档 canonical_slug，使用「模型编码」。新操作差异按对象命名；既有审计原文、导入文件表头和数据库字段不重写。

模型运营字段、永久 ID、JSON 批量维护及模块归属统一遵守[字段与身份规范](MODEL_OPERATIONS_IDENTITIES.md)。新建及存量对象均须符合规定前缀与 UUID v4 格式。具体模型服务统一使用 model_service-UUID；旧前缀须通过专用事务同步迁移全库主键与引用，不保留公开旧号或别名。


「查看 JSON」按模块、服务商、模型、服务商下模型或具体模型服务层级进入独立页，标题与导出范围一致。总表按钮在模块页头，详情按钮在对象信息区右侧；模型广场的模型操作提供模型级入口。当前范围完整 JSON 不受搜索、分页、折叠或页签影响，全文自然滚动并可复制，支持刷新和来源上下文返回；对象和数组支持逐层展开／收起以及全部展开／收起，默认全部展开；收起后显示字段或项目数量，空对象、空数组及基本值完整保留。折叠仅影响浏览，完整复制与批量维护始终使用完整 JSON。无效对象不回退全量。v2 JSON 使用 scope、target、revision、rows 和只读 references，字段、共享对象、价格历史和回导规则遵守[字段与身份规范](MODEL_OPERATIONS_IDENTITIES.md#批量维护-json)。JSON 页及来源页面的批量维护使用同一 target，复用宽抽屉和原子保存；越界、篡改只读引用、过期修订等整批拒绝，连接变更预览显示受影响渠道。

## 后台访问控制

- 访问控制包含租户管理、用户管理。租户列表统一政企和个人入口并保留数据来源筛选；组织、成员、项目在租户详情维护，复用现有共享 D1 事务和开户校验。个人租户保留唯一默认项目。用户按登录账号展示，详情按租户查看成员角色和项目归属，成员管理返回指定租户；企业内用仅展示本企业成员。
