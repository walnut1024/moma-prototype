# 旧模型运营页面规格

基线为 `8b2c452`。以下条款记录当时的入口和流程。现行规则见[页面规格](../../PAGE-SPEC.md)。

## 原导航、服务、数据及指南条款

- `listing`、`providers`、`model-market`、`model-costs`、`model-prices`、`model-templates`、`tariff-dictionary` 使用 `/api/5120/`。模型资料、服务商、密钥组/池、渠道及映射、采购/售价历史、服务、路由、检测与试调用、发布和操作审计均落 D1；筛选和未提交输入保留在浏览器。

- 新 D1 初始化计费字典和参考模型主档。平台管理员在研发说明中显式导入两套模型服务演示案例及其依赖，成功后保持下架。已有工作区启动时读取原数据，导入复用同一主档，记录冲突时整包拒绝。

- 后台 2 运营分析依次为用量数据、用户数据、客户数据三个同级入口；运营和系统管理员可访问，运维不可访问。运维入口称调用数据，保留 `call-analysis` 路由。模型运营依次为渠道管理、模型服务（默认入口）、模型广场、模型售价、模型资料。面包屑中的「模型运营」仅为分组文本，不链接到同级的模型服务；具体页面的父路径仍保留筛选与分页。 各子功能入口在页头标题下展示一条职责说明。模型资料按模型、模型作者、模型系列、计费项、计费单位、货币排列，维护模型主档和共用字典；模型售价的“计量配置”进入字典页面，切换字典页签保留来源返回路径，面包屑统一归属模型资料。

- 不提供独立 `service-routing` 页面；路由在模型工作区“路由及映射”维护，领域事务、历史配置和数据保留。概览为运营默认首页，不恢复旧独立工作台或安全治理模块。

- 运营导航底部的入门指导分组保留“模型运营”指南（`getting-started`），运维不可访问；接入和维护流程就近提供帮助，不强制先读教程，不因首次登录强制新建。渠道管理不恢复旧使用引导弹窗。

- 后台面包屑由 `breadcrumbs.mjs` 生成。一级分组链接到该分组默认入口，「模型运营」打开「模型服务」。详情页的上一级链接保留列表筛选和分页，当前项显示为文本。模型服务抽屉不增加面包屑层级，关闭保留列表筛选、滚动和入口焦点。向导为「模型运营 → 接入并上架模型」，返回注明来源。任务跳转保留模型、页签、筛选及当前输入，缺失对象不静默替换。普通详情不重复返回按钮。独立订购页返回当前版本订购入口。

- 六类主要用途为语言模型、视觉理解、视觉生成、语音模型、向量模型、重排模型；语言模型可支持图像/视频输入，不能仅因名称含 VL 或具备图像能力改类。既有类型代码、图像/视频任务及计量单位保留。输入/输出模态与向量/相关性等结果类型区分，未知能力/规格保持未填写。

- 基础资料库的共享主档编辑按用途分区：模型卡片维护名称、Logo、类型、输入/输出模态、结果类型、上下文与模型描述；模型详情维护作者、适用场景、支持语言、任务、资料链接、详细介绍及按类型展示的能力规格；模型编码、系列、版本与发布日期在“其他信息”，技术与接口属性独立展开。广场公共展示内容按模型 ID 维护一次，模型资料更新不覆盖已保存的广场内容。售价在独立模型售价维护；模式、关联和模型调用标识 在路由及映射维护；既有模型级客户范围保留并继续参与经营检查。

- 主档名称、介绍、图标等在当前表单编辑，预览受影响服务并明确提交后同步引用展示；不因展示文字修改重测连接。类型、能力、模态、任务、版本及深度思考/结构化能力变更走专门影响检查，重验受影响范围；不兼容依赖先修复或明确下架，合格后发布，不直接覆盖在线配置。仅属性顺序变化不误判，稳定身份、权限、修订、存储和焦点保护保留。

- 模型运营初始数据集中于 [Mock 配置](../../MODEL_OPERATIONS_MOCK_DATA.md)，基础资料、供应管理、模型服务共用稳定引用与目录范围，前台读取后台生效服务。只在没有存档时初始化；已有用户配置、删除记录、凭证、草稿与历史不因刷新或配置更新被补回或覆盖。

- 对外服务正式资料沿用其现有完整校验；技术接入可以先保存最低身份资料，任务/能力缺失保持待完善，不能据此启用技术服务或上架。资料与服务编码规则的已知差异见 [MODEL_OPERATIONS_TERMS_REVIEW](../../MODEL_OPERATIONS_TERMS_REVIEW.md)，不靠改名宣称差异已修复。XLSX/CSV 前两列统一模型编码/模型资料名称，不增加旧表头别名。

- 「路由策略」页签可单选当前模型服务的路由策略。支持 LiteLLM 的加权随机、最少并发、低延迟优先、按用量分流和成本优先，未设置的服务默认使用加权随机。保存后更新当前策略，切回加权随机时读取已保存权重。按用量分流展示渠道的 RPM 和 TPM 上限，成本优先提示缺少有效采购价的渠道。

- 上下文长度路由可配置 Tokenizer 和各已启用渠道的上下文长度。关闭时保留配置。开启后可输入请求 Token 数预览。预览先排除停用、不可用及上下文不足的渠道，再取优先级最靠前的一组。加权随机展示预计分流比例，其他策略展示候选渠道。

- 入门指导「模型运营」分为模型运营做什么、渠道管理、模型服务、模型广场、模型售价、模型资料、日常维护八篇短指导，六个模块的名称和顺序与左侧模型运营一致。每次仅展示当前一篇；`getting-started?guide=...` 支持直达、刷新及前进后退，篇内补充内容按需展开。

- 首篇说明模型运营的职责与价值，按内部使用、对外经营、日常维护提供操作路径，并列明六个功能的业务入口、数据来源及引用关系。技术验证与启用可在缺成本、售价时完成，缺成本待核算。内部服务启用后通过模型服务列表的调用标识、API 协议和端点交接，面向授权公司成员的内部上架尚未实现。对外经营在技术启用和经营配置齐备后到模型广场上架。广场展示、经营上架及技术启停分别管理。旧接入记录保留并从对应模块继续，不恢复重复编辑或全局四步接入上架主按钮。

- 销售对象与售价分别编辑、预览及确认。销售对象通过 `salesScope` 独立保存，经营上架前须明确配置。模型内经营服务共用销售对象；售价按统一服务或具体渠道服务归属。渠道服务各有上架阶段，灰度客户在灰度上架时单独选择。

- 技术启用弹窗列出资料、身份、连接、映射、路由与平台验证证据，可前往缺项配置。在模型广场上架时另行核对当前成本、售价、技术启用与销售对象。价格变化不清除技术证据，连接／能力／路由变化需重验。

- 使用说明见[模型运营指南](../../MODEL_OPERATIONS_GUIDE.md)，分阶段范围见[实施清单](../../MODEL_OPERATIONS_IMPLEMENTATION.md)，实际证据记入[PROGRESS](../../MODEL_ONBOARDING_PROGRESS.md)。

- 接入模型内联搜索多选，一次提交后可继续接入渠道。接入渠道可新建或复用当前服务商已有连接，复用只新增模型关系，不改共享地址、密钥或其他模型成本。采购项优先显示对应类型常用项，保留全部搜索。

- 模型 ID 维护先下架停服，核对原值与新值并确认客户迁移；保持规范身份、记录ID及历史，不创建自动别名。归档服务须无活动路由、草稿、映射、服务商和未完成任务；归档记录及恢复条件保留，不提供列表归档入口；恢复保持下架停服。

- 渠道管理的模型总表、服务商详情和模型详情渠道表的「成本」共用同一有效采购记录与单元格，使用一个展示列，每条渠道占一行，多个计费项在同一成本单元格内横向排列，以分号分隔，窄屏按可用宽度换行；每个计费项按名称、适用条件、价格、币种及单位组合展示，例如「输入 Token：1.00 元/百万 Token」。人民币显示元，其他币种按记录显示。成本设置表单及数据库分别保存计费项、金额、币种、单位和条件。模型总表展示有效采购价、币种及适用条件。「成本设置」按当前渠道打开 960 px 宽抽屉，标题显示渠道名称及成本设置，顶部显示服务商与模型。每条渠道分别维护计费项、条件、币种、价格、单位及历史版本；首次无采购配置时为空。下一步预览发布配置生效及到期时间，确认成功后刷新当前表格。复用采购版本事务、角色、修订冲突、失败输入保护与未保存保护。零价与缺价分开，调价不追改旧请求及价格快照，不清除技术证据。

## 原渠道工作台条款

「模型运营」侧栏并列提供「渠道管理（新）」和「渠道管理（new）」。原「渠道管理」可通过旧链接访问，默认打开服务商总表，沿用现有权限。新入口 `providers-new` 默认打开「渠道视图」，可切换至「服务商视图」。渠道视图按模型分组，每条模型渠道一行，显示渠道及服务商、状态、上游模型调用标识及 API 地址、容量和采购成本。支持按模型、渠道、服务商或渠道 ID 逐行搜索、按状态筛选，并在详情返回时保留筛选和页码。「编辑」打开当前渠道的原配置抽屉，「更多」提供容量设置和成本设置。两页读取同一供给数据，复用现有编辑、权限、验证和保存操作。

服务商列表操作只保留编辑与删除，删除流程及风险确认统一使用「删除」文案，保留原两步关联检查、软归档和历史保护；服务商名称继续作为详情入口。服务商详情及其 JSON 页不提供「批量维护」，渠道表原有批量操作保持；模型渠道的单条、批量删除入口统一称「删除模型渠道」，沿用关联检查、停服下架与风险确认，不物理删除模型资料和历史。API 密钥池原「检测」操作称「测试连接」，校验行为保持。渠道名称支持预设选择及输入自定义值，输入新值后提供明确的「添加自定义渠道名称」操作。渠道 JSON 读取当前保存状态，独立汇总服务商、模型登记、连接与模型渠道数量；已删除渠道不进入当前渠道行，仍保留的模型登记照常导出，不把登记数当作有效渠道数。

模型渠道行的原「配置」入口统一称「编辑」，沿用同一编辑抽屉与保存/验证校验。新增渠道的「模型」选项使用名称与模型编码组合展示（名称 · 编码），选择仍按稳定模型 ID 定位并联动模型编码，不合并存储。渠道名称可选择官方、自营、转售或输入自定义名称；新建默认自营，切换模型不覆盖手工名称；编辑沿用存量名称，连接名称字段仍独立。容量表下方的「添加容量指标」打开复选弹窗，可一次选择多项后「添加所选项」；已添加指标勾选禁选，取消不修改容量草稿，添加保留已有数值；RPM/TPM、单位转换、保存校验、修订冲突和取消保护不变。

服务商总表将「服务商」和「服务商编码」拆成独立两列，服务商 ID 不在列表显示；名称下钻、编码复制和按 ID／名称／编码搜索保留，永久 ID 的存储、关联、详情与 JSON 查询不变。模型总表及服务商下钻的模型渠道、待配置模型、已登记模型抽屉和模型详情供应服务商表，继续按原有方式合并名称与编码展示；模型表头为「模型」，名称在上、编码在下，保留编码复制、详情、分组及其他永久 ID 列。

渠道管理页（「服务商视图」「模型视图」双视图）、模型渠道表、API 密钥池、接入新模型/新渠道表单、渠道编辑抽屉、密钥池与凭证候选编辑及接入记录续配使用 Semi Design 原生组件和默认样式。保留默认配色、字体、字号、圆角、表单和表格密度，仅设置布局、间距和响应式规则；旧后台样式不覆盖该区域及其弹层。表格合并单元格、脱敏、候选测试与应用等行为按本章既有条款保持。

- 渠道管理默认显示服务商总表。依次展示服务商、Provider ID、供给类型、已登记模型、API 密钥池、服务商地址 服务地址（Base URL）和操作。首列显示可下钻的服务商名称及图标；独立 Provider ID 列展示和复制完整永久 ID。详情展示完整 ID。支持按完整 ID、名称或编码搜索，返回总表保留搜索和页码。已登记模型只计实际供应关系，按统一模型合并别名，内置参考项不计入。点击数量在抽屉查看对应模型的名称、模型编码和类型；API 密钥池只显示服务商密钥数量。服务地址（Base URL） 读取当前未归档渠道的地址，相同地址只显示一次。渠道管理的只读地址、ID、编码和标识在值左侧提供复制按钮，多条地址逐条复制。

- 行操作为「详情」「编辑」「移除」。点击服务商名称或「详情」进入该服务商的「模型渠道」，可切换「服务商 API 密钥池」。不提供独立连接列表、连接详情及连接编辑页面；底层连接、稳定 ID 和共享关系保留。协议、地址、认证、超时等配置统一从「模型渠道 → 编辑」维护，「高级配置与历史」承接候选验证、影响范围、历史配置及回滚；所有原有权限、修订和引用检查继续有效，不改变服务启停。停用服务商可在详情启用。编辑抽屉默认只读。名称、图标、官网、描述和各渠道 服务地址（Base URL） 左侧有编辑图标，点击后才进入该字段的编辑。服务商 ID、编码和供给类型只读，数量由实际记录计算。服务商地址 服务地址（Base URL） 在当前抽屉内逐条展开编辑，不打开或替换为另一编辑弹层；同一时间只编辑一条地址，取消后回到对应编辑按钮。地址编辑期间暂停资料字段编辑；切换字段或关闭抽屉保留未保存保护。地址已关联模型时在行内完成候选验证和应用，未关联模型的渠道在行内保存新地址后须重测并启用。渠道及密钥的其他配置在服务商详情维护。

API 密钥池列表按密钥组展示优先级、密钥名称 / ID、脱敏密钥、当前绑定渠道、状态与操作。优先级从 P1 开始，可拖拽组内排序，也可上移／下移。备用顺序直接保存。切换有渠道引用的 P1 时，先查看影响并检测全部引用，再应用优先级。失败保留当前顺序，刷新可继续处理候选。

列表中的「替换」仅输入新的 API 密钥，点击「保存」后验证已有绑定并一次性生效。保留密钥名称、ID、优先级和渠道引用。失败保留原密钥，审计记录替换对象及受影响渠道，不记录密钥明文。

两条旧演示渠道 supplier-review-CH-001 / supplier-review-CH-002 及其四条初始样例映射不再作为默认数据安装；已有线上记录须核对无供应、路由、模型关联及任务引用后，通过现有删除渠道事务归档。合法手工保存的未关联渠道继续保留，不因状态文案自动清理。

渠道管理的服务商总表页头仅提供「录入服务商」，不提供「创建渠道」。新渠道从服务商详情的「新增接入」维护。录入使用 1280px 宽抽屉，小屏不超出视口，仅保留表单，不提供 JSON 导入或模式页签。API 密钥输入占位提示 sk-xxx，此提示不限制其他服务商密钥前缀。服务商图标显示 PNG、JPEG、WebP 且不超过 512 KB 的格式要求，URL 输入提示 http:// 或 https://；既有格式、大小与地址校验保持。表单包含服务商名称、服务商编码、供给类型、多个 服务地址（Base URL）、多个 API 密钥、服务商图标、官网和 300 字描述。名称、编码和供给类型必填，供给类型为第三方推理服务或自有推理服务；编码创建后不可修改。地址逐条添加，作为待配置渠道地址保存；密钥逐条添加，最多 20 条；明确选择默认 API 密钥组或新建命名密钥组，本次密钥按输入顺序加入所选组。默认组与命名组、密钥 ID 及优先级和服务商 API 密钥池同源；后续分组、排序、轮换仍在密钥池维护。只提交并持久化掩码与指纹。图标支持上传 PNG、JPEG、WebP 或填写 URL，最大 512 KB。主体、地址及密钥一次原子保存，失败保留输入。服务商列表增加供给类型，地址与密钥数量读取同一渠道地址和密钥池；官网和描述在资料详情查看及编辑。供应模型在服务商详情另行登记或批量导入；新地址保持待验证，不自动启用或上架。同编码服务商移除后可重新录入，沿用主体稳定 ID，旧渠道及价格版本保留归档，新渠道须重新验证，不自动恢复旧服务。

- 首次上架向导继续使用其接入表单和原子保存；服务商详情仍分别登记模型和添加渠道。可用性及最近测试来自现有渠道证据，不新增持续探测或实时遥测。

- 模型视图及渠道模型明细按真实映射展示计费项；服务商模型及渠道表展示各模型渠道的当前有效刊例价；能力声明通过“配置”中的当前模型配置维护。金额保留零值、缺失、单位、币种和条件；地址可查看完整值。行操作与对应对象明确关联，关联状态来自精确供应映射，不把健康状态当关联。

## 原模型服务删除说明

- 模型服务列表的「更多」提供「删除」。确认前检查启停、上架、路由、草稿、映射和未完成任务，存在订单、调用或套餐引用时拒绝删除并提示归档或先处理引用。删除后移出服务目录，保留模型资料、渠道、价格、路由及审计历史；再次添加同一模型复用稳定 ID，旧价格与路由不自动生效。
