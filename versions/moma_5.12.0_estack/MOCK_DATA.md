# 5.12.0 全站 Mock 数据

本版本的初始资源和参考样例集中在 `src/mock/`。管理端模型运营通过 JavaScript Workers 读写 D1，仓库配置仅作首次导入及只读参考。其余模块保留版本内浏览器业务数据；图表样例继续使用 JSON 配置及原有派生逻辑。租户侧尚未接入 D1，不把两种数据源宣称为实时联动。

## 配置与运行数据

| 文件 | 内容与使用时机 |
| --- | --- |
| [application.json](src/mock/application.json) | 客户、用户、成员、项目、Key、额度、订单、账单、网关规则、集群、部署、后台账号等非模型初始资源；仅创建工作区时载入 |
| [system-model-catalogue.json](src/mock/system-model-catalogue.json) | 系统内置模型主档及既有业务所引用的模型稳定 ID |
| [initial-workspace.json](src/mock/initial-workspace.json) | 历史评审模型资源的初始化差异；不在恢复存档时重放 |
| [model-operations.json](src/mock/model-operations.json) | 当前统一服务和分供应商案例的模型、供应及销售配置 |
| [catalogues.json](src/mock/catalogues.json) | 官方参考目录、供应参考项、连接模拟响应、语音/视频/提示词素材，以及旧独立页面的参考样例；以原模块名分组，参考资料不是运行资源 |
| [application-data.js](src/mock/application-data.js)、[model-data.js](src/mock/model-data.js) | 校验、克隆、组合初始配置及记录来源；不复制领域事务 |

`application.json` 中 `initial`、`personal`、`enterpriseOrganization` 分组在创建时组合一次；计价字典独立维护，不重复保存相同初始记录。`@now:毫秒偏移` 仅用于初始请求时间，让初次打开的近期样例可查询，不会重新给已有请求改日期。派生用量样例的规模、模型、身份及权重取固定初始配置，只保留当前仍存在且客户/项目归属相符的引用；用户新建 Key、模型或成员不会获得虚构历史，编辑初始 Key 也不把旧样例重分配给其他 Key。序列化时不把派生样例当成用户请求保存；无初始来源标记的旧工作区不生成这类样例。

以下三层必须区分：

1. **系统初始数据**：仓库 JSON，只读模板。`initialData.builtinIds` 和模型域 `modelData.builtinIds` 记录初始资源 ID 及版本。配置升级不自动覆盖已有工作区。
2. **用户配置数据**：模型运营为 D1 中的当前资源，未迁移模块为版本独立浏览器存储。新增、修改、删除 ID 单独登记在 `userIds`；修改内置资源后仍保留其内置身份。已保存集合（包括空集合）以存档为准，不补回用户删除的数据。没有来源标记的旧记录保持原状，不根据名称或手机号认定它是初始数据。
3. **运行事实**：请求、登录事件、订单快照、审计和历史。来自明确动作或既有记录，不能靠重新载入配置重建；未知计量、费用、用户归属和时延保持未知。

## 前后台的数据关系

| 用户面 | 共享记录及管理面 |
| --- | --- |
| 模型广场、模型详情、模型选择器、API 指南 | 仍读取租户侧浏览器模拟数据；本期不消费管理端 D1 发布。后续若迁移，需要单独设计安全的对客投影 |
| 按量及 Token Plan API Key | 同一客户的 `apiKeys`、`grants`、项目及有效订阅；后台客户 Key 和额度页读取同一 ID |
| 模型订购 | 当前服务与售价生成可选规格；确认按量订购写入同一 `products` / `orders`，订购结果为生效中。已有套餐从实际订单读取；本轮不实现新的套餐销售流程 |
| 文本/图片/视频/语音体验 | 发送与交付继续使用服务准入检查；完成后记录带客户、服务 ID、调用 ID 的 Mock 请求 |
| 调用日志、用量统计 | 从当前客户同一批请求派生；Request ID 去重，网页体验没有返回的 Tokens 和费用不补造 |
| 组织及成员、组织操作记录 | 同一 `organizations`、`users`、`memberships`、`audits`；平台账号候选来自共享用户，组织管理员修改后后台读到相同记录 |
| 注册、认证、身份切换 | 认证会话独立；显式稳定 ID 映射到业务用户。新个人注册建立自己的客户及项目，政企申请写申请记录，仍需审核，不自动授予企业成员权限 |
| 智能路由 | `tenantRoutes` 保存客户自己的模型选择，不与管理面供应渠道路由混用 |
| 后台概览、用户数据、用量/调用数据 | 同一用户、显式登录事件和请求事实；不再单独生成另一份注册/登录人数或前台日志 |

前台写操作统一在 [tenant-data.mjs](src/tenant-data.mjs) 重新读取身份和修订号、校验客户/所有者及引用，再一次保存到版本共享业务存储。写入失败不显示成功，并保留表单；冲突要求刷新。未迁移的后台模块仍沿用浏览器领域事务并通过同页事件、同源 `storage` 和聚焦复查同步。模型运营由服务端执行同一领域规则，确认 D1 原子保存后更新页面缓存；聚焦检查远程修订，冲突保留输入。前台普通成员只能维护自己的 Key/智能路由，组织维护必须是当前企业管理员；切换客户不能带走原客户记录。

Key、客户路由和组织编辑在打开时冻结修订号；其他标签页修改后不能用旧表单覆盖新记录。账号或客户切换会清除原身份的临时表单及明文 Key，筛选视图按身份隔离。Key 关闭额度限制保存为不限额度，再开启相同额度/周期保留原用量；修改额度或周期才重置用量。TPM/QPM 保存实际输入并由本地请求模拟器检查；不限 Key 额度不豁免客户授权、客户额度或限流。模型订购状态读取实际有效订单。

模型接入的页头进度跟随当前操作；保存连接不自动发布采购价。采购价尚未发布时明确提示维护及发布，采购生效后才能完成备用准备，备用渠道不会自动投入流量。前台调用记录冻结发送时的模型及调用 ID，资料或 ID 后续变更不改写原请求身份。统计按模型实际类型筛选，基础模型筛选包含其各供应商调用；音频秒数、字符数及 Token 不混加。不显示没有实际额度来源的固定套餐汇总。

模拟 API 请求的重复 Request ID 仅允许原 Key、客户、模型及服务复用；不同归属冲突不返回原请求或价格快照，原 Key 被撤权后不能重放成功结果。正常重复请求不再次增加用量。

仅持久化 Key 掩码和版本，明文只在本次创建/重置页面内可复制；刷新后不把掩码当成可用密钥。前台请求投影不包含供应凭证、指纹和内部采购快照。组织用户与认证身份只能使用明确映射，禁止按相同名称或电话认领历史数据。

旧独立组织、智能路由和无归属对话存储不删除，也不自动归给当前用户；原本没有客户关联的数据不能擅自成为当前企业的成员或配置。旧参考目录和历史交易引用保留，因此所有后台历史模型不必等于首页两款演示模型。

## 验收与维护

- 修改初始数据时在 JSON 中改稳定 ID 和引用，不在页面追加局部样例；构建会检查模型配置和全站配置的重复 ID、客户、项目、订单及成员引用。
- 空白工作区验证初始化；已有工作区验证手工修改、删除、草稿和历史不被回填；写入失败与并发冲突必须保持原存档。
- 使用明确联动身份，完成前台创建 Key、订购、体验，再在后台按相同 ID 查到记录；刷新后保持，切换另一客户不应出现前一客户的数据。
- 组织双面使用同一记录；用户自己不能停用/移除当前登录成员，不能通过外部 ID 修改其他客户资源。
- 客户统计与平台统计从相同请求计算；Mock 体验的未知 Tokens、采购及扣费不能显示成已核算零元。
- 两标签页同时编辑时拒绝旧修订并保留输入；切换账号后原表单及已保存筛选视图不可带入。关闭额度后刷新保持不限，TPM/QPM 修改后重新打开保持原值；分类筛选不能退回全部模型。
- 模型运营通过现有 Cloudflare Pages Functions + D1 跨浏览器共享；生产与预览绑定独立数据库，旧浏览器存档不自动导入。其他模块仍仅在同源同浏览器共享。发布与验证见 [D1 实施台账](docs/model-operations-d1/PROGRESS.md)。

测试入口：[application-mock-data.test.mjs](tests/application-mock-data.test.mjs)。现有模型准入、发布、撤权和业务事务测试继续适用。
