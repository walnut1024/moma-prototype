1. 重新确认 prototype 仓库及目标分支，读取当前状态。工作区已有大量并行改动，不能以当前 HEAD 代替实际实现，也不能重置来获得干净目录。
2. 核对本计划列出的写入调用方、价格/发布快照、前台准入和已保存数据边界。本文列出模块只是影响面，不要求所有文件重写。
3. 按第 9 节执行适用检查，记录基线失败；既有失败先独立归因，不顺手修复无关功能，也不能在最终报告省略。
4. 确认当前任务仍获代码修改授权。用户先后授权 P1、P2，并继续要求完成所有计划；P3 与 P4 技术验证据此执行。真人新人试用按用户答复保留待验收；部署不在本轮授权范围内。

## 4. P1：草稿与对客生效闭环

### 4.1 实施内容

- 梳理现有售价、客户范围及服务候选的所有写入入口，复用既有草稿、修订和事务边界。仅为实际任务增加所需状态，不建通用工作流框架或第二套模型仓库。
- 保存形成任务草稿，预览显示旧值、新值、适用客户和生效时点；当前编辑区提供明确发布按钮。
- 统一后台模拟请求、mock 客户 API 及客户价格展示的有效版本。发布成功后新请求使用新价；已开始请求、内部重试和历史保持原快照；已有订购不锁旧价。
- 客户范围发布与访问检查一致。草稿不扩权，移出客户不能借已有订购或旧发布快照继续发起新请求。
- 发布隔离其他未完成任务。相关字段一起校验；主状态/发布快照更新失败不得留下半生效的客户状态。复用现有回执与防伪造规则，不用直接修改状态绕过平台证据。
- 保存失败保留输入，冲突不覆盖，结果未知先查同一操作。离开三选一、放弃本次修改与丢弃草稿按不同范围执行。
- 同步现有向导和维护调用方，使阶段内原入口仍能完成业务；P3 负责重组四阶段界面，不能把 P1 的调用方适配推迟到 P3。

### 4.2 主要影响面

现有售价/范围编辑入口、`ServiceWorkspaceDialogs.jsx`、`ModelOnboardingSales.jsx`、`model-operations.js`、`service-workspace.js`、服务会话草稿、发布证据与客户端、`mock-onboarding-service.js`、`mock-onboarding-sync.js`、`store.js`、`domain.js`、客户目录及访问检查。按引用搜索确认实际触达，不添加并行价格来源。

### 4.3 出口与证据

- UX04、UX05、UX11 规则与原型界面闭环通过；UX09、UX10 的持久化/冲突部分通过。
- 使用已有订购、两种销售模式、并行路由草稿、请求跨发布时间及存储失败场景验证。客户展示和两条调用路径分别核对，不只测管理端价格记录。
- 优先复用 `model-operations`、`unified-service-content`、`service-content`、`service-session-drafts`、`platform-service-client`、`mock-onboarding-service`、`mock-onboarding-sync`、`service-access`、`admin-storage-quota` 等既有测试。
- 只新增能捕获未发布生效、跨任务夹带、价格跨版本和半提交回归的断言，不编写仅镜像实现的测试。

## 5. P2：模型工作区与日常运营

### 5.1 实施内容

- 导航采用模型服务、供应商管理、基础资料。模型清单与接入任务按稳定关联呈现，包含各生命周期，不把同一任务和服务列成两款模型。
- 工作区按模型资料、路由及映射、售价管理、操作记录组织；日常任务直达区域。移除目标漂移的页头保存，采用本区域具名保存、预览及发布。
- 从模型进入共享资源维护后返回原模型、页签、筛选和草稿；不存在对象显示明确空态，不静默选其他对象。
- 共享展示资料先存草稿，预览全部影响后发布同步；调用能力变化走影响检查，必要重验或明确下架后发布。保留单一主档、稳定 ID 和引用，不增加第二份可编辑资料。
- 路由和共享地址/Key 复用候选、冻结范围、测试与应用能力；草稿不影响旧配置，正常轮换不撤销旧 Key，失败不部分切换。
- 下架明确阻止后续订购和调用，已开始的原请求按原配置完成；普通下架、主动取消、身份变化及安全撤销必须区分。旧“下架即丢弃在途结果”断言需要替换，但其他安全保护保留。
- 恢复检查当前资料、价格、范围、供应、路由及有效证据；失效部分重验。模式切换、移除引用和历史保护继续可达且完整。

### 5.2 主要影响面

`AdminConsoleV2.jsx`、`navigation.mjs`、`breadcrumbs.mjs`、`ServiceManagementWorkspace.jsx`、`ServiceContent.jsx`、资料与供应页面、候选维护、`model-operations.js`、`model-management.js`、`service-routing.js`、`service-access.mjs`、`service-directory.mjs`、`useServiceDirectory.js`，以及所有受下架在途结果影响的体验调用方。名称仅是定位索引；修改前搜索全部相关调用方和已存在的共享守卫。

### 5.3 出口与证据

- UX06、UX07、UX08、UX10、UX11、UX12 的日常任务和界面部分通过；UX02 的稳定对象复用通过。
- 同时验证当前执行中的调用和下架后新请求，验证已有 Key、重放操作及非目标模型；账号切换/撤权不得显示旧身份结果。不能仅改文案来声称在途行为已改变。
- 复用 `service-workspace`、`breadcrumbs`、`channel-service-context`、`channel-change-management`、`candidate-frozen-scope`、`credential-rotation-scope`、`service-routing`、`model-service-mode`、`service-access`、`auth-state`、`experience-drafts` 等测试及相关体验浏览器路径。
- 界面检查覆盖目标桌面窗口、键盘、错误、固定操作区、长 ID/URL 和返回焦点。只改后台作用域样式；前台若涉及调用状态，只改该业务边界，不顺带重做视觉。

## 6. P3：首次接入、备用任务与概览

### 6.1 实施内容

- 四阶段改为选择模型、接通供应、配置销售、验证并上架。模型优先，供应商选择区分已有主体、从模板新增和自定义新增，疑似重复提示复用。
- 最少身份在前，采购条件归供应阶段，完整展示资料归销售阶段。预填只来自明确记录，未知保持未知，不替用户决定客户范围、销售模式或价格。
- 基于候选路由与候选服务进行平台验证，保留用量授权；最终一次明确发布并上架。验证、路由与上架门槛分别校验，提交失败不留下半完成的对客状态。
- 进度由实际资源和有效检查派生，恢复最近确认成功状态；结果未知先查原操作，已建资源复用，明文 Key 不入草稿。
- 新增供应选择备用准备或投入当前服务。备用满足必要采购与检查即可完成，投入另需关联/路由发布；既有服务不重新填价、不重置模式或范围。
- 概览保留经营统计并直接从时间筛选开始，不设置当前任务汇总；接入与异常在模型和供应商工作区处理。
- 同步 `GettingStarted.jsx`、`DevelopmentNotes.jsx` 的步骤、维护路径、按钮、结果和边界。正式帮助按任务组织，研发说明保留现有 banner 入口，不把内部技术限制堆到产品流程。

### 6.2 主要影响面

`ModelOnboarding.jsx`、`ModelOnboardingSales.jsx`、`guided-onboarding.js`、`SupplierChannelConfiguration.jsx`、`channel-onboarding.js`、资源匹配/选择、平台试调用/发布、`OperationsOverview.jsx`、导航上下文、运营入门和研发说明。复用 P1 的发布边界与 P2 的工作区，不再创建另一套候选或维护页面。

### 6.3 出口与证据

- UX01、UX02、UX03 全流程通过，UX09/UX10 的刷新、中断、结果核对及跨页部分通过。
- 新资料与复用资料、统一/分供应商、新建/复用渠道、缺价、接口不兼容、试调用失败、最终提交失败均有覆盖；旧服务已上架不能让新增供应误报完成。
- 复用 `guided-model-onboarding`、`custom-channel-onboarding`、`channel-draft-recovery`、`service-material-publication`、`platform-service-client`、`getting-started`、`breadcrumbs` 等测试，不依赖文案字符串代表业务完成。
- 至少实际走通首次任务、保存退出后继续、备用完成及投入现有服务四类浏览器路径；不能以只读源码或测试替代界面闭环。

## 7. P4：集成与新人验收

- 按 [UX01—UX12](MODEL_ONBOARDING_ACCEPTANCE.md#当前验收ux-v10) 整理规则、mock 合同、浏览器及真实运营试用证据。对分阶段修改过的相关组合做一次必要的整体回归，不反复无差别运行全部检查。
- 重点交叉场景：售价变更+路由草稿；共享能力变更+在线服务；下架/恢复+执行中请求；新增备用+旧服务已上架；成功提交响应丢失+刷新；多人冲突+跨页返回。
- 邀请未参与设计的目标运营完成核心任务，记录误选、求助、回退、生效判断、输入丢失和耗时。不设未经验证的固定分钟目标。无法取得真实运营试用时，该项保持待验收，不由代理自测替代。
- 核对保留的并行分析、身份及其他版本行为没有受影响；旧失败单独归因，不能把未通过的全量表述为通过。
- 收口 PROGRESS 的实际结果、限制和剩余问题。生产上游、真实计费、跨浏览器或硬件能力未测就明确记录，不扩张原型完成声明。

出口：全部适用 UX 项有实际证据，关键新人任务可独立完成，无对象误判、生效误判、输入或历史丢失等阻断项。只有文档通过、测试文件存在或按钮可点击均不足以收口。

## 10. 风险与实施边界

| 已知风险 | 本计划的处理 |
| --- | --- |
| 当前工作区包含并行改动，提交时间不代表实际内容 | 每阶段复核状态和拥有源码，保留无关修改，不用历史测试成绩证明当前状态 |
| 售价有后台现行价格和已发布 mock 快照两条路径 | P1 完整串联展示/请求/快照，并覆盖旧请求与新请求，不只改按钮 |
| 首次一次发布涉及主状态、候选回执与路由依赖 | 复用事务及同步边界，明确整体成功条件与结果核对；不添加假成功回执 |
| 旧前台下架行为会取消在途结果 | P2 精确替换普通下架的规则；身份、权限、撤销及已取消任务保护保留 |
| 主档保存会直接同步多个服务 | P2 先形成草稿/发布边界再改入口；展示与能力分别验证影响 |
| 旧测试硬编码页面标签或旧提交步骤 | 按新契约更新受影响断言，保留安全/引用/历史保护；不整批删测试或增加兼容分支 |
| 原型可模拟流程，但不能证明真实网关及计费 | 原型、新人试用与未来生产验收分开记录，不新增真实外部请求 |

没有新增依赖、框架、通用状态机、存储命名空间或数据迁移的预先要求。不得重置用户数据；不得因本次 UX 工作顺带改其他版本、上线、推送或发送通知。
