## 数据和验证边界

- 保留手工资料、供应关系、稳定ID、渠道、脱敏密钥元数据、路由、价格、客户范围及历史。不重放初始数据、不按名称推断合并、不补造报价或成功状态、不默认开放全部客户。
- 复用角色权限、修订冲突、原子保存和幂等回执；失败保留输入及有效配置，未知结果查询原提交。
- 预览不保存、不调用；检测不自动启用，启用映射不自动投入路由，恢复路由不自动上架。
- 基础一期不新增自动故障转移、任意协议脚本、通用草稿系统、版本管理界面或专属协议价。
- 每阶段核验新增、编辑、取消、失败和刷新保留；命令变化补HTTP／D1契约；跨模块检查前后台同步、租户隔离、权限和历史快照。
- 验证使用独立本地D1，不在生产运行完整案例写入测试；真实上游连通与原型闭环分别报告。
- 第一至四阶段形成首次上架闭环，第五六阶段完成维护退出；每阶段完成相关回归、构建、Sites及版本隔离后发布，生产只读比较部署前后业务值。

阶段1已补齐：资料维护返回供应商并保留选择；渠道添加／编辑显式协议和根地址确认；服务端检测及独立启停供给；检测后进入对应服务或预选创建；创建页只读引用主档并配置模式和调用标识。原资料必填校验及 D1 稳定引用复用，不重写主档或恢复旧向导。定价范围上架、维护退出继续按阶段4—6实施，本轮不宣称完整上架闭环已完成。实际验证与发布记入MODEL_ONBOARDING_PROGRESS.md。

阶段2已补齐：服务内独立模型映射表，新增／编辑宽抽屉、请求两侧预览、保存、验证、启用、停用及解除。沿用 modelSupplies 稳定记录，引用同款主档下的供应商／渠道／上游标识；不复制地址、凭证或采购价，不自动创建路由、分配流量或上架。分供应商模式限制当前供应商。在用映射只改名称；未引用映射可保存待验证供给变更，原有效关系保持，验证后明确应用或放弃。生效／草稿路由（含未参与条目）、未完成任务保护停用、解除和目标切换；供应侧删除也检查候选关系。核验在服务端复用当前供给的检测证据，检查调用标识、接口、协议与路径，不发送新请求，不替代平台试调用或真实上游验收。旧有效关系原样保留，未重放种子或批量改写数据。

阶段3已补齐：新路由默认固定渠道且不预选映射；在路由区域右上角提供配置路由／替换渠道／编辑路由、停用路由、恢复路由。固定渠道只选一个已启用且当前检查通过的服务映射，预览新旧目标后原子生效；未保存取消与失败保持原配置。停用检查当前服务已停服（分供应商只看当前组或模型总开关），隐藏不能代替停服；明确确认后清空草稿并释放活动引用，保留历史和供应配置。恢复只读取停用前已发布配置，重新校验现有供给和接口，写入新的生效记录；草稿存在时要求明确编辑发布，不默默覆盖。恢复不自动恢复服务、上架、售价或范围。已有加权、其他策略、运行参数及历史不因更新被改写。来源校验按稳定映射ID排序，避免前端增量更新顺序与D1顺序不同造成误冲突。
