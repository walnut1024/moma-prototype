# 5.12.0 模型运营页面重组执行计划

日期：2026-11-06。状态：已按用户确认收回至模型运营管理端；P0 基线核对完成，P1 首个增量已实施，首个增量回归与界面验证通过；P1 后续拆分及 P2—P5 尚未完成。

本计划落实本轮确认的五模块结构，执行顺序为内部使用的管理流程、对外经营的管理流程。本文件是执行台账，不重建已删除的 PRD。以下方案与判定表是本轮拟实施及验收口径，不代表现有能力。历史实施文档中的成绩不作为本轮验收结果；与本轮冲突的有效规则在对应阶段修改前同步修订。

## 目标与范围

- 五个同级入口：渠道接入、模型服务、模型成本、模型售价、模型资料。
- 内部使用的管理流程不要求售价、订单或销售上架，即可完成服务配置、开放范围设置、管理端验证和启用。成本可以并行配置，缺失不等于零。
- 对外经营在技术服务之上增加成本配置、售价发布与销售设置；同一平台可同时存在内部服务与经营服务，不设全局场景切换。
- 沿用现有统一服务／分供应商服务身份粒度。供给组织方式与是否收费独立，不为本轮增加任意多服务、客户差异价或新计费引擎。
- 限定独立 5.12.0；复用现有组件、D1 事务、领域逻辑与模拟调用。不改变 5.11.0，不新增真实上游调用或生产网关。
- 本轮保留渠道接入的上游 API Key 配置；不设计用户调用平台的 Key，不改租户登录、会话、身份、成员权限、Key 签发／撤销及鉴权体系，不新增租户访问 D1 的接口。
- “内部流程打通”指管理员完成接入、服务配置、现有开放范围设置、模拟验证与启用；“经营流程打通”指管理员完成成本、售价和销售配置。用户端订购、账单、计费引擎及跨端调用贯通不属于本轮交付。
- 每阶段完成页面、规则、数据、相关回归与说明后再进入下一阶段。菜单只在对应页面可以实际使用时上线，不放空壳入口。

## 目标页面与迁移去向

侧边栏只展示五个模块。详情、供应商管理、计量配置通过页内入口访问；页签是内容分组，不全部展开为导航。

| 模块／目标页面 | 内容与来源 | 原位置处理 |
| --- | --- | --- |
| 渠道接入／渠道列表 | 复用现有供应商、模型视角，展示渠道状态与上游信息 | “模型接入”改名；供应商和共享密钥管理保留 |
| 渠道接入／渠道详情／接入配置 | 协议、地址、凭证、上游模型 ID；复用渠道编辑表单 | 移除采购价格编辑，保留成本摘要和定向跳转 |
| 渠道接入／渠道详情／请求适配 | 已支持的参数、协议与响应适配 | 只迁移已有能力，不因结构调整增加任意脚本适配器 |
| 渠道接入／渠道详情／测试记录、操作记录 | 当前渠道检测、验证与维护历史 | 保留明确启停、共享影响检查和凭证保护 |
| 模型服务／服务列表 | 技术状态、调用 ID、可用来源；销售状态作为独立信息 | 不再以销售上架判断技术可用 |
| 模型服务／服务详情／服务概览 | 服务名称、调用 ID、启停状态、资料摘要；成本售价只读摘要 | 移出模型主档编辑，跳转引用的资料详情 |
| 模型服务／服务详情／渠道与路由 | 当前路由及映射工作区、渠道关联、分流策略 | 保留关系和路由，只在供给侧编辑上游连接与适配 |
| 模型服务／服务详情／调用授权 | 原“售价与开放范围”中的服务侧客户开放范围 | 从售价拆出，复用现有授权粒度；不新增成员或 Key 权限配置 |
| 模型服务／服务详情／验证与调用 | 原 API 调用指南、管理端平台试调用与验证结果 | 去除内部服务管理端验证对售价、订购的前置要求 |
| 模型服务／服务详情／操作记录 | 服务配置、路由、授权、启停历史 | 历史记录保留原事件含义，不按新文案重写历史 |
| 模型成本／成本列表、成本详情 | 渠道采购价格、折扣、计费项、单位、币种、生效时间与历史 | 供给来源是成本归属对象，不按模型合并不同渠道价格 |
| 模型成本／计量配置 | 原模型资料下的计费项、单位、币种配置 | 售价页提供同一页面入口，不复制字典 |
| 模型售价／售价列表、服务售价详情／售价配置 | 服务的统一售价或分供应商售价及版本 | 原服务工作区价格编辑删除，改为摘要与跳转 |
| 模型售价／服务售价详情／销售设置 | 展示、销售对象范围、上架与停售 | 调用授权仍归模型服务；购买条件不等于调用权限 |
| 模型售价／服务售价详情／变更记录 | 价格与销售变更历史 | 不重复记录或搬移破坏已有历史引用 |
| 模型资料／资料列表、资料详情 | 基本信息、能力与规格、使用说明 | 服务中的模型卡片编辑回到唯一资料主档 |

跨页规则：从渠道去成本自动带入供给对象，从服务去售价自动带入服务，从服务去资料带入资料 ID；返回保留对象、页签与筛选。缺少配置打开带关联对象的新增表单，不要求重新搜索。不新增旧编辑页兼容分支；同步更新应用内所有入口、帮助链接及测试。

## 状态与业务规则

| 动作／状态 | 职责 | 不应连带发生的变化 |
| --- | --- | --- |
| 渠道启用 | 渠道当前技术配置可被服务选择 | 不自动绑定服务、开放授权或销售 |
| 配置生效 | 应用已验证的技术配置与路由 | 不自动发布价格或扩大调用范围 |
| 服务启用／停用 | 管理服务技术可用状态，供既有调用链路读取 | 不把用户可见性当启停开关；不据此声称用户端已经贯通 |
| 售价生效 | 明确收费规则、版本及生效时间 | 不清除未受影响的技术验证，不重算历史 |
| 上架／停止销售 | 管理销售开放状态与展示配置 | 不连带停用技术服务，不修改用户既有订单、订阅或收费资格 |
| 调用授权 | 维护现有粒度的服务侧客户开放范围 | 不新增成员／Key 授权层，不创建订单或订阅 |

新建服务明确选择是否需要收费；内部使用无售价记录是合法状态，不用零元售价表示。已有收费服务不能因缺少新字段被默认成内部免费服务；已有状态关系先盘点再明确转换，无法判定的记录保持不可新增开放，并提示处理。新旧字段转换不得清除用户数据、放宽权限或补造历史。

成本待配置不阻断内部服务的管理端配置、验证与启用；依赖完整成本的计算仍须提示待完善。管理端已有模拟记录使用可确认的计量与价格依据，缺失成本标记待核算，不补零值。

### 管理端授权与数据边界

- “调用授权”页签本轮只承接现有客户开放范围，复用当前全部／指定客户配置、有效客户校验及既有保存规则。客户包括平台已有的企业客户和个人客户，不把企业成员新增为授权对象。
- 授权目标沿用现有模型／服务配置实际支持的粒度。P0 核对并写清当前作用范围；现有模型级范围不包装成供应商服务级权限。不新增组织、成员、Key 多层交集或继承规则，不扩大原授权集合。
- 组织、成员和用户 Key 管理保持原状；管理端只引用现有可选客户，不增加身份登记、凭据签发、成员冻结或新租户接口。
- 模型运营继续使用现有后台认证和 D1 事务。新增成本、售价页面也进入同一模型运营数据边界，不因路由变化读取另一份本地管理数据。
- 当前后台 D1 与用户侧浏览器数据的衔接限制单独记录；不把后台模拟验证当成租户鉴权或实际调用成功，不以开放后台接口、复制管理数据等方式绕过限制。

### 管理端状态判定

下表只规定五模块中的配置、验证、启停和销售操作。用户端是否能够购买或调用不作为本轮验收结论。

| 情况 | 管理端展示 | 验证与启用 | 价格与销售操作 |
| --- | --- | --- | --- |
| 内部服务，无售价，技术配置与开放范围完整 | 技术状态与成本状态分别展示 | 可模拟验证并明确启用 | 不要求售价、订单或上架；不生成零元销售配置 |
| 内部服务，成本缺失 | 显示成本待配置／待核算 | 不因缺成本阻断普通技术验证和启用 | 不填零成本，不生成虚假成本结果 |
| 技术配置不完整或验证失效 | 显示具体待完成项 | 阻断启用，修复后重新验证 | 有售价也不能替代技术校验 |
| 经营服务，技术就绪但售价缺失或未生效 | 技术状态与销售待配置状态独立展示 | 可完成技术验证和启用 | 阻断销售上架，不默认免费 |
| 经营服务，售价有效且销售配置完整 | 展示独立技术、价格、销售状态 | 技术启停按技术规则处理 | 可明确上架销售 |
| 已停售的经营服务 | 销售状态为已停售，保留价格和操作历史 | 不自动停用技术服务 | 可维护售价；重新上架重新检查；不修改已有订单和权益 |
| 已到期且无接续价的销售配置（适用已有有效期规则时） | 标记价格失效，不把过期价展示为当前生效价 | 不清除未受影响的技术验证 | 阻断新增上架；已有销售配置标为不可销售，价格历史保留 |
| 服务已停用 | 保留配置和历史，明确技术停用状态 | 重新启用需满足当前技术检查 | 不允许新增上架；已有销售配置显示服务不可用，不抹去售价与历史 |
| 修改成本或售价 | 展示对应版本、生效时间和变更记录 | 不清除未受影响的技术验证 | 仅产生对应价格版本，不追改历史、不变更客户范围 |
| 内部与经营用途切换 | 展示影响范围，不能通过改页面标签直接切换 | 本轮只允许停用后、通过既有依赖检查的明确变更 | 存在活动商业依赖或无法核对时阻断切换；不自动收费、退费或变更用户权益 |

停售后按量用户调用、过期售价与有效订阅的组合、旧用户 Key 在用途切换后的处理，归用户调用与商业权益链路另行设计；本轮不为这些问题新增机制，也不声称已解决。管理端变更不得通过默认值或数据重写改变其既有记录。

### 里程碑 A 必验：管理端模拟记录与历史

以下要求在 P2 验收，使用现有后台模拟试调用和价格记录，不新建用户计费系统：

1. 内部服务的配置、启用和模拟验证不创建订单、订阅或销售费用，也不通过零元售价满足检查。
2. 现有模拟记录涉及成本时，缺少价格或计量事实保持待核算；有效成本使用本次模拟实际来源的价格版本、币种和单位。结果不代表真实上游费用。
3. 用现有成本编辑入口改价后，新模拟记录使用适用的新版本，旧记录保持旧版本与原值；补齐价格不自动重算原先缺成本的记录。P3 只迁移编辑入口，不延后历史保护。
4. 管理操作与现有模拟请求复用原操作 ID、事务及回执恢复；重复提交或超时重试不重复生成价格版本、模拟用量和费用记录。结果不明先核对原操作，不报告成功或另造成功回执。
5. 不增加租户请求记账表、用户 Key 幂等协议、销售扣款或结算链路；这些不作为管理端验收的隐含前置条件。

4. 核对现有客户开放范围的对象、粒度及保存条件，写清统一服务／分供应商服务下的实际作用范围；本轮只迁移和复用，不新增成员或 Key 权限层。

### P1：拆开技术服务与销售规则

依赖：P0 进入条件全部满足。目标：领域规则允许内部服务独立存在，旧经营服务行为保持明确。

- 分离服务启停、展示与销售状态；收费选择沿用现有可调用服务身份，独立于统一／分供应商模式。
- 拆分技术就绪、客户开放范围、售价和销售上架检查；内部服务的管理端验证与启用不再统一要求售价、采购价和销售上架。
- 技术验证只绑定影响请求的配置；价格变更有自己的版本及生效校验。路由、能力、连接变化仍使相关证据失效。
- 调整命令、事务、D1 读写和模拟发布快照；保留角色、修订冲突、幂等、原子保存及失败恢复。
- 将管理端状态判定表形成领域测试，保留现有模拟记录、价格历史及操作幂等；不新增租户身份、授权层或用户计费持久化。
- 核对所有旧状态读取位置和服务模式切换、停服恢复、发布、归档等命令；不留下直接操作旧字段的绕过入口。

主要范围：`model-management.js`、`model-operations.js`、`service-workspace.js`、`service-commercial.js`、`state-transaction.js`、`mock-publication-gate.js`、`platform-publication-state.js`、`platform-service-client.js`、`server/api.js`、`server/model-commands.js` 及模型运营管理端实际 D1 持久化映射；不增加租户接口。

验收：内部服务无售价可通过技术检查；经营服务缺售价不能进入收费销售；旧价格与授权不被重置；失败不部分生效。此阶段通过仅表示规则通过，不宣称租户流程完成。

### P2：打通内部使用的管理流程

依赖：P1。

- 服务详情切换为概览、渠道与路由、调用授权、验证与调用、操作记录。服务主操作为验证、启用、停用；内部分支跳过售价与销售步骤。
- 模型资料主档编辑归位；概览只引用摘要，调用 ID 仍在服务上下文维护。已有经营维护入口在售价新页可用前保持可达，P4 一次替换，不另建第二套编辑逻辑。
- 从原售价页面拆出客户开放范围，使用 P0 核实的现有对象和作用粒度；保存、取消、刷新与后台权限校验保持一致。
- 复用管理端平台试调用和验证回执，验证当前渠道、映射、路由及调用示例；内部服务不要求订单或销售价格。技术变更只使相关证据失效。
- 完成“里程碑 A 必验”的模拟记录、成本版本及提交恢复检查；停用服务与停止销售的管理动作分别验收。

主要范围：服务工作区、配置弹窗、发布检查、调用指南、平台试调用、接入向导、现有开放范围组件及对应管理命令；不改租户登录、用户 Key 页面、用户服务目录或用户调用接口。

验收任务：管理员新建内部服务 → 选择已验证渠道 → 配置映射与路由 → 设置现有客户开放范围 → 管理端模拟验证 → 明确启用 → 刷新查看生效配置及记录 → 停用／恢复并核对状态。全程不要求售价、订单或销售上架。

同时验证：无权后台角色不能修改；D1 保存失败保留输入；内部配置和模拟验证不生成销售费用；缺成本待核算；已有模拟记录保留当时成本版本；改价不追改历史；重复提交和回执恢复不重复写入。

里程碑 A：内部服务的管理端配置、模拟验证、启停与历史保护通过。不要求“未登录后台的新浏览器完成租户调用”，也不把本阶段结果标为用户端调用已贯通。

### P3：完成渠道、成本、资料的页面归位

依赖：P2；此阶段完成内部使用的成本管理流程。

- 新增模型成本列表、详情、变更记录与计量配置入口，复用采购价格编辑和版本化逻辑。
- 成本按供给来源及模型关联定位；服务关联多个来源时展示对应成本记录，不合成一个未经定义的服务成本价。
- 成本新页面能保存、取消、处理冲突和刷新回读后，再删除渠道内采购价编辑；渠道保留摘要和定向跳转。
- 渠道接入按目标结构组织接入、适配、测试和历史，保留供应商／模型视角与共享密钥维护。
- 资料列表／详情收拢唯一主档编辑；字典入口迁到模型成本，更新全站相关跳转和面包屑。
- 新页面从一开始接入现有 D1 数据与权限边界，更新 `AdminConsoleV2.jsx` 的路由数据选择；不得因新增路径落入另一套本地管理数据。
- 自建来源保留明确的成本依据及待核算状态；本轮不实现新的 GPU 分摊或资源会计系统。

主要范围：导航、面包屑、`AdminConsoleV2.jsx`、`CloudModelOperations.jsx`、`ProviderManagement.jsx`、渠道／采购表单、采购价格事务、`TariffDictionary.jsx`、资料编辑组件及对应样例。

验收：同一渠道价格在成本、渠道摘要和历史中一致；修改成本不清除连接验证；零价与缺价明确；跨页返回与刷新有效；无权角色不能从直达 URL 或命令修改价格；复跑 P2 的改成本不追改历史与缺价待核算用例。

里程碑 B：内部接入、服务管理与成本管理流程可用；验证范围仍为管理端。

### P4：独立售价页面与经营操作

依赖：P3；开始对外经营部分。

- 新增售价列表、服务售价详情，包含售价配置、销售设置、变更记录；复用现有统一／分供应商价格版本能力。
- 售价按可调用服务身份关联。新建售价选择现有服务，不新建资料或渠道；内部服务无售价不是错误。
- 在新页面完成价格编辑、发布、销售范围及上架／停售操作后，删除服务页旧价格编辑和旧销售操作入口。
- 售价生效、销售状态与服务启停分别提交和记录；按管理端状态表检查上架、停售、价格失效和用途切换，不处理用户订阅、额度扣除或 Key 资格转换。
- 售价页与成本页使用同一计量字典；管理侧必要时查看关联成本，客户响应不包含成本快照。
- 用途切换检查已有依赖，存在活动商业依赖或无法核对时阻断；不自动修改用户收费关系、订单或权益。

主要范围：现有售价／商业配置组件、`service-commercial.js`、价格发布命令、导航与 D1 页面边界、服务概览摘要及销售入口调用方。

验收：可为服务配置并发布售价、上架销售、停售；未生效售价不能开始收费销售；改路由不改售价；内部服务的配置、验证与启用不受这些操作影响。

### P5：经营管理流程与整体验收

依赖：P4。

- 完成管理员从服务配置到成本维护、售价发布、销售设置、上架／停售的操作闭环；保留跨页对象、返回位置和唯一编辑入口。
- 验证管理端生效价、版本及历史一致，修改当前价格不追改历史。回归 P2 的内部模拟无销售费用、缺成本待核算与操作幂等。
- 同步五模块帮助、入门指导、开发说明和验收文档；清理旧页签、旧编辑入口及冲突的有效条款。
- 运行受影响管理端回归与构建；浏览器检查完整任务、刷新／前进后退、键盘、窄屏、取消、失败、冲突及旧数据维护。共享代码影响已有用户侧行为时做回归检查，发现衔接问题单独记录，不扩建用户功能。
- 记录每阶段变更、证据和剩余限制；生产部署作为单独交付动作，不沿用旧发布授权。

验收任务：管理员配置可用服务 → 配置成本 → 设置并发布售价 → 配置销售范围 → 上架销售 → 调价／停售／停服分别验证 → 查看各自历史；同时回归内部无售价的服务配置、模拟验证与启用。

里程碑 C：五模块及内部使用、对外经营两条管理流程通过原型验收。用户端展示、购买、身份鉴权、实际调用及结算不纳入本轮完成声明。

## 验证与数据保护

- 实施前检查现有改动，按阶段记录自己的文件及片段；不以清理工作区为理由丢弃并行修改，不发布混入的无关改动。
- 优先复用 `service-commercial-*`、`service-workspace`、`channel-runtime-pricing`、`d1-*` 等涉及管理端的现有测试，新增能检出本轮回归的用例；共享逻辑影响用户侧时运行其既有检查，不据此扩展用户侧实现。
- P1—P2：管理端状态、后台权限、开放范围、模拟验证、D1 和变更命令契约；P3：成本、字典、导航、持久化；P4—P5：价格、销售配置、历史及内部管理流程回归。
- JSX／逻辑变化按版本规则执行 lint 和 `npm run build:5.12.0`；跨模块完成后运行版本测试。最终执行完整构建、版本隔离及 Sites 检查。每次仅计划文件变化不运行应用测试。

- 本计划中的“验证通过”仅指管理端原型模拟链路；租户访问 D1、用户端实际调用、真实上游、生产鉴权、真实计费和负载稳定性均不在本次完成声明内。
