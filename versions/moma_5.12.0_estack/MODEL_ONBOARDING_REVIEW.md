## 2. New API：先选提供商，再配置连接与模型

### N01：从渠道列表进入创建

打开 `/channels`，进入创建渠道流程。提供商选择支持搜索，展示内置提供商、插件网关及自定义等选择方向。此入口将接入类型放在前面，后续表单围绕所选提供商展开。[截图 01](../../outputs/model-onboarding-interaction-review-20261031/screenshots/01-newapi-channels.png)

### N02：查看 OpenAI 的连接与模型配置

选择 OpenAI 后，查看连接与模型区域。页面可配置密钥，当前展示 single 模式；模型部分提供预设、从上游获取及相关重定向入口，并允许配置多个模型。这里只确认入口与字段存在，没有执行获取或模型调用。[截图 02](../../outputs/model-onboarding-interaction-review-20261031/screenshots/02-newapi-openai-connection.png)

### N03：切换路由、映射和请求相关分区

创建界面将连接与模型、路由与映射、请求与响应、其他设置放在不同页签。模型映射与连接输入有明确分区，复杂配置不需要全部常驻在同一段表单内。[截图 03](../../outputs/model-onboarding-interaction-review-20261031/screenshots/03-newapi-model-mapping.png)

这说明本次被测 New API 已有成熟的配置分区。对 MoMA 的参照应包括它如何组织提供商、模型和高级配置，不能把它概括成未经分区的旧式大表单。

### N04：核对创建默认状态

本次创建表单中的启用选项默认开启。由于没有提交，尚未观察其保存、测试、启用之间的后端执行顺序。本报告只记录这个界面默认值，不推断保存后能否实际调用。

## 5. 新版 MoMA：按任务逐步走查

### M01：只登记供应商主体

操作：填写并保存供应商主体信息，不录入模型、渠道或连接配置。

观察：主体登记成功，模型数量为 0、渠道数量为 0。主体登记可以独立完成，没有被迫先创建空连接。

### M02：保存不完整的 Anthropic 草稿并刷新恢复

操作：进入渠道配置，选择 Anthropic；版本字段保留未完成的 `2026-`，地址也保持未完成状态，保存草稿后刷新并继续编辑。

观察：草稿内容恢复，未完成的字段没有因刷新而消失。这个步骤验证保存草稿可容纳尚未完成的输入；没有据此声称该配置可以直接执行调用。[截图 07](../../outputs/model-onboarding-interaction-review-20261031/screenshots/07-moma-anthropic-draft-restored.png)

### M03：为上游 ID 匹配资料，保留已输入的实际调用标识

操作：输入 `vendor/raw:model.v2`，再匹配模型资料。

观察：上游 ID 保留原值，没有被资料库中的平台编码覆盖。资料身份与上游调用标识可以分别维护。

### M04：使用参考批选，并保留未匹配行

操作：已有 `unmatched/item` 未匹配行时使用参考目录批选；随后尝试保存含无效行的选择集。

观察：参考批选没有清除未匹配行；无效行阻止整批提交。明确取消勾选错误行后，才创建剩余选中的 2 条映射。没有自动跳过坏行，也没有为它们生成游离映射。

这一步仍需要运营判断实际模型身份。参考目录辅助填表，不能代替账号授权或模型调用结果。

### M05：在父表单内新增 Key，再取消或保存

操作：打开 Key 子表单，填写未保存内容后取消；查看内联放弃确认，再返回父表单。另一路径明确保存 Key 后继续测试流程。

观察：放弃确认位于当前子表单内，本次可见 dialog 计数为 1；父表单数据保留。明确保存后可回到后续测试。此处的计数是本次界面的观察，不代表已经遍历所有嵌套入口及键盘关闭路径。

### M06：两条无价映射保存、测试，通过后仍未启用

操作：对 M04 创建的 2 条映射保持采购价为空，执行 mock 基础测试。

观察：配置可以保存，2 条基础测试通过，映射仍未自动启用。空采购价没有被本次流程填写成零。保存、测试结果与明确启用是不同状态。

这一结果证明当前操作链路的状态区分；真实上游授权和采购计费并未在本次 mock 中验证。

### M07：固定启用选择，再明确执行启用

操作：选择待启用模型，进入确认状态；检查选择与重测操作，再明确确认启用。

观察：确认阶段固定了本次两项选择，复选框与重测操作不可在确认期间继续改动；明确确认后才启用所选映射。[截图 08](../../outputs/model-onboarding-interaction-review-20261031/screenshots/08-moma-enable-frozen-selection.png)

本次证据支持选择集合在确认阶段保持稳定。大批次、多页面并发和所有停用恢复组合，不由这一次两项选择的操作推定为全部通过。

### M08：携两条映射进入服务管理，再返回

操作：从接入结果前往服务管理，携带 2 个 association ID，并从服务侧返回。

观察：两条映射上下文保留，返回入口可用。本步骤没有自动提交模型服务。

它验证供应接入结果的上下文传递；资料首次转为模型服务的创建路径另见 M13。

### M09：分别查看 403、空列表和部分发现

操作：切换 mock 发现情形，分别触发 403、empty 和 partial。

观察：三种情形有各自反馈，部分返回没有被表达为完整模型列表；这些操作没有删除已有配置。[截图 10](../../outputs/model-onboarding-interaction-review-20261031/screenshots/10-moma-partial-discovery-1280.png)

这是对发现反馈及保留配置行为的验证，不表示实际供应商的权限、分页协议或接口响应已被检验。

### M10：查看分层诊断

操作：打开测试诊断，先阅读默认摘要，再展开技术信息。

观察：默认显示结论、请求阶段、处理建议及用量未知等信息；技术追踪字段放在折叠区域。未知费用没有显示为免费。[截图 09](../../outputs/model-onboarding-interaction-review-20261031/screenshots/09-moma-test-diagnostics.png)

本次截图证明诊断页面的分层呈现，不等于每种错误码、每种任务或所有可选追踪字段都已经通过真实接口验证。

### M11：带未保存路由修改前往维护供给，再返回

操作：将路由权重从 50 改成 47，保持未保存；前往维护供给，再返回原服务配置。

观察：返回后权重恢复为 47，界面明确标记尚未保存；已生效路由仍是 v1。维护供给没有把当前未保存权重顺便发布。[截图 11](../../outputs/model-onboarding-interaction-review-20261031/screenshots/11-moma-route-draft-restored-1920.png)

本步验证同一次浏览器会话中的往返恢复。该份未保存路由在刷新、浏览器重启或并发编辑后的恢复，不属于这一步已取得的证据。

### M12：选择明确客户与允许供给，执行平台试调用并确认发布

操作：显式选择江苏租户，允许供给仅选择硅基流动；执行 mock 平台试调用，再明确确认发布。

观察：试调用通过，界面显示成本 `0.000024`、试算 `0.000038`，客户未扣费；随后执行确认发布动作。相关页面证据见[截图 12](../../outputs/model-onboarding-interaction-review-20261031/screenshots/12-moma-platform-published-1440.png)。

上述数字是该次 mock 页面显示值，不能外推为真实模型报价、供应商账单或实际客户结算。再次确认发布为 v2 后，关闭并重新打开弹窗，实际显示“候选 v2 · 修订 4”“已发布 v2”，服务仍为已下架。此次成功路径不替代所有失败门槛组合；发布证据过期、配置变化、伪造本地记录及直接写操作的阻断另由合同测试验证。

### M13：从独立资料创建销售服务

原地新建“走查资料独立身份”，填写核心身份、对话任务及输入输出类型；返回父渠道后保留连接与上游 ID。保存渠道，mock 基础调用通过后明确启用，携该映射进入服务管理。“所选模型与服务”提供“新增模型服务”，打开后预填原资料，补齐作者、发布时间和介绍，明确保存为服务草稿；没有自动选择服务模式、关联渠道或上架。成功后 URL 清除 `sourceLibrary`，交接摘要变为“配置服务”。见[截图 13](../../outputs/model-onboarding-interaction-review-20261031/screenshots/13-moma-material-service-created.png)。原资料 ID、B 测试证据及 C 绑定身份一致性由完整链路测试直接断言。

### M14：取消、焦点及分页补充

最小资料子表单输入未保存名称后取消，在当前子弹窗内确认；继续编辑保留名称，焦点返回“模型名称”；放弃后父表单保留，焦点返回“选择模型”。重复渠道名在第一步旁显示错误，`aria-invalid=true`，焦点落在渠道名称。参考目录从第 1／3 页翻到第 2／3 页，仍处于选择模型步骤，不触发保存或测试。

## 7. 已观察到的改进与仍有摩擦

### 7.1 已观察到的改进

1. **主体登记没有空渠道负担。** 实际保存了 0 模型、0 渠道的供应商主体。
2. **接入资料不会替换已输入的上游 ID。** 匹配后保留了含斜杠、冒号和点的调用标识。
3. **批量输入有明确的错误边界。** 未匹配行保留，坏行阻止整批，用户取消其选择后才保存其余两项。
4. **技术测试与运营启用分开。** 两项通过后仍未启用，确认阶段固定选择，再明确执行启用。
5. **草稿和返回路径有实际恢复证据。** 不完整连接草稿刷新恢复；未保存路由权重经过供给维护后仍恢复为 47，生效版本维持 v1。
6. **异常反馈更容易定位。** 发现的三类结果分开表达；诊断以结论、阶段、建议为主，追踪信息按需展开。

### 7.2 仍有的交互成本

- **流程阶段较多。** MoMA 同时管理供应主体、模型资料、渠道映射、采购成本和销售服务。连接可测试、映射可启用、服务可发布分别对应不同业务条件，运营需要理解这些边界。后续应持续检查当前主动作、返回位置和完成状态是否足够清楚。
- **参考批选仍需要人工判断。** 本次 `unmatched/item` 被完整保留，运营必须完成资料匹配或明确取消选择。保留错误行有利于避免数据丢失，也增加了大批次中的处理工作；应继续检验错误定位、分页和选择集是否便于操作。
- **启用确认强调稳定集合。** 冻结选择后，运营调整范围需要退出当前确认状态。后续走查应确认返回修改的路径清楚，且不会清空已完成的测试和原选择。
- **维护供给与服务配置仍是跨页面任务。** 本次权重往返恢复成立，其他服务表单、渠道关联选择及资料创建路径仍需分别检查，不能把一个成功例子推广到所有草稿。
- **mock 的“通过”容易被理解过度。** 业务页面应表达当前任务结果，交付说明和技术记录需保留 mock 来源。演示评审时，应同时说明真实适配、账号权益和计量能力未在此范围验证。

这些摩擦需要继续按任务处理。供给与销售的职责边界能够解释流程结构，实际操作是否清楚仍要依靠具体走查结果判断。
