# MoMA 5.12.0 模型运营术语

本术语表描述模型资料、上游供应和平台对外服务。模型运营分为渠道管理、模型服务、模型广场、模型售价和模型资料。统一模型服务模式与渠道直选模式是当前服务模式；采购和销售分别定价。

## 模型身份与资料

**模型资料**：基础资料中的参考档案，记录模型规格及来源。创建服务、登记渠道模型或新建广场卡片时可复制所需字段。保存后，各模块独立维护自己的值。
_Avoid_：把服务商接入记录当作新的模型资料，或把服务展示内容当作另一款模型身份。

**资料 ID**：系统识别同一份模型资料的稳定关联标识，与可读名称及调用参数分开。
_Avoid_：模型编码、上游模型调用标识、模型调用标识。

**模型编码**（`canonical_slug`）：用于跨服务商识别同一确定型号与版本的可读编码，如 glm-5.3；与模型内部永久 ID 分开。
_Avoid_：仅写“模型 ID”而不区分资料标识、业务编码和模型调用标识。

**模型资料名称**（`name`）：基础资料中维护的参考名称，创建业务记录时可按需复制。

**模型展示名**（`name`）：模型广场维护的用户可见名称。基础资料、模型服务和渠道管理各自维护本模块的名称。
_Avoid_：模型名称、模型显示名、以展示名代替稳定关联标识。

**模型作者**：模型的研发者或发布团队，不必等于平台直接采购服务的服务商。
_Avoid_：服务商、固定的对外服务发布主体。

**模型类型**：按模型用途划分的类别；任务类型描述具体执行的工作，例如图像理解或语音识别。

**输入／输出模态**：模型接收和生成的内容形态，如文本、图片或音频。结果类型描述向量、相关性分数、排序结果等返回形式。
_Avoid_：把声明的模态、任务或能力视为已经完成真实验证。

## 供应与调用

**服务商**：直接向平台提供模型服务并形成采购成本的一方，其上游推理、中转或转售方式不改变该直接采购关系。
_Avoid_：仅凭模型作者、研发厂商或对外发布标识认定服务商。

**服务商资料**：记录供应主体、展示信息与运营联系方式的主档，供渠道和供应模型引用。

**服务商编码**：标识服务商主体的业务编码；渠道直选模式服务关联中使用同一服务商编码表达来源。
_Avoid_：不解释含义的 Provider 标识、上游模型调用标识。

**供应模型**：某个服务商与一款模型资料的供应关系。关系登记不等于已配置可用渠道；渠道管理的两种视图仅展示具有未删除渠道的供应关系。删除最后一条渠道时，同步归档当前服务商对该模型及其别名的供应登记，保留模型资料、采购价格和操作历史。

**服务商能力声明**：该服务商对模型支持参数、上限和能力差异的说明；不改写统一主档，也不代表渠道已经通过验证。

**连接**：平台访问服务商的一组接口、地址和认证配置。同一服务商可用一条连接接入多个渠道。

**渠道**：服务商为一款模型提供的一个独立供给来源，例如甲云（自营）或甲云（转售）。复用连接时仍分别维护来源名称、上游模型调用标识、检测与采购价。
_Avoid_：服务商主体、单把 API 密钥、一个销售服务。

**渠道模型映射**：平台模型身份与某个渠道内上游模型调用标识的对应关系。

**上游模型调用标识**（`upstream_model_id`）：平台向服务商发起请求时使用的模型标识，可因渠道不同而不同。
_Avoid_：资料 ID、模型编码、模型调用标识。

**服务根地址／请求地址**：服务根地址是标准接口的基础地址，请求地址是包含任务路径的完整调用地址。自定义任务直接配置完整任务地址。

**服务商 API 密钥／密钥组**：用于上游鉴权的 API Key 及其资产分组，保留 API 密钥名称。当前绑定渠道数表示配置关系，不表示调用量。
_Avoid_：客户调用平台时使用的 API 密钥、把资产分组顺序视为所有渠道的调度策略。

**渠道密钥池**：一个渠道绑定的多条服务商 API 密钥及其启用状态、优先级。旧专属、默认及共享组引用在明确修改前保持原值；优先级配置不证明已实现真实网关多 Key 配额调度。

## 价格与对外服务

**刊例价**：服务商对某模型的参考报价，具有独立来源和有效期。只在服务商模型详情维护；不自动作为实际采购价或客户售价。

**采购报价／采购价**：服务商提供给平台的计费规则、单价及适用条件；渠道接入及管理端技术验证、启用可以先不配置；经营调用按既有有效采购条件校验，缺价保持待核算。
_Avoid_：服务商售价、渠道售价、平台售价。

**采购参考价／折扣系数**：采购参考价是服务商报价的计算基准，折扣系数参与计算实际采购单价；明确的手工采购价可覆盖该计算结果。
_Avoid_：将参考价直接当作实际成本或客户售价。

**Token 成本**：实际供应消耗按适用采购报价形成的平台成本，不是客户收费。

**计费项／计费单位／币种**：计费项确定费用对象，计费单位确定单价对应的数量，币种确定金额货币；三者共同限定价格含义。

**模型服务**（model_service）：平台对外提供的一个具体模型调用入口，拥有永久模型服务 ID，可关联一条或多条同款模型渠道，分别维护调用配置、售价与经营状态。

**模型服务 ID**（model_service.id／引用 model_service_id）：创建后不变的具体入口编号。名称、调用值及价格变化不改变其身份。

**模型 ID**（model.id／引用 model_id）：同一模型的内部永久身份，与模型编码及参考资料内容分开。
_Avoid_：以模型资料、供应关系或单个渠道代替对外服务。

**模型调用标识**（`call_id`）：客户在平台 API 请求中填写的模型标识，由服务模式及服务配置确定，可按规则修改；与创建后不变的模型服务 ID 分开。协议字段映射见[模型运营数据契约](MODEL_OPERATIONS_DATA_CONTRACT.md)。
_Avoid_：上游模型调用标识、固定的“发布方/模型名”格式。

**统一模型服务模式**（Provider-Agnostic Routing）：用户只选择模型，平台在后台完成服务商选择、负载均衡及故障转移。使用模型级模型调用标识与售价，实际服务商切换不自动改变客户单价。

**渠道直选模式**（Provider-Explicit Routing）：用户选择具体渠道服务。新建渠道服务绑定一条已启用的供给，具有独立的模型调用标识、售价、路由、订单和上架阶段；请求不切到其他可选渠道服务。广场按模型聚合卡片，上架操作可逐渠道或按服务商勾选。

**平台售价**：平台向客户销售模型服务的计费规则与单价，在模型售价独立于采购报价维护；内部服务可无售价。
_Avoid_：服务商售价、平台目录价、采购价格。

**关联渠道／渠道路由**：关联确定服务可选的供给集合，路由确定请求在允许供给中的选择、分配或回退规则。关联成功不表示路由已经生效。

## 接入任务与配置

**接入任务**：围绕一款模型完成首次上架、准备备用供应或投入已有服务的工作。完成条件由任务目标决定，不以另一项服务已经上架替代。
_Avoid_：把接入任务当作第二份模型身份。

**未提交输入**：仅在当前编辑页面保留的内容；预览不写业务数据，确认提交后一次保存。后台不提供草稿保存与恢复。

**生效配置**：已经明确发布或应用、供相应业务使用的配置版本。
_Avoid_：最新编辑内容、未发布候选。

**备用供应**：已具备必要采购条件和有效连接检查、尚未投入当前服务路由的供给。
_Avoid_：把未分配流量的备用供应称为未完成接入或运行异常。

## 验证与状态

**测试通过**：本次选定范围的验证成功，不等于所有能力通过或服务已对外开放。

**启用模型**：让验证有效的渠道模型映射具备技术供给资格；不替代正式服务的价格、能力及发布条件。

**应用配置**：明确将已验证的候选连接或密钥切换为当前配置；测试候选不自动覆盖当前配置。

**发布配置**：明确使检查通过的服务配置或路由版本生效，预览不写入，确认后一次提交。

**上架销售**：管理员确认技术已启用、经营服务成本／售价有效及销售对象后开放销售状态；不自动启用技术服务，不代表用户端已贯通。

**停用技术服务／停止销售**：在模型服务停用技术服务，停止处理新请求。在模型广场下架，停止客户新订购和新调用。
_Avoid_：仅隐藏模型、仅停止新增订购、删除服务。

**放弃本次修改**：撤销尚未保存的编辑，回到最近一次保存内容。
_Avoid_：删除已保存的资源或历史。

**销售对象**：模型内经营服务共用的 `salesScope`，经营上架前须配置。

**成本待核算**：没有可确认的适用价格或计量事实，不以零代替；后台技术验证可继续，历史不会因后补价格自动重算。

## 客户与登录身份

**客户** 是订购或使用模型服务的业务主体，分为政企客户和个人客户。**租户** 是系统承载客户项目、密钥和用量的隔离范围。运营开户、身份及权限治理界面用「租户」，订购和经营分析场景继续用「客户」。

**登录账号** 标识一个可登录前台的人。此人加入政企客户后，在该客户下是**企业成员**，其成员角色和状态由该客户管理。

**调用用户** 是一笔请求中记录到的具体用户。应用用 API 密钥发请求时，客户可以有明确归属，调用用户可能未采集。

**后台账号** 是平台人员登录运营运维后台的身份。


**使用空间** 是用户进入某一客户租户业务的环境，分企业空间和个人空间。一个账号可以进入本人已开通的个人空间和已加入的企业空间。

**项目** 属于一个客户租户，承载模型权限、API Key、预算与调用记录。企业空间支持多个项目；个人空间固定一个默认项目，由本人使用并继承个人空间的有效模型使用资格。

**主责部门** 是企业项目的组织归属与成本归集依据。项目可以由多个部门的成员共同参与。
