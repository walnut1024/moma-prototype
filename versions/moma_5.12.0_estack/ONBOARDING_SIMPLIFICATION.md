# 模型接入简化增量说明

日期：2026-10-31

本次继续精简目录外模型接入和日常维护，并修复渠道专属 Key 的轮换范围。常用目录、目录外主体与模型、连接和新 Key 在同一张表单填写；保留“保存接入 → 显式测试 → 显式启用”及“候选测试 → 明确应用”的业务边界。三个添加入口、现有后台视觉及导航结构保持。权威规则与新增验收 AC63–74 见 [模型接入 Spec 第 23 节](MODEL_ONBOARDING_SPEC.md#23-目录外接入与日常维护简化2026-10-31)。

交付范围仍为浏览器内 mock 原型。参考目录、模拟测试、费用试算和原型发布状态均不构成真实账号授权、真实上游成功或生产报价。

## 1. 本次流程

| 阶段 | 操作 | 业务结果 |
| --- | --- | --- |
| 配置接入 | 同页选择已有／参考记录，或输入目录外供应商名称、模型 ID 和类型；填写地址与 Key | 未登记的参考项和新身份只留在当前表单，不登记业务对象 |
| 保存接入 | 显式保存当前选中的连接与模型 | 一次事务补齐必要主体、模型资料、新 Key 掩码、渠道与供应映射；失败不留下部分对象 |
| 基础测试 | 点击明确标明产生用量的测试按钮 | 该次点击授权当前基础测试；保存本身不会启动调用 |
| 技术启用 | 基础检查通过后显式启用 | 合格新渠道单模型或新追加单映射可直接明确启用；历史恢复、多项选择和服务影响按固定范围检查 |
| 日常维护 | 地址与 Key 先明确测试候选，再明确应用 | 测试按钮合并候选保存及同义用量勾选；失败不改变当前配置 |
| 服务配置 | 主动进入服务管理 | 继续配置采购计量、销售价、允许供给、路由、客户范围、平台试调用及发布 |

上一轮内置目录场景已实测为新 Key 6 项、已有 Key 5 项。本轮浏览器实测：目录外 OpenAI 兼容单模型 **9 项**、已有渠道追加模型 **6 项**、地址及正常 Key 轮换 **各 5 项**。起点为已打开的添加表单或目标已可见的详情列表，终点为技术启用或明确应用；正式服务上架另计。

## 2. 参考目录与身份

- 常用供应商预设来自现有参考数据；模型候选同时展示已有资料和未登记参考项，供应商公开参考清单中的精确 Model ID 优先展示；不按开发者名称猜测供应关系。选择和取消选择不创建供应商、模型资料、渠道或 Key。
- 已有供应商按明确引用、预设标记或精确业务编码解析；历史内部 ID 的字面含义不用于认定主体。多个候选或供给类型冲突时要求明确选择，不取第一条。
- 已有模型资料使用原稳定 ID。未登记参考项仅在保存时创建必要资料；不复制已有模板身份，不按相似名称或版本名合并。
- 平台模型编码、资料 ID 与上游模型 ID 分开维护。切换资料时，仅将仍等于旧资料默认值的上游 ID 替换为新默认值；不同于旧默认值的自定义调用 ID 保留。
- 目录只用于辅助填写。是否获准使用模型、接口是否响应、能力是否满足服务承诺、采购计量及价格是否有效，仍分别检查。
- 目录外供应商只需当前表单中的主体名称，内部英文编码由保存事务生成并固定；目录外模型只需模型 ID 和类型，显示名默认同输入，语言模型为可修改的默认类型。
- 快速接入资料的任务、输入／输出模态和能力保持未知，标为“待完善”。技术测试可进行，正式服务仍需补齐资料、能力与商业条件；不按模型类型补造能力。
- 三个独立登记入口继续保留。用户在其他入口明确保存的资源按原规则保留，取消渠道表单不删除这些记录。

## 3. 原子保存与草稿

常用和目录外接入均使用 `channelQuickCreate`。新建渠道的本次事务可以包含：供应商主体、已有／参考／最小模型资料、新 Key 的掩码与指纹、必要供应关系、渠道和模型映射。任何一行、引用或凭证校验失败，整次事务不提交。保存不会同时创建销售服务、发布路由或修改客户售价。

输入契约：

- `providerId`、`providerPresetId`、`newProvider:{name}` 三选一；每行的 `libraryId`、`modelPresetId`、`newModel:{modelId,type,name?}` 三选一。
- `values.models` 是固定的选中模型集合；每行保留自己的 `upstreamModelId` 与 `scenarios`。每批最多 50 个模型，重复或无效项拒绝整批。
- `values` 保留接口类型、规范化地址、任务地址、适配器选项及受支持的连接设置，正式提交按现有接口规则校验。
- `newApiKey` 只接受 `maskedKey`、`fingerprint`、可选 `accountRpm`，不接收原始 Key。新 Key 随渠道保存，不要求先在另一个弹窗独立保存。
- 新 Key 加入指定组后，新渠道明确绑定该 Key；不会顺便切换共享组当前主要 Key，也不会使其他引用渠道继承新资格。
- 从草稿提交时校验 `draftId` 与 `expectedDraftRevision`；成功后把该草稿标为完成。
- 已有渠道追加模型使用 `providerId` 与 `values:{endpointId,models}`；不夹带新主体、Key 或连接字段，新资料与新映射仍原子提交，草稿渠道必须匹配。

“保存草稿”独立于保存接入。草稿保存未完成的非敏感连接文本、目录引用、新主体与新模型文本，不提前创建业务对象。恢复时重新解析当前资源、冲突和权限；新 Key 明文不进入草稿，恢复后需要重新输入。已保存浏览器数据、旧服务引用、采购记录和稳定 ID 不因本次简化而重置。

## 4. 测试授权

普通基础测试包括文本、图像理解、向量和重排。在按钮中明确表达会产生用量，用户点击即授权这次操作，取消同义的前置勾选框。测试计划、连接签名及权限仍在派发前重新检查，按钮文案不能代替这些校验。

图片生成、语音、视频和流式、工具、结构化输出等专项验证，继续明确任务范围与用量确认。语音须选择识别或合成，不猜测默认任务。未知费用保持未知，不按免费处理。

测试使用原有可恢复任务：先保存提交快照，结果不确定时查询原操作 ID；不会因为关闭弹窗、刷新进度或失败反馈而自动创建付费重试。临时密钥组只产生独立记录，不替换当前正式配置或资格。

## 5. 启用与维护的简化边界

省略选择框和重复确认仅适用于同时满足以下条件的情况：

1. 当前固定范围是接入流程创建的一条新映射，可以来自新渠道或向已有渠道追加。
2. 该映射未启用且从未启停；已有渠道的其他映射不被选入。
3. 当前基础测试已通过，配置和凭证仍匹配，没有未完成任务或明确撤销等阻塞。
4. 当前映射没有已发布服务引用；确认范围没有在准备与提交之间变化。

用户仍须明确点击“启用模型”。测试成功不自动启用。简化的是重复的可视选择与确认，底层仍生成固定选择快照，并通过原有原子事务重新检查。

多项选择、历史恢复或存在服务影响时，展示明确范围并执行完整检查。列表、详情及测试入口统一固定选择快照、当前验证和服务影响检查，移除旧结果直达启用的旁路。恢复只恢复明确选中的映射，其余保留停用。

地址或 Key 维护把“保存候选、勾选同义用量同意、开始基础测试”合为一次明确标明产生用量的测试操作；通过后再一次明确点击应用。影响范围前置展示，不再追加同义的二次应用确认。测试失败、未知或取消保留当前配置；候选、引用或权限变化仍由应用前预检阻断。高成本任务保留任务范围和独立用量授权。

渠道专属 Key 只更新明确目标渠道的绑定；组主要 Key 覆盖全部真实组引用；混合引用时明确本次范围，不忽略专属渠道或误改共享主要 Key。所有目标验证成功后才原子应用，旧 Key 不自动撤销，售价、路由和历史保留。

测试派发前复核冻结的完整影响版本，避免顺序测试共享组时新增模型被隐式纳入用量。Key 列表显示实际“当前使用渠道”；未使用的备用 Key 可直接替换资料，不误使在线渠道失效。组主要和专属 Key 仍需候选验证，删除／撤销保持完整引用保护。应用后保留当前轮换页面与成功版本。

## 6. 供给与销售继续独立

- 采购价为空可以保存、测试并技术启用；正式服务供给仍需完整且有效的采购计费项。显式零价与未知值保持区分。
- 资料及渠道接入不自动创建第二套服务身份，不自动关联、开放客户范围或上架。
- 服务管理继续负责服务模式、对外调用 ID、客户销售价、明确允许供给、路由、平台试调用和发布门槛。
- 修改采购价或切换实际渠道，不自动改变客户售价。既有请求的版本追踪、费用快照和撤销阻塞规则保留。
- mock 来源保留在技术记录和研发说明中；正式表单不增加实现说明或常驻免责段落。

## 7. 研发说明与界面范围

沿用现有组件、浅色工作台和紧凑表单，不新增一级导航、独立接入中心或额外配置向导。资料、供应商和渠道三个添加入口继续服务各自的独立登记任务。

`DevelopmentNotes.jsx` 说明参考目录、原子登记、内联 Key、测试点击授权和启用例外；`GettingStarted.jsx` 使用运营任务语言介绍单页接入和后续服务配置。实现字段、事务细节及 mock 边界保留在研发须知和本文件中，不堆入正式表单。
